# v2 设计：眼位小地图

> 前置：v1 设计见 [design.md](design.md)。本文档只描述 v2 新增部分。
> 数据结论全部来自三局实测 dump（2 快速 + 1 正常）。

## 一、要解决什么

两个游戏本身不告诉你的信息：

1. **我方的眼什么时候过期**——游戏只在小地图上画个点，不说还剩多久，
   也不提醒你它是被排掉了还是自然到期。
2. **敌方的眼在哪**——真眼照到时能看见，真眼一过期就看不见了，
   但那颗眼还要活五六分钟。

## 二、显示形式

面板里加一块**方形小地图**，与现有横条一起在按住 Alt 时出现。

- **底图**：22 座塔（复用 v1 的 `constants/towers.json`）+ 两个泉水。
  已被推掉的塔画成灰点——顺带成了战场态势图，零额外数据。
- **我方眼**：亮点 + 到期倒计时。快到期时点变色。
- **我方眼被排**：提前消失即判定被排，红色闪一下再移除。
- **敌方眼**：暗红点，**只标位置、不带倒计时**（原因见第五节）。

## 三、坐标映射

地图是 ±8400 的正方形，游戏坐标 x 向右、y 向上，画到屏幕上 y 要翻转：

```
屏幕x = (x + 8400) / 16800 × 边长
屏幕y = (1 - (y + 8400) / 16800) × 边长
```

校准锚点（实测坐标）：天辉泉水 `(-7456, -6938)` 左下、夜魇泉水 `(7408, 6848)` 右上，
与游戏小地图朝向一致。另有莲花池 `(-7548, 4209)` / `(7503, -4404)`、
观察者哨塔 `(-4096, -448)` / `(3392, -448)`、传送门 `(-6457, 7599)` / `(6425, -7313)`
可用于核对。

## 四、我方眼位跟踪

**身份**：眼不会移动，`(team, unitname, xpos, ypos)` 四元组即唯一身份。

**寿命**（实测，两种模式一致，进常数表）：

| 类型 | `unitname` | 实测存续 | 取值 |
|---|---|---|---|
| 假眼 | `npc_dota_observer_wards` | 364~373s（多数 365~369） | 366 |
| 真眼 | `npc_dota_sentry_wards` | 426s（12 个样本几乎不差） | 426 |

比游戏标称的 6 分 / 7 分各长约 6 秒，推测是插眼动画或消失延迟。
倒计时用实测值更贴近"视野何时真正消失"。

**到期倒计时** = 首次见到的 clock + 寿命 − 当前 clock。

**被排检测**：眼从数据里消失，而倒计时还没走完 → 判定被排。
容差 5 秒，避免临界抖动误报。

**中途启动**：程序启动时已存在的眼不知道插放时间，倒计时显示为未知（画点不画数字）。

## 五、敌方眼位记忆

**只标位置，不做倒计时。** 因为我们只在真眼照到的那十几秒里看得见它
（实测敌方眼可见时长中位约 11~20 秒），根本不知道它是什么时候插的——
可能刚插，也可能快过期了。一个可能虚高五分钟的倒计时会误导决策，
而"那里有眼"这一条信息本身就足够用（别从这走 / 去排掉它）。

**保留时长**：记住后保留一个假眼寿命（366s）再自动移除，避免地图上越积越多。
这是"最长可能还活着"的时间，宁可多留不可少留。

## 六、已知坑（都是实测踩出来的）

1. **泉水会伪装成眼**：双方泉水也用 `minimap_ward_obs` 图标绘制，
   存续贯穿全局（796s）。**必须按 `unitname` 过滤**，只看 `image` 会把泉水
   当成永不过期的眼。
2. **`(0,0)` 幽灵条目**：数据里存在坐标为 `(0,0)`、存续 0 秒的假对象，需丢弃。
   同类幽灵也出现在哨塔、莲花池、传送门上。
3. **敌方眼的 team 是 2/3**，与买活事件的 0-9 槽位编号不是一套，别混。

## 七、明确不做

- **敌方英雄失踪计时**：数据可行（`minimap_enemyicon` 带英雄名+坐标），
  但实测每个敌人每局消失 11~19 次、中位仅 5~19 秒，做成提醒会非常吵。
  留作 v3 候选，届时需要先想清楚"多久算失踪"。
- **敌方塔血量**：`buildings` 段只有己方，无数据。
- **观察者哨塔归属**：11 座哨塔的 `team` 恒为 5（中立），占领状态不体现在 GSI 里。
