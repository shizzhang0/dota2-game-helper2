# v2 设计：眼位小地图

> 前置：v1 设计见 [design.md](design.md)。本文档只描述 v2 新增部分。
> 数据结论全部来自三局实测 dump（2 快速 + 1 正常）。

## 一、要解决什么

两个游戏本身不告诉你的信息：

1. **我方的眼什么时候过期**——游戏只在小地图上画个点，不说还剩多久，
   也不提醒你它是被排掉了还是自然到期。
2. **敌方的眼在哪**——真眼照到时能看见，真眼一过期就看不见了，
   但那颗眼还要活五六分钟。

## 二、显示形式

面板里加一块**方形小地图**，与现有横条一起在按住 Alt 时出现。

- **底图**：只画 22 座塔（复用 v1 的 `constants/towers.json`）。三路和两个基地
  自然就被勾出来了，泉水位置固定且在塔阵尽头，不必再画。
  已被推掉的塔画成灰点——顺带成了战场态势图，零额外数据。
- **我方眼**：亮点 + 到期倒计时。快到期时点变色。
- **我方眼被排**：提前消失即判定被排，红色闪一下再移除。
- **敌方眼**：暗红点，**只标位置、不带倒计时**（原因见第五节）。

## 三、坐标映射

地图是 ±8400 的正方形，游戏坐标 x 向右、y 向上，画到屏幕上 y 要翻转：

```
屏幕x = (x + 8400) / 16800 × 边长
屏幕y = (1 - (y + 8400) / 16800) × 边长
```

校准锚点（实测坐标，仅用于核对映射是否画反，不绘制）：
天辉泉水 `(-7456, -6938)` 应落在左下、夜魇泉水 `(7408, 6848)` 落在右上，
与游戏小地图朝向一致。另有莲花池 `(-7548, 4209)` / `(7503, -4404)`、
观察者哨塔 `(-4096, -448)` / `(3392, -448)` 可作交叉验证。

## 四、我方眼位跟踪

**身份**：眼不会移动，`(team, unitname, xpos, ypos)` 四元组即唯一身份。

**寿命**（实测，两种模式一致，进常数表）：

| 类型 | `unitname` | 实测存续 | 取值 |
|---|---|---|---|
| 假眼 | `npc_dota_observer_wards` | 364~373s（多数 365~369） | 366 |
| 真眼 | `npc_dota_sentry_wards` | 426s（12 个样本几乎不差） | 426 |

比游戏标称的 6 分 / 7 分各长约 6 秒，推测是插眼动画或消失延迟。
倒计时用实测值更贴近"视野何时真正消失"。

**到期倒计时** = 首次见到的 clock + 寿命 − 当前 clock。

**被排检测**：眼从数据里消失，而倒计时还没走完 → 判定被排。
容差 5 秒，避免临界抖动误报。

**中途启动**：程序启动时已存在的眼不知道插放时间，倒计时显示为未知（画点不画数字）。

## 五、敌方眼位记忆

**只标位置，不做倒计时。** 因为我们只在真眼照到的那十几秒里看得见它
（实测敌方眼可见时长中位约 11~20 秒），根本不知道它是什么时候插的——
可能刚插，也可能快过期了。一个可能虚高五分钟的倒计时会误导决策，
而"那里有眼"这一条信息本身就足够用（别从这走 / 去排掉它）。

**保留时长**：记住后保留一个假眼寿命（366s）再自动移除，避免地图上越积越多。
这是"最长可能还活着"的时间，宁可多留不可少留。

## 六、已知坑（都是实测踩出来的）

1. **泉水会伪装成眼**：双方泉水也用 `minimap_ward_obs` 图标绘制，
   存续贯穿全局（796s）。**必须按 `unitname` 过滤**，只看 `image` 会把泉水
   当成永不过期的眼。
2. **`(0,0)` 幽灵条目**：数据里存在坐标为 `(0,0)`、存续 0 秒的假对象，需丢弃。
   同类幽灵也出现在哨塔、莲花池、传送门上。
3. **敌方眼的 team 是 2/3**，与买活事件的 0-9 槽位编号不是一套，别混。

## 六.五、托盘与设置窗口

### 为什么现在就要做

程序目前**没有任何正常退出的途径**：窗口无边框、`skipTaskbar` 为真、没有托盘，
只能去任务管理器杀进程。托盘补的是这个真窟窿，不只是锦上添花。

### 托盘

复用已有的 `icons/icon.ico`。Tauri 需要开 `tray-icon` feature（已确认可用）。

```
右键菜单                左键单击 → 打开设置窗口
├ 设置…
├ 调整面板位置           （与 Ctrl+Alt+F10 共用同一份编辑态，别各存一份）
├ ──────
└ 退出
```

### 设置窗口

Tauri 第二个 window，普通带边框小窗，页面 `ui/settings.html`，
沿用覆盖层的深色配色与 Bahnschrift 字体。

1. **显示项开关**（9 个）：中路符 / 赏金 / 莲花 / 智慧 / 堆野 /
   敌塔防 / 敌买活 / 净资产 / 眼位小地图
2. **面板缩放**：0.8 ~ 2.0，默认 1.0。用 `transform: scale()` 实现——
   走合成器，符合 v1 定的"动画只用 transform/opacity"约束。
   注意面板本身已有 `translateX(-50%)` 居中，要写成
   `transform: translateX(-50%) scale(n)` 并把 `transform-origin` 设为顶部中央。
3. **面板背景透明度**：0.3 ~ 0.9，默认 0.72。
   **只调背景底色的 alpha，不调文字和圆环。** 可读性是设计文档的第一条硬约束——
   背景是不断变化的游戏画面，整块调淡会让数字糊在团战特效上。
   调背景既能达到"不那么挡眼"，又保证数字始终清晰。
4. **打开常数表目录**按钮：现在改符间隔要自己翻到 `%APPDATA%` 深处，很不友好。

### 配置与生效

存 `settings.json` 于配置目录（与 `constants/`、`layout.json` 同级）：

```json
{
  "show": { "mid": true, "bounty": true, "lotus": true, "wisdom": true,
            "stack": true, "glyph": true, "buyback": true, "econ": true,
            "wardmap": true },
  "scale": 1.0,
  "bgOpacity": 0.72
}
```

Rust 提供 `get_settings` / `set_settings` 命令；设置窗口保存后 emit `settings` 事件，
**覆盖层实时应用，不需重启**。

**关于关掉某项后面板变窄**：这与 v1 定的"宽度写死防抖动"不冲突。
那条针对的是游戏中净资产位数变化导致的横移；改设置是用户主动的一次性操作，
变窄是预期内的结果。

## 七、明确不做

- **敌方英雄失踪计时**：数据可行（`minimap_enemyicon` 带英雄名+坐标），
  但实测每个敌人每局消失 11~19 次、中位仅 5~19 秒，做成提醒会非常吵。
  留作 v3 候选，届时需要先想清楚"多久算失踪"。
- **敌方塔血量**：`buildings` 段只有己方，无数据。
- **观察者哨塔归属**：11 座哨塔的 `team` 恒为 5（中立），占领状态不体现在 GSI 里。
