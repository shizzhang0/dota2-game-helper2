# 面板拆块：四个可独立摆位的块

> **历史过程记录，不再维护。** 拆块已经做完，结论都已并入
> [../design/overlay.md](../design/overlay.md)，两边冲突时以 design 为准。
> 保留本文是为了记住当时是怎么权衡的。

## 为什么要拆

现在是一整条横向面板，尺寸由 `overlay.css` 里写死的值算出来：

| | |
|---|---|
| 宽 | `324`（五个符）+ `170`（塔防+买活）+ `116`（净资产）+ `116`（眼位）+ 分隔与间距 `63` + 内边距 `24` + 边框 `2` = **815px** |
| 1.5× 缩放（实际在用的值） | **1223px**，1920 屏上占 **64%** |
| 高 | **126px**，完全由眼位小地图的 108px 撑起 |

三个结构性问题：

1. **眼位小地图是异类。** 它 108px 高，其余格子只有 67px —— 面板高度被它一个人决定，
   另外八格上下各空出 20px。而它是**地图**，语义上属于小地图那一侧，不属于顶部一长条。
   它一个人贡献了面板 14% 的宽和 100% 的高。
2. **今天的面板压在计分板上。** `top: 14px` + 居中 + 1220px 宽，正横跨 Dota 顶部计分板。
3. **九项视觉权重相同**，`far/near/now` 三档只改了透明度 .78→1 和环粗 4→6。

拆块解决 1 和 2。第 3 条是格子内部的视觉层级问题，**不在本次范围内**。

## 分组

按"一起看"的关系分四组，各自一份坐标：

| id | 内容 | 1× 尺寸 | 1.5× 尺寸 |
|---|---|---|---|
| `timers` | 中路符 · 赏金 · 莲花 · 智慧 · 堆野 | 350×85 | 525×128 |
| `enemy` | 敌塔防 · 敌买活 | 196×85 | 294×128 |
| `econ` | 净资产 · GPM · XPM | 142×70 | 213×105 |
| `wardmap` | 眼位小地图 | 142×126 | 213×189 |

尺寸是实测的 `offsetWidth` / `offsetHeight`（含 1px 边框）。
**`econ` 比另外两个矮**——它那格没有圆环，CSS 里写死了 `height: 52px`。

每块自带半透明底板 + 圆角边框（沿用现在 `.panel` 的样式）。
**`.sep` 竖分隔线全部删除**——块与块之间已经有物理间隔，不需要再画线。

**一个块里的格子被显示项开关全部关掉时，整块连底板一起消失**，不留空壳。
（现有逻辑是逐格 `hidden`，块容器需要跟着算。）

## 默认摆位

全部按视口比例算，**不写死像素**，以适应不同分辨率。

| 块 | x | y | 1920×1080 / 1.5× 下的实测值 |
|---|---|---|---|
| `timers` | 水平居中 | `屏高 × 7.5%` | (698, 81) |
| `enemy` | 水平居中 | `timers` 下方 10px | (813, 217) |
| `econ` | `16` | 与 `timers` 同一水平线 | (16, 81) |
| `wardmap` | `16` | `econ` 下方 10px | (16, 196) |

`timers` 与 `enemy` 都水平居中，只是 y 不同——规则比"挂在右边"少一条。

`y = 屏高 × 7.5%` 是为了让开计分板；今天的 14px 是压在它上面的。
顶部这一摞到 y=345，左列到 y=385，都在视线焦点（y≈540）上方。

## 数据模型

`layout.json` 从单坐标变成四坐标：

```json
{
  "timers":  { "x": 698, "y": 81 },
  "enemy":   { "x": 813, "y": 217 },
  "econ":    { "x": 16,  "y": 81 },
  "wardmap": { "x": 16,  "y": 196 }
}
```

**迁移**：老文件里的顶层 `{x, y}` 当作 `timers` 的位置沿用，其余三块取默认值。
不写迁移的话用户已经摆好的位置会丢。

## 编辑态

四块**各自虚线描边、各自可拖**，松手各存各的坐标。块内没有交互控件，整块都能当拖拽区。

### 设置卡片：可拖，但必须有专门的把手

卡片本身也可拖，**位置不存盘**，每次进编辑态回到屏幕中央偏下。
（四块之后"面板"没有唯一所指，原来的"锚在面板下方跟随"失去意义。）

> **卡片不能整块当拖拽区——这会重演 design/overlay.md 里记的第 3 号坑。**
> 拖拽在 `pointerdown` 时 `setPointerCapture`，之后 `pointerup` 被改派到捕获元素，
> `click` 便落在卡片而不是它内部的按钮上。卡片里装着「完成」按钮、九个复选框、
> 两个滑块和一个下拉框，**整块可拖会把它们全部打死**，且「完成」失效等于编辑态出不去。
>
> 所以卡片顶部加一条**标题栏当把手**，只有在把手上 `pointerdown` 才进入拖拽。
> 四个块没有这个问题，它们内部没有任何可点的东西。

### 恢复默认摆位

卡片里新增一个按钮。**这是拆块必须补的安全网，不是锦上添花**：
四块独立可拖之后，把某一块拖到 `x = -400` 就彻底找不回来了——它平时隐藏，
编辑态下也在屏幕外，没有任何入口能救。今天单块也有这个风险，只是概率低四倍。

### 越界钳位

启动读盘时把每块坐标钳进视口（保证至少有一角可见）。
顺带解决换分辨率、拔掉副屏之后坐标失效的问题。

## 明确不做

- **不动格子内部的视觉**（圆环、字号、`far/near/now` 分档）。那是另一件事，拆块先落地。
- **缩放与透明度仍是全局一套**，不给每块单独设。每块一套意味着卡片上要多八个滑块，
  而"眼位图 1.2× 但净资产 1.6×"这个需求从没出现过。真需要了再加。
- **不做块之间的吸附对齐。**
- **不做每块独立显隐**——已经有九个显示项开关了。

## 验收

- [ ] 四块能各自拖动，松手后重启位置保留
- [ ] 老 `layout.json`（顶层 `{x,y}`）启动后 `timers` 落在原位置，其余三块在默认位
- [ ] 把某块拖出屏幕外再重启，它被钳回视口内可见
- [ ] 「恢复默认摆位」把四块复位
- [ ] 卡片能靠标题栏拖动，且拖完之后**九个复选框、两个滑块、下拉框、「完成」按钮全部仍可点**
- [ ] 关掉某组内全部显示项时，该块的底板一起消失
- [ ] 首次运行（无 `layout.json`）在 1920×1080 与另一分辨率下默认摆位都不越界
