# 覆盖层图标化

> **历史过程记录，不再维护。** 已实施，结论都已并入
> [../design/overlay.md](../design/overlay.md)，两边冲突时以 design 为准。
> 保留本文是为了记住当时是怎么权衡的（尤其是被否掉的那些候选）。

## 为什么

覆盖层上现在有 **12 条中文**：

| 位置 | 内容 |
|---|---|
| `timers.js` `KIND_LABEL` | 赏金 · 圣水 · 强化 · 智慧 · 莲花 · 堆野 |
| `render.js` | 中·{符} · 敌塔防 · 可用 · 敌买活 · 净资产 |
| `wardmap.js` | 眼位 |

把它们全换成图标，收益不是"省掉 12 条翻译"，而是**那条写死的宽度约束会自己消失**。

backlog 里记着多语言最难的一块：`.cell` 60px、买活 104px、净资产 116px 全是写死的，
写死是为了防抖动；而"净资产"换成 `Net Worth` 会更宽，直接翻译会撑破或截断，
所以"得让宽度跟着语言走"。**面板上没有词，这个问题就不存在了。**

剩下的多语言正是 backlog 早就判定为"十几行就够"的那部分：
**只剩编辑态卡片和托盘右键菜单两处**。

## 硬约束：不用 Valve 的素材

仓库是公开的 MIT。backlog 里为了托盘图标已经记过这条——
"前作用的是 Valve 的压制之刃素材，本仓库公开，不宜沿用"。铺一整套游戏图标是同一个问题乘以十。
运行时去拉也不行：程序在 #7 之后一个网络请求都不发。

**做法是：原创描边式 SVG，沿用游戏的视觉语汇（形状语言 + 配色），但不是 Valve 的文件。**
这是现有决定的延续——`overlay.css` 里那组符色注释就写着"取自游戏中各事件自身的颜色"。
颜色早就在对齐了，这次让形状跟上。

## 图标集

全部 24×24 viewBox、描边式、`stroke="currentColor"`，颜色由所在格子的 `--accent` 决定。

| 项 | 图标 | 备注 |
|---|---|---|
| 中路符 | 币堆 / 水滴 / 双箭头 | **随阶段变**，与常数表的 `kind` 一一对应 |
| 赏金符 | **钱袋** | 见下面"为什么不是币堆" |
| 莲花 | 莲花（三瓣） | |
| 智慧神符 | 摊开的书 | |
| 堆野 | **堆叠层**（三层菱形） | 见下面"为什么不是营地框" |
| 敌方塔防 | 盾 | |
| 敌方买活 | 回转箭头 | 五个英雄色圆点保持不变 |
| 净资产 | 币 | GPM / XPM 是通用缩写，保留文字 |
| 眼位地图 | **面板上不放标签** | 眼 + 塔两个图标只用在编辑态卡片那一行 |

### 眼位地图为什么不放标签

其余格子都是"圆环 + 数字"，脱离标签认不出是什么；但**一张画着塔和彩色圆点的
Dota 地图是自明的**，不需要一个图标告诉你"这是地图"。「眼位」两个字本来就冗余，
换成图标只是把冗余换了种形式。

而且灰色的塔图标会**和地图自己的配色撞**——地图上灰塔的含义是"已被推掉"。
标签灰 `#B3BECB` 比死塔灰 `#5A6470 @.3` 亮不少，实际多半分得开，
但那属于"要靠亮度差去分辨"的设计，不够干净。

顺带矮 15px：眼位块是四块里最高的（214×213），去掉标签约变成 214×198。

**眼 + 塔这对图标仍然要画**，放在编辑态卡片「眼位小地图」那一行——
那里才是需要它的地方（说明这块地图画了哪两类东西），且有文字作伴，不存在撞色的解读风险。

### 尺寸

**基准 14px。** 实测 12px 下智慧的书和莲花的花瓣会糊；而标签位在 1× 下约 12px、
实际使用的缩放是 1.15~1.5×，落在 16~21px。取 14 是让 1× 也还能读。

图标是 SVG，跟着 `--panel-scale` 一起缩放，不需要新的尺寸开关。
**实测确认**：缩放 2× 时 SVG 布局尺寸仍是 52、渲染尺寸变成 104，
浏览器按新尺寸重新光栅化而不是拉伸位图，边缘保持干净的矢量边。

### 真正的风险在小端，不在大端

描边式图标的 `stroke-width="1.7"` 是 24 viewBox 里的值，换算成实际像素：

| 面板缩放 | 图标显示 | 描边实际粗细 |
|---|---|---|
| **0.8×** | 11.2px | **0.79px** |
| 1× | 14px | 0.99px |
| 1.5× | 21px | 1.49px |
| 2× | 28px | 1.98px |

**小于 1px 的描边会被抗锯齿摊成一层浅灰**，再叠上远期格子本身的 `opacity: .78`，
在明亮的团战画面上可能就看不清了。

两个备选，**等实现出来看实物再定，不预先拍板**：描边加粗到 `2.0`，
或把基准从 14px 提到 16px。

### 为什么赏金不是币堆

中路格子的图标随阶段变，而 **0:00 那一阶段就是赏金**——和旁边独立的赏金符格子会
一模一样。现在靠 `中·` 这个前缀区分，去掉文字就没了。

只有赏金阶段会撞（圣水的水滴、强化的双箭头在别处没有对应格子），所以只改赏金符那一格。

排除掉的候选：**三枚散币**——它和币堆是同一个视觉家族（都是圆/椭圆堆叠），
扫一眼最容易看混，正好没解决要解决的问题。**宝箱**轮廓差得更开，
但箱盖线和锁扣在 14px 下细节太多。

### 为什么堆野不是营地框

严格说**营地刷新框更准**：这个格子数的是"下一个整分钟野怪刷新"，是事件不是动作；
而 Dota Plus 自己的堆野提示就是按住 Alt 时画在营地上的刷新框，那才是游戏的原生隐喻。

但虚线框在 14px 下容易糊成一团，而堆叠层的轮廓在小尺寸下最清晰。
**这里让位给可读性。**

> 如果将来做"营地画到眼位小地图上"，那时该换回营地框——它和地图是同一个隐喻。
> 那件事的前置是**没有营地坐标**：塔有 `towers.json`（22 座实测坐标），营地没有，
> 而且录像里野怪营地不作为静态对象出现（只有活着的野怪单位），要像当初测塔那样重新测一套。

## 一个要一并决定的状态显示

敌方塔防的 `ready` 态现在在**数字位**显示「可用」两个字。去掉文字之后：

**数字位永远只放数字。** `ready` 时数字位留空，靠**环画满 + 盾点亮**表达；
冷却时数字位是倒计时、盾压暗。

这条要在真实画面上看一眼再定——空的数字位配满环是否够清楚。

## 卡片同时当图例

编辑态卡片里那九个显示项开关，**每行前面加上对应图标**。卡片就同时是设置和图例，
一份数据两用——和眼位图例复用地图 class 是同一个思路，颜色和形状永远不会脱节。

文字集中在卡片，而卡片正好是唯一需要翻译的地方。

## 覆盖层上仍然保留的文字

- **倒计时数字**、**净资产数字** —— 数字不需要翻译
- **GPM / XPM** —— 通用缩写，Dota 各语言版本都这么写

## 不在本次范围内

- **格子宽度与布局重算**。文字没了，`.cell` 60px、买活 104px、净资产 116px 这些
  写死值就该重定——但那是 backlog 里「面板布局」那条独立的事，先做图标，
  宽度才有得算。本次**保持现有宽度不动**，图标塞进原来标签的位置。
- **多语言**。仍排最后。
- **格子内部的视觉层级**（`far/near/now` 分档）。

/** 14px 是基准：实测 12px 下书和莲花的细节会糊，而标签位在 1× 下约 12px、
    常用缩放 1.15~1.5× 落在 16~21px，取 14 让 1× 也还能读。 */
export function icon(name, size = 14) {
  const d = P[name];
  if (!d) return "";
  return `<svg class="ico" width="${size}" height="${size}" viewBox="0 0 24 24" aria-hidden="true"
     fill="none" stroke="currentColor" stroke-width="1.7"
     stroke-linecap="round" stroke-linejoin="round">${d}</svg>`;
}

  glyph: "glyph", buyback: "buyback", econ: "coin",
};
