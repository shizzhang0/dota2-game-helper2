## 功能

### 用眼架那套"按价格对账"优化净资产（2026-10-08 记）

眼架的做法是：这一包花掉的钱减去看得见的资产增加，剩下的部分去对真眼价格的整数倍，
对上了就认定钱变成了眼架里的存货（见 [design/networth.md](design/networth.md) 的眼架一节）。
想看这个思路能不能推广：**信使在路上的东西**、储藏处到身上的交接，现在靠时间窗和猜测，
能不能改成"花掉的钱对得上哪件东西的价格"。

做之前过一遍 [design/networth.md](design/networth.md) 里启发式规则的证据表：
每条新判据都要单独关掉逐次算账，真阳性少的不进正式代码。
价格对账最怕的是**巧合**——几百块的差额能凑上的组合很多，门槛要从价格分布上定，不能事后凑。

### 针对开了 Dota Plus 的用户优化布局（2026-10-15 记）

现在所有位置都是按**没开 Plus** 量的（用户没开、也不打算买）。开了 Plus 之后按住 Alt，计时牌下面那一块是另一个样子，
已知的情况（量自三张开 Plus 的直播截图，按 1080 高换算，见 [design/overlay.md](design/overlay.md)「贴着 Dota 自己的界面画」）：

| | 没开 Plus | 开了 Plus（按住 Alt） |
|---|---|---|
| Plus 自带的五个符文倒计时 | 没有 | 计时牌下 64~98，外径约 34、中心距约 40；**不按 Alt 时不显示** |
| 「x:xx UNTIL NIGHT」那行字 | 73~84 | 被挤到 114~127 |
| 我们的倒计时（42~70） | 塞在计时牌和那行字之间 | **和 Plus 自带的上下叠在一起**（70 对 64，压住 6 左右），而且内容重复 |

要想清楚的：

- **怎么知道用户开了 Plus**：GSI 不推这个；Steam 的 `user_convars.vcfg` 里有没有相关的键没查过。
  查不到的话，设置卡片加一个「我开了 Dota Plus」的勾
- **开了 Plus 时倒计时怎么办**：内容和 Plus 自带的一样（中路符 / 赏金 / 智慧 / 莲花 / 堆野），可能干脆不画；
  但 Plus 的只在按住 Alt 时出现，我们的平时也在——不按 Alt 时还要不要显示？
- **其余几样要不要动**：买活那一行（68）、净资产、塔防、眼位，开 Plus 时有没有别的东西压上来，没核对过——
  直播截图都不清楚，需要一张**开了 Plus 的清晰全屏截图**（按 Alt 和不按 Alt 各一张，2560×1600 最好）
- 量完把结论补进 overlay.md，待验清单第七节「Dota Plus」那条跟着更新

## 已明确不做

记在这里免得反复讨论。理由见各自的设计文档。

| | 原因 |
|---|---|
| 开机自启 | 用不着 |
| 拖动摆位 | **v1.4.0 起不再能拖**（2026-10-09 用户确认不加回来）：买活、塔防、眼位贴着顶栏和小地图，拖了反而对不准；倒计时和净资产的位置是定好的、跟着分辨率缩放。对不上的界面该改代码里量的值 |
| 每块单独调大小 / 整体缩放 / 透明度 / 底板 | v1.4.0 随拖动一起去掉：大小跟着游戏界面按屏高缩放，再给旋钮只会把它调得和游戏界面错开 |
| 自己"买不起买活"的提示 | 右下角金钱那里原生已经提示（2026-10-09 定） |
| 语音提示 | 前作的方案，吵 |
| 白天黑夜倒计时 | 游戏原生已显示 |
| 肉山 / 不朽盾计时 | 同上，游戏原生已显示（2026-09-08 定）。数据其实是够的——顶层 `roshan` 段玩家视角确实没有，但 `roshan_killed`（带 `killed_by_team`）和 `aegis_picked_up` 两个事件都会推过来，足以算重生窗口和盾过期。不做是因为原生已有，不是因为做不了。 |
| 任何输入模拟 | 违背"纯接收器"定位 |
| 敌方塔血量 | `buildings` 段只有己方，无数据 |
| 观察者哨塔归属 | `team` 恒为 5（中立），GSI 不体现占领状态 |
| 队友 / 敌人的个体数据 | GSI 玩家视角不提供 |
| 掉在地上的装备计入净资产 | GSI 只推自己物品栏，无解 |
| 价格表旧了自动提示 | **2026-09-23 定。** 要主动提示"表旧了"，程序得在运行时知道**当前**装的是哪个 Dota 版本，那要读游戏安装目录——与"发布出去的程序不碰安装目录"冲突。能做的那一半已经做了：开发区显示程序版本和价格表对齐的 Dota 版本，用户报"数字不对"时能直接念出来，见 [design/overlay.md](design/overlay.md) 的「开发区」。 |
| 格子内部再做视觉层级 | **按现状保留（2026-09-20 定）。** 面板拆四块解决了"块摆在哪"；格子内部 `far/near/now` 三档只有透明度 .78→1 和环粗 4→6，九项基本等权重。曾记为"等实战看清楚哪些格子是一眼要看到的再说"，实战下来的判断是**现在这样就够用**。真要动，先得拿出"按住 Alt 那半秒找错了目标"的具体例子，否则放大/压暗只是换一种拍脑袋。 |
| 敌方英雄失踪计时 | **2026-09-21 定。** 数据本来可行（`minimap_enemyicon` 带英雄名和坐标），但**游戏原生的小地图已经把这件事显示了**——敌方英雄在哪、还在不在视野里，抬头就能看见。我们再算一遍"消失了多久"是在重复它已经给的信息，而这个覆盖层的定位是"对局中游戏**不告诉你**的事"。<br><br>实现上也不占便宜：实测每个敌人每局消失 11~19 次、中位仅 5~19 秒，做成提醒会非常吵，得先解决"多久才算失踪"和"怎么表达不打扰"——**为一件原生已有的事付这个设计成本不划算**。 |
| 浏览器版覆盖层（网页直接收 GSI） | 技术上要在本机再跑一个服务把 GSI 转给页面，等于把一个 exe 换成「服务 + 浏览器」；而覆盖层的全部价值在于**压在游戏画面上**，浏览器窗口做不到。（原先记在 backlog 的「文档与项目主页」一节里，那节已完成删除。）|
| 观战 / 看回放时工作 | 定位就是"你正在打的那一局"（2026-09-08 定）。观战和回放已经有一堆现成工具，而这个覆盖层要解决的是对局中游戏不告诉你的事。技术上能做半套（符与眼位只依赖 `map` / `minimap`，观战下反而更全；坏的只有净资产和敌方买活），但半开的面板会让人以为是坏了。改成**检测到就整窗隐藏**，判定方式见 [design/overlay.md](design/overlay.md) 的"智能显隐"。 |
