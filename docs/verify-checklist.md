# 待验证清单

实战里需要人工确认的事项——**做了但还没在真实对局里确认过**的。

> **只剩净资产这一节了**（2026-09-08）。眼位小地图、倒计时、行为与交互三节全部验完。
> 剩下的几条都是口径边角：**没有一条会改设计**，只是确认某件装备算多少钱，
> 单件误差从几十到几千金。发版不必等它们。
验完在 `- [ ]` 打勾，并把实测值写回对应的设计文档。

还没做的事在 [backlog.md](backlog.md)。

**对账方法**（净资产类都照这个做，选点比多测几局更重要）：

1. 打之前在编辑态卡片的「开发」里勾上**记录对局数据**
2. 打完用回放看官方「财产总和」，与面板对账
3. **只选自己阵亡、且没有信使在途的时刻**——那时金钱只有 +2/秒的被动收入，
   一两秒的对齐误差只有个位数。信使送达前后、补刀密集的时刻两秒就能差 100 以上，
   没有分辨力，别在那里取点
4. 有差额就报「大概时间 + 官方数字」，能直接定位到是哪一包、哪件装备

> **下面这些场景大多不好主动触发**（队友塞装备、从储藏处直接卖东西、吞月之碎片、
> 炼金送神杖）。别为了验它们去改打法——**每局都开着录制**，等场景自然发生了再回头对账
> 就行。这几条的共同点是单件误差有限、且出现频率低，压着不影响用。

## 一、净资产

已验证（2026-09-08，快速模式 matchid 8988706327，六个时间点全部吻合）：
**消耗品按充能折算**（用剩的吃树 1/3 记 30、叠起来的两个烟记 100）·
**中立物品与强化不计** · **白送的 TP 不计、自购的计** · **眼架按里面装的眼计价**。
这一轮修掉三个 bug：消耗品叠加只算一份、眼架按固定价 50、传送卷轴扣错张。

> 原先这里举的例子是"树苗 1/4 记 23"。**树苗在价格表里没有 `charges`**
> （`{"cost": 55, "consumable": true}`），走不到折价公式，那个数算不出来——
> 折价机制本身验证成立，错的只是例子。换成真能对上的吃树（90 金 3 充能）。

已验证（2026-09-07，快速模式 matchid 8986026437，七个时间点全部吻合）：
开局白送 TP 不计 · 阵亡赠送的 TP 不计（判据 2026-09-17 换成 `player.deaths`）·
储藏处计入 · 信使在途计入 · 中立物品不计 ·
魔杖 460 / 掠夺者 2800 / 辉耀 4700 / 冰眼 5900 / 法师克星 3100 / 相位鞋 1400 /
影刃 3250 / 银月 5700 / 魔晶 1400 · 卖出按半价回收 · 龙心 5200。

> 龙心当时是靠覆盖表改到 5200 的。2026-09-09 价格源换成游戏本体自己的
> `items.txt` 后它本来就是 5200，覆盖表连带删掉——这一条的验证结论不变。

- [x] **月之碎片（吞噬后只剩 buff）** 我们按 4000 计，**官方也计 4000**（2026-09-14 验完）。
  它**不走价格表**——吞掉之后物品栏里没有这件东西，只剩一个 modifier，
  所以取值在 `constants/normal.json` 的 `moonShardValue`，改那里，不是价格表。

  观战录制里力丸 21:07 吞下一颗：官方净资产 40988 -> 44990，同一秒金钱只涨 2，
  **装备侧正好 +4000**。我们那一路的差值从 19:14 起一直是 0、吞下时也没跳，
  说明两边一致。

- [x] **阿哈利姆祝福 5800 与神杖 4200 的区分**（2026-09-14 验完，并修掉一个 bug）
  两者共用同一个 buff 名，我们靠物品栏历史判断档次。

  用**观战回放**验的（一局天辉有炼金，先后送出四根杖）。结果比预想的糟：
  受赠方我们记的不是 5800 也不是 4200，而是 **0**——炼金送出的杖修饰符名叫
  `modifier_item_ultimate_scepter_consumed_alchemist`，**尾巴带来源后缀**，
  而代码是精确查表。改成前缀匹配后，受赠四人的逐包一致率
  38.1/48.1/27.5/52.5% → 78.4/57.6/52.6/86.3%，同局夜魇五人（无赠杖）纹丝不动。
  详见 [design/networth.md](design/networth.md) 的「修饰符名带来源后缀」。

- [ ] **队友代拿的物品**（队友把圣剑/宝石塞给你带）
  我们按 `purchaser` 排除。官方是否也排除？
  注意 `purchaser` 是全局 0-9 槽位，夜魇要 +5。

  两局观战录制里**确实有** `purchaser` 不是自己的物品，但全是
  `foragers_health`（0 金）、`tango_single`（30 金）这类，**不足以验"圣剑 5600"
  那个量级**——30 金的差额和别的噪声分不开。机制层面可以探（找 `purchaser != 自己`
  的包，看官方有没有把它算进去），但要下结论还得等一件真·贵重物品被塞过来。

- [x] **不朽盾不计入**（2026-09-14 验完）。观战录制里幻影刺客 23:15 拿到盾：
  官方净资产 25374 -> 25644，而金钱同步 +270，**装备侧 +0**——官方不给盾记钱。
  我们价格表里 `aegis` 本来就是 0，一致。该玩家全程只有 ±100 的已知 TP 偏差，
  从没出现过盾那个量级的跳变。

- [ ] **肉山掉落的另外两样**：奶酪、阿哈利姆祝福（肉山版）。
  两局录制里都没出现，还没验。奶酪价格表里是 1000、祝福是 5800，
  按物品价计——但官方算不算，同不朽盾一样需要实例。

- [x] **传送卷轴的口径**（2026-09-17 定案，2026-09-14 起曾重新存疑）
  口径「自购的计、白送的不计、用掉的先扣白送」**全部由 [Dota 2 Wiki][tpwiki] 和
  7.29 更新日志确认**：开局自带 1 张免费的、被英雄击杀再送 1 张、免费的不计入
  Net Worth、一摞里没有价值的先被用掉。存疑的从来只是"怎么认出免费那张"。

  判据已从 `hero.alive` 换成 **`player.deaths` 这一包涨没涨**。142 次充能增加里
  `alive` 有 14 次（约 10%）比发放晚一包，那一包还报着活着 → 多算 100；
  `player.deaths` 一次都不晚。四局观战全量对账**四局全部改善**
  （一致率 50.3→59.5 / 45.3→53.2 / 56.6→60.2 / 55.7→60.7），
  40 个玩家局的终值只有一个变差。细节见 [netWorth 设计](design/networth.md)。

[tpwiki]: https://dota2.fandom.com/wiki/Town_Portal_Scroll

- [ ] **白送的魔晶怎么算**（2026-09-18 **缺样本**；前一天记的"2 例白送"是错的，已更正）
  魔晶除了花 1400 买，还能靠**打掉痛苦魔方直接赠送**（给本队经济最低且没有魔晶的
  两人之一，不掉落物品）。赠送的那份官方大概率不计入净资产，而我们无条件加 1400。

  但**四局录制里 23 个魔晶全部是自购，白送样本数为 0**，这条口径没被真正考验过。
  2026-09-17 曾判定其中 2 例是白送（"拿到时金币纹丝不动"），**判据看错了包**：
  买来的魔晶会先在物品栏里待十几到二十秒才被吃掉，那两例的 −1398 出现在标志翻转
  **二十秒之前**，形状和其余 21 例一样。那两人终值上的 +1400 因此**原因未明**。

  已排掉的判据：买魔晶**不发** `CHAT_MESSAGE_ITEM_PURCHASE`（`id=609` 零条，
  同局 41 种其他物品 id 全部正常）· 物品栏出现过魔晶物品（23 例里 8 例没采到）·
  基线掉 1400（买入期间按物品计价，基线根本不动）。

  **待办：录一局有魔方被打掉的观战录制**（观战有 `net_worth` 当真值，十人全看得到，
  哪边打掉都行），确认三件事：官方认不认那 1400 · 赠送走不走物品栏 · 有没有播报事件。
  见 [netWorth 设计](design/networth.md)。

- [ ] **从储藏处直接卖东西**（2026-09-14 已确认会发生并已修，待实战确认）
  原先记的是"先确认到底会不会发生"。录像 C 里发生了：21:10 卖掉一个 null_talisman，
  净资产当场虚高 505，**一直虚高到 22:40**——正好是在途账的 90 秒 TTL。
  v1.2.1 按"同一包里金钱涨了 ≈V 或 ≈V/2"把它和"被信使取走"分开，三局五个样本全中，
  见 [design/networth.md](design/networth.md) 的"卖出要先排除掉"。

  **还剩一类漏判**：`infused_raindrop` 这种有充能但没标 consumable 的物品，
  我们按全价算而官方按剩余充能折价，卖出时金钱对不上 V 也对不上 V/2。
  那属于计价口径，不在这条里。

- **掉在地上的装备：无解**，GSI 只推自己物品栏，不用验。

已验证（2026-09-08 实战）：**对局中途启动程序**——开着游戏再打开覆盖层，净资产正确。

## 二、眼位小地图

**这块曾经完全是靠三局 dump 离线做的**，一度是全清单里风险最高的一节。
**现在整节验完了。**

已验证（2026-09-08 实战）：

- 我方眼倒计时（假眼 360s / 真眼 420s，归零与视野消失同步）
- 被排检测无误报漏报
- 敌方眼位置与按类型保留 360s / 420s
- 塔的灰点与推塔进度一致
- 中途启动：程序启动前就已存在的眼只画点、不画倒计时
- 眼多时标签不糊（只标 60 秒内到期的，这个阈值合适）

**2026-09-15 用观战录制做了逐包复验**（原来那轮是看面板验的）。数字记在
[design/wards.md](design/wards.md) 的「观战录制的逐包验证」，结论：

- 寿命常数有权威出处：游戏文件里 `lifetime = 360 / 420`，实测多出的 7 秒是 GSI 上报延迟
- 泉水误认、(0,0) 幽灵条目：三局十万余条，**各 0 次**
- 被排检测：**0 误报**；8 次漏报全是剩余时间落在 `wardKilledGrace` 内的，属设计意图
- 敌方眼（合成部分视野验的）：**0 漏报**；代价是显示出来的敌方眼有 0.5~20% 的时间
  其实已经没了，最长挂到寿命上限
