# 待验证清单

实战里需要人工确认的事项——**做了但还没在真实对局里确认过**的。
验完在 `- [ ]` 打勾，并把实测值写回对应的设计文档。

还没做的事在 [backlog.md](backlog.md)。

**对账方法**（净资产类都照这个做，选点比多测几局更重要）：

1. 打之前在编辑态卡片的「开发」里勾上**记录对局数据**
2. 打完用回放看官方「财产总和」，与面板对账
3. **只选自己阵亡、且没有信使在途的时刻**——那时金钱只有 +2/秒的被动收入，
   一两秒的对齐误差只有个位数。信使送达前后、补刀密集的时刻两秒就能差 100 以上，
   没有分辨力，别在那里取点
4. 有差额就报「大概时间 + 官方数字」，能直接定位到是哪一包、哪件装备

> **下面这些场景大多不好主动触发**（队友塞装备、从储藏处直接卖东西、吞月之碎片、
> 炼金送神杖）。别为了验它们去改打法——**每局都开着录制**，等场景自然发生了再回头对账
> 就行。这几条的共同点是单件误差有限、且出现频率低，压着不影响用。

## 一、净资产

已验证（2026-09-07，快速模式 matchid 8986026437，七个时间点全部吻合）：
开局白送 TP 不计 · 阵亡赠送的 TP 不计 · 储藏处计入 · 信使在途计入 · 中立物品不计 ·
魔杖 460 / 掠夺者 2800 / 辉耀 4700 / 冰眼 5900 / 法师克星 3100 / 相位鞋 1400 /
影刃 3250 / 银月 5700 / 魔晶 1400 · 卖出按半价回收 · 龙心需覆盖为 5200。

- [ ] **消耗品按剩余充能折价**
  我们算 `价格 × 当前充能 ÷ 满充能`（树苗 x1 记 30 而不是 90）。
  官方是否也折价？验法：手里只留一组用剩的树苗/净化，其余物品固定，看差额。
  影响：单件几十金。

- [ ] **月之碎片（吞噬后只剩 buff）** 我们按 4000 计。
  同时确认这个价格是否也需要进覆盖表。

- [ ] **阿哈利姆祝福 5800 与神杖 4200 的区分**
  两者共用同一个 buff 名，我们靠物品栏历史判断档次。
  待验场景：**炼金术士把神杖送给你**（物品栏里从没出现过东西，应记 4200）。

- [ ] **队友代拿的物品**（队友把圣剑/宝石塞给你带）
  我们按 `purchaser` 排除。官方是否也排除？
  注意 `purchaser` 是全局 0-9 槽位，夜魇要 +5。

- [ ] **肉山掉落**（奶酪、不朽盾、阿哈利姆祝福）是否计入官方口径。
  上一局拿到过不朽盾（21:54），但当时正差着龙心那 100，没法单独判断。

- [ ] **从储藏处直接卖东西**
  已知会让净资产虚高最多 90 秒（在途账要等 TTL 超时才消）。
  这个操作少见，先确认到底会不会发生，再决定值不值得修。

- [ ] **对局中途启动程序**
  开着游戏再打开覆盖层，净资产是否正确。

- **掉在地上的装备：无解**，GSI 只推自己物品栏，不用验。

## 二、眼位小地图

**这块曾经完全是靠三局 dump 离线做的**，一度是全清单里风险最高的一节。

已验证（2026-09-08 实战）：我方眼倒计时（假眼 360s / 真眼 420s，归零与视野消失同步）·
被排检测无误报漏报 · 敌方眼位置与按类型保留 360s/420s · 塔的灰点与推塔进度一致。

- [ ] **中途启动**：程序启动前就已存在的眼，应当只画点、不画倒计时。

- [ ] **眼多的时候标签会不会糊**
  只有 60 秒内到期的才标数字（实测同时最多 14 个己方眼）。这个阈值合不合适。

## 四、行为与交互

已验证（2026-09-08 实战）：**换局 / 重开后状态干净重置**（倒计时、眼、净资产、塔防
四份状态都靠 `info.newMatch` 触发，连着打验过）。

- [ ] **设置项改动即时生效**，九个显示开关逐个开关一遍

- [ ] **缩放与透明度在真实战斗画面里的可读性**
  透明度调低时数字会不会在明亮团战里糊掉

- [ ] **长时间挂机**：跑满一局（40 分钟以上）内存与 CPU 是否稳定
  2026-09-08 初步观察：打的过程中没感觉到异常，内存占用正常。但这不等于验过——
  泄漏要的是**满局的曲线**，几分钟的绝对值看不出斜率。真要验就开着跑完一局，
  前后各记一次数。已排进后续测试。
