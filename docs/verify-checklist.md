# 待验证清单

实战里需要人工确认的事项——**做了但还没在真实对局里确认过**的。

> **只剩一条了**（2026-09-21）：肉山掉的阿哈利姆祝福，要肉山第三次死在天辉侧
> 才会掉，纯看运气。眼位小地图、倒计时、行为与交互三节早已验完，
> 净资产这一节的其余各条也都验完了。**发版不必等它。**
验完在 `- [ ]` 打勾，并把实测值写回对应的设计文档。

还没做的事在 [backlog.md](backlog.md)。

**对账方法**（净资产类都照这个做，选点比多测几局更重要）：

1. 打之前在编辑态卡片的「开发」里勾上**记录对局数据**
2. 打完用回放看官方「财产总和」，与面板对账
3. **只选自己阵亡、且没有信使在途的时刻**——那时金钱只有 +2/秒的被动收入，
   一两秒的对齐误差只有个位数。信使送达前后、补刀密集的时刻两秒就能差 100 以上，
   没有分辨力，别在那里取点
4. 有差额就报「大概时间 + 官方数字」，能直接定位到是哪一包、哪件装备

> **下面这些场景大多不好主动触发**（队友塞装备、从储藏处直接卖东西、吞月之碎片、
> 炼金送神杖）。别为了验它们去改打法——**每局都开着录制**，等场景自然发生了再回头对账
> 就行。这几条的共同点是单件误差有限、且出现频率低，压着不影响用。

## 一、净资产

已验证（2026-09-08，快速模式 matchid 8988706327，六个时间点全部吻合）：
**消耗品按充能折算**（用剩的吃树 1/3 记 30、叠起来的两个烟记 100）·
**中立物品与强化不计** · **白送的 TP 不计、自购的计** · **眼架按里面装的眼计价**。
这一轮修掉三个 bug：消耗品叠加只算一份、眼架按固定价 50、传送卷轴扣错张。

> 原先这里举的例子是"树苗 1/4 记 23"。**树苗在价格表里没有 `charges`**
> （`{"cost": 55, "consumable": true}`），走不到折价公式，那个数算不出来——
> 折价机制本身验证成立，错的只是例子。换成真能对上的吃树（90 金 3 充能）。

- [x] **代拿的物品**（2026-09-20 验完，顺带修掉一个判错）
  官方**完全按 `purchaser` 算：等于自己才计**。matchid 9006189153 里
  队友买的 5 例（护腕 155、真视宝石 900×3 等）官方一例都没算。

  同时暴露出我们原先两处判错，都已修（`isTeammates` -> `notOwnedBy`）：
  **`purchaser = -1`**（刚捡起来的肉山掉落物）原先照计，官方不算——最硬的证据是
  slot0 的刷新球碎片 `pu` 从 `-1` 变 `0` 的那一包，官方净资产**同包 +1000**；
  **敌方 `purchaser`** 原先按"同队与否"判所以不排除，而 slot2 末局拿着一个从地上
  捡的夜魇方的雾（`purchaser=9`），终值一直虚高 50。

  改完这局**十个人的终值偏差全部是 0**（改之前最大 50）。

  两局观战录制里**确实有** `purchaser` 不是自己的物品，但全是
  `foragers_health`（0 金）、`tango_single`（30 金）这类，**不足以验"圣剑 5600"
  那个量级**——30 金的差额和别的噪声分不开。机制层面可以探（找 `purchaser != 自己`
  的包，看官方有没有把它算进去），但要下结论还得等一件真·贵重物品被塞过来。

- [x] **从储藏处直接卖东西**（2026-09-21 验完）
  原先的病：录像 C 里 21:10 卖掉一个 null_talisman，净资产当场虚高 505，
  **一直虚高到 22:40**——正好是在途账的 90 秒 TTL。v1.2.1 按"同一包里金钱涨了
  ≈V 或 ≈V/2"把它和"被信使取走"分开。

  **实战复核**：四局录制里扫出 12 次从储藏处卖东西，**没有一例出现"虚高 ≈ 卖出价
  并持续一个 TTL"那种形态**。最干净的三个全额卖出：

  | 时刻 | 卖了多少 | 当时偏差 | 30 秒后 |
  |---|---|---|---|
  | 9:07 slot7 | 450 | 0 | **0** |
  | 30:51 slot3 | 100 | 0 | **0** |
  | 38:51 slot5 | 650 | −1002（别的原因） | **0** |

  见 [design/networth.md](design/networth.md) 的"卖出要先排除掉"。

  **还剩一类漏判**：`infused_raindrop` 这种有充能但没标 consumable 的物品，
  我们按全价算而官方按剩余充能折价，卖出时金钱对不上 V 也对不上 V/2。
  那属于计价口径，不在这条里。

- **掉在地上的装备：无解**，GSI 只推自己物品栏，不用验。
  **2026-09-21 撞上了一个实例**：阵亡掉落的真视宝石（900），官方仍按 `purchaser`
  算在死者头上，而我们看不见它。这条是 GSI 的边界，不是可以修的 bug。

  **死亡掉落是一类，不止宝石**：真视宝石 900、**圣剑 5600**、法师圣剑 5600
  （不朽盾表价 0，不影响）。所以最坏情况不是 900 而是 **5600**——拿圣剑的人一死，
  我们的净资产会当场少掉 5600，直到有人把它捡进物品栏才重新看见。

已验证（2026-09-08 实战）：**对局中途启动程序**——开着游戏再打开覆盖层，净资产正确。

## 二、眼位小地图

**这块曾经完全是靠三局 dump 离线做的**，一度是全清单里风险最高的一节。
**现在整节验完了。**

已验证（2026-09-08 实战）：

- 我方眼倒计时（假眼 360s / 真眼 420s，归零与视野消失同步）
- 被排检测无误报漏报
- 敌方眼位置与按类型保留 360s / 420s
- 塔的灰点与推塔进度一致
- 中途启动：程序启动前就已存在的眼只画点、不画倒计时
- 眼多时标签不糊（只标 60 秒内到期的，这个阈值合适）

**2026-09-15 用观战录制做了逐包复验**（原来那轮是看面板验的）。数字记在
[design/wards.md](design/wards.md) 的「观战录制的逐包验证」，结论：

- 寿命常数有权威出处：游戏文件里 `lifetime = 360 / 420`，实测多出的 7 秒是 GSI 上报延迟
- 泉水误认、(0,0) 幽灵条目：三局十万余条，**各 0 次**
- 被排检测：**0 误报**；8 次漏报全是剩余时间落在 `wardKilledGrace` 内的，属设计意图
- 敌方眼（合成部分视野验的）：**0 漏报**；代价是显示出来的敌方眼有 0.5~20% 的时间
  其实已经没了，最长挂到寿命上限
