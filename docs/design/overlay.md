# 程序外壳：窗口 · 交互 · 编辑态 · 托盘 · 设置

## 纯 Alt 查询

**平时屏幕上什么都没有。按住 Alt 显示完整面板，松开即隐。**

实现：Rust 侧轮询 `GetAsyncKeyState(VK_MENU)`（~50ms）。
**只被动读键盘状态，不注册热键、不拦截按键**——游戏内 Alt 的原有功能（Alt 点地图等）
完全不受影响，与"纯接收器"的定位一致。

`GetAsyncKeyState` 在反作弊环境下的风险评估为无（不注入、不 hook，只读键盘状态），
但保留"常显模式"作为兜底配置项。

## 硬约束

- body 透明、锁定态整窗鼠标穿透
- **动画只用 `transform` / `opacity`**（圆环的 `stroke-dashoffset` 是明确许可的例外）
- 深色描边 / 半透明底 / 等宽数字，可读性优先——按住 Alt 就是为了读它
- vanilla JS + SVG，不引入任何框架或图表库
- 渲染由 `setInterval` 每 250ms 驱动，只改文本/类名/CSS 变量，DOM 只建一次
- **宽度写死**：净资产从 4 位涨到 5 位时若让宽度自适应，居中面板会整体横移，读数时抖动
- 块与块之间不画分隔线——**块本身就是分组边界**，四块各自独立摆位，中间隔着的是桌面

## 程序结构

### Rust 侧

| 模块 | 职责 |
|---|---|

| `gsicfg` | 首次运行探测 Steam/Dota 路径，写 `gamestate_integration_*.cfg` |
| `constants` | 常数表播种到配置目录、**补齐已存在文件缺的新键** + 读取命令 |
| `prices` | OpenDota 价格表拉取、缓存、本地覆盖 |
| `settings` | `settings.json` 读写 + 变更广播 |
| `log` | 分级文件日志 + 前端错误转发 |
| `record` | 对局录制 |
| `tray` | 托盘图标与菜单 |
| `main` | 窗口、全局热键、编辑态 |

### 前端

| 模块 | 职责 |
|---|---|
| `cachepool` | 合并 GSI 增量包，维护完整状态 |
| `match` | 按 `map.matchid` 切分对局；POST_GAME / 断流时清空回待机 |
| `timers` | 常数表 + `clock_time` 纯函数算全部倒计时 |
| `events` | events 去重 + 塔防状态机 |
| `networth` | 净资产 |
| `minimap` / `wardmap` | 眼位解析与 SVG 渲染 |
| `render` | 四块渲染、摆位与拖拽 |
| `editor` | 编辑态设置卡片 |
| `main` | 装配 |

**前端是编译期嵌入二进制的**：改完 `ui/` 下的文件必须重新 `cargo build` 才会生效。

`build.rs` 会递归遍历 `ui/`，**逐个文件**发 `cargo:rerun-if-changed`，所以改完直接
`cargo build` 就行。不能图省事写成目录形式 `cargo:rerun-if-changed=../ui`——
实测那样写 cargo 认不出来，会把 crate 当成永远是脏的，**每次** build 都重编一遍
（一次 3 分半），比它要解决的问题更糟。

### 智能显隐

`map.game_state` 不在 PRE_GAME / GAME_IN_PROGRESS 时整窗隐藏。

**观战 / 回放视角也整窗隐藏**（2026-09-08 定，见 [../backlog.md](../backlog.md) 的"明确不做"）。

判定不靠白名单，靠**结构**：自己打的时候 `player` 是扁平的一份人（`player.team_name`
是 `"radiant"` / `"dire"` 这样的字符串）；观战和看回放时 GSI 推的是**全员结构**——
`player` 变成 `{ team2: { player0: {...}, player1: {...} }, team3: {...} }`，
`hero` 同理。于是"`player` 在、但没有 `team_name`、却有 `team\d` 这样的键"就是观战。

```js
const spectating = !!p && !p.team_name && Object.keys(p).some(k => /^team\d+$/.test(k));
```

**为什么必须显式判掉，而不是"反正算不出来就空着"**：净资产那条链路读的是
`player.gold` / `player.items`，在全员结构下这些键根本不存在，取到 `undefined` 之后
一路算成 0——面板会**照常显示一个看起来正常的 0**，而不是明显的坏值。
显示一个错数字比什么都不显示更糟。

**不做部分降级**。技术上是能的：符、莲花、智慧、堆野只依赖 `map.clock_time`，
眼位地图只依赖 `minimap`，这两样在观战下反而更全；坏掉的只有净资产（需要
`player.gold`）和敌方买活（需要 `myTeam`）。不做的理由是产品定位——
观战和回放本来就有一堆现成工具，这个覆盖层要解决的是**你正在打的那一局**里
游戏不告诉你的事。半开的面板还会让人以为是坏了。

## 四个可独立摆位的块

面板原本是一整条：`324`（五个符）+ `170`（塔防+买活）+ `116`（净资产）+ `116`（眼位）
+ 分隔与间距 `63` + 内边距 `24` + 边框 `2` = **815px**，1.5× 缩放下 **1223px**，
1920 屏上占 64%，而且正横跨在 Dota 顶部计分板上。高度 **126px** 完全由眼位小地图撑起——
另外八格上下各空出 20px。

拆成四块，各自一份坐标：

| id | 内容 | 1× 尺寸 | 1.5× 尺寸 |
|---|---|---|---|
| `timers` | 中路符 · 赏金 · 莲花 · 智慧 · 堆野 | 350×85 | 525×128 |
| `enemy` | 敌塔防 · 敌买活 | 196×85 | 294×128 |
| `econ` | 净资产 · GPM · XPM | 142×70 | 213×105 |
| `wardmap` | 眼位小地图 | 214×213 | 321×320 |

尺寸是实测的 `offsetWidth` / `offsetHeight`（含 1px 边框）。
**`econ` 比另外两个矮**——它那格没有圆环，CSS 里写死了 `height: 52px`。
**`wardmap` 的尺寸跟着「眼位地图大小」设置走**，表里是默认 180px 时的值。

`#panel` 从"面板本体"降级成一个**无样式的容器**，四个 `.block` 由 `render.js` 建在它里面。
块是 `position: fixed`，父容器有没有尺寸都不影响；`--panel-scale` / `--panel-opacity`
设在容器上，靠 CSS 变量的继承传给四块，仍然只写一次。

**`transform-origin` 必须是 `top left`**：缩放时块从自己的左上角长大，存的坐标才不会失真。

**一个块里的格子被显示项开关全部关掉时，整块连底板一起消失**，不留空壳。

### 默认摆位

全部按视口比例算，不写死像素。

| 块 | x | y | 1920×1080 / 1.5× 实测 |
|---|---|---|---|
| `timers` | 水平居中 | `屏高 × 7.5%` | (698, 81) |
| `enemy` | 水平居中 | `timers` 下方 10px | (813, 217) |
| `econ` | `16` | 与 `timers` 同一水平线 | (16, 81) |
| `wardmap` | `16` | `econ` 下方 10px | (16, 196) |

`y = 屏高 × 7.5%` 是为了让开计分板（1080 屏上 81px）；拆块之前的 14px 是压在它上面的。
顶部这一摞到 y=345，左列到 y=385，都在视线焦点（y≈540）上方。

### layout.json

```json
{
  "timers":  { "x": 698, "y": 81 },
  "enemy":   { "x": 813, "y": 217 },
  "econ":    { "x": 16,  "y": 81 },
  "wardmap": { "x": 16,  "y": 196 }
}
```

Rust 侧不参与：`save_layout` / `load_layout` 把它当不透明字符串收发，不解析结构。

**迁移**：老文件里的顶层 `{x, y}` 当作 `timers` 的位置沿用，其余三块取默认值。

### 钳位与重置

四块独立可拖之后，把某块拖到 `x = -400` 就**彻底找不回来了**——它平时隐藏，
编辑态下也在屏幕外，没有任何入口能救。所以：

- **读盘时钳进视口**，顺带解决换分辨率、拔掉副屏
- **拖拽落点也钳一次**，否则本次会话里那块就丢了，要等下次启动才回得来
- 卡片里有**「重置」**按钮作为显式复位入口（见「设置」第 6 条）

拆块之前单块面板也有同样的风险，只是概率低四倍。

## 图标：覆盖层上没有文字

**覆盖层上不出现任何需要翻译的词。** 剩下的只有数字（倒计时、净资产）和
GPM / XPM 这两个通用缩写。

收益不是"省掉十几条翻译"，而是**那条写死的宽度约束自己消失了**——
原先"净资产"换成 `Net Worth` 会撑破格子，所以多语言最难的一块是"让宽度跟着语言走"。
面板上没有词，这个问题就不存在。多语言因此收敛到**编辑态卡片 + 托盘菜单**两处。

**不用 Valve 的素材。** 仓库公开且是 MIT，backlog 里为托盘图标已经记过这条。
做法是原创描边式 SVG，沿用游戏的视觉语汇（形状语言 + 配色），但不是它的文件——
这是现有决定的延续，`--k-*` 那组符色注释早就写着"取自游戏中各事件自身的颜色"。

### 图标集（`ui/js/icons.js`）

全部 24×24 viewBox、`stroke="currentColor"`，颜色由所在格子的 `--accent` 决定。

| 项 | 图标 |
|---|---|
| 中路符 | **随阶段变**：两枚叠压的硬币 / 水滴 / 双箭头 |
| 赏金符 | 钱袋 |
| 莲花 · 智慧 · 堆野 | 莲花 / 摊开的书 / 三层堆叠 |
| 敌方塔防 · 敌方买活 · 净资产 | 盾 / 回转箭头 / 硬币 |
| 眼位地图 | **面板上不放标签**；眼 + 塔只用在卡片那一行 |

### 三个非显然的取舍

1. **赏金符用钱袋而不是硬币。** 中路符 0:00 那一阶段就是赏金，两格会撞图标，
   而原本靠"中·"这个前缀区分的文字已经没了。只有赏金阶段会撞
   （水滴和双箭头在别处没有对应格子），所以只改赏金那一格。

2. **堆野用堆叠层而不是营地框。** 语义上营地框更准——这格数的是"野怪刷新"这个事件，
   而 Dota Plus 自己的堆野提示就是按住 Alt 时画在营地上的刷新框。
   但虚线框在 14px 下糊成一团，**这里让位给可读性**。
   将来若做"营地画到眼位小地图上"，那时该换回营地框——它和地图是同一个隐喻。

3. **眼位那一格不放标签。** 其余格子是"圆环 + 数字"，没标签认不出；
   但一张画着塔和彩色圆点的 Dota 地图是自明的。而且灰色的塔图标会**和地图自己的配色撞**
   ——地图上灰塔的含义是"已被推掉"。顺带矮了约 15px。

### 图标和数字的位置是对调的

**有圆环的格子**（五个倒计时 + 塔防）：图标压在环中央，倒计时移到环下面。
一开始是反过来的——数字在环里、图标在环下当标签。上手看过之后推翻：
环是那一格的"容器"，装身份（图标）比装数字更自然；而数字读起来像图注。

**净资产**：图标和金额同一行、放左边。

**买活**：图标在下方当标签，**不能照搬净资产**。分界不是"有没有圆环"，
而是**内容是单值还是一行数据**：净资产只有一个值，币 + 数字读起来就是"金钱：7319"；
买活是五个值，图标摆进那一行就成了"第六个东西"，混进数据里了。
放到下方之后，它和塔防的倒计时正好落在同一水平线上，两格反而对齐了。

塔防与买活之间的间距要单独放大到 14px：它们是两种不同形态的格子，
块里通用的 6px 太挤，会读成一组。

**买活的圆点外面套一个圆角框。** 塔防有个很重的圆环当容器，圆点却什么都没有，
两边一比就"飘"——框是圆环在这种形态下的对应物。

**框撑满格子高度**，把塔防"环 + 倒计时"的结构镜像一遍：框顶对齐圆环顶、
框底对齐倒计时底；圆点吃掉箭头以外的全部高度并居中，中心因此正好落在圆环中心那条线上。
实测四处偏差全为 0。

> 中间走过一次弯路：为了"框别显得空"把它收紧、再在格子里垂直居中——
> 结果它和圆环、倒计时两边都不挨着，比没框还乱。
> **框该对齐的不是自己的内容，是隔壁那一格。**

框宽 118px，格子因此从 104 放宽到 122，否则会溢出。

框的颜色取 `--k-chance`（"敌方缺失 = 机会"）的 **32%**，和框里的图标同色系。
不用满强度：**框是容器不是数据**，太亮会和旁边塔防那个红色进度环抢，
也会让人误以为它自己在表达某种状态。

**塔防 ready 时把盾填实**（`fill-opacity: .3`）。数字位这时是空的（数字位永远只放数字），
光靠"环画满"不够显眼。曾考虑写 `READY`，但那是英文单词、不像 GPM/XPM 那样是
Dota 各语言版本通用的缩写，等于在刚清空的面板上重新放回一个要翻译的词。

这一改还顺手解决了描边过细的风险：环内径 48px，图标能放到 **24px**，
0.8× 时描边从 **0.79px 变成 1.36px**。原先 14px 时那条是最大的可读性隐患。

两个不能省的细节：

- **`.num` 要 `min-height`**：塔防 ready 态数字为空，不留高度那一格会比旁边矮、整行跳。
- **`.nw` 要 `min-width`**：币在左边之后，净资产从 4 位涨到 5 位会把币往左推。
  这和"格子宽度写死防抖动"是同一个理由，只是尺度小了一层。

格子高度因此从 69px 变成 75px。

### 尺寸与两个坑

**环内 24px，行内 16px。** 12px 下书和莲花的细节会糊；
最初取的 14px 标签位在 0.8× 下描边只剩 0.79px，是挪进环里之后才不成问题的。

1. **`.cell svg { width: 52px }` 会把图标撑成 52px。** 那条是给圆环用的，特异度 (0,1,1)。
   必须写成 `.cell .lab svg.ico`（0,2,1）——**和眼位地图那个 bug 是同一个坑**。
2. **`set()` 用不了。** 它比较值后写 `textContent`；图标要整段替换 SVG，
   得走另一个 `setHtml()`，同样只在变化时才动 DOM（渲染 250ms 一轮，别每帧重建 SVG）。

### 放大不糊，风险在小端

实测缩放 2× 时 SVG 布局尺寸仍是 52、渲染尺寸变成 104——浏览器按新尺寸重新光栅化，
不是拉伸位图，边缘保持矢量清晰。

风险在**缩小**：描边 `1.7` 是 24 viewBox 里的值，图标越小描边越细。
标签位那版 14px 在 0.8× 时只剩 **0.79px**，会被抗锯齿摊成浅灰；
挪进环里放大到 24px 之后是 **1.36px**，实测在最暗和最亮的背景上都清楚。
另加了 `drop-shadow(0 0 2px #000)` 作衬底。

### 一个实测教训

币堆最初画成两个叠起来的**扁椭圆**，13px 下退化成**两条横杠**，完全看不出是硬币——
正好败在图标化的全部目的上（不靠文字也能理解）。改成两枚**相互叠压的圆**才立得住。
小尺寸下椭圆和细线是最先垮掉的两种形状。

### 卡片同时是图例

九个显示项开关每行前面放对应图标（`showIcon()`），**和面板用的是同一份 `icons.js`**，
形状永远不会脱节——和眼位图例复用地图 class 是同一个思路。
文字集中在卡片，而卡片正好是唯一需要翻译的地方。

**每行只放一个图标。** 眼位那行曾经放过"眼 + 塔"（想表达那块地图画了哪两类东西），
但九行里只有它是两个，反而不齐。塔图标仍留在 `icons.js` 里，供眼位图例那一节使用。

> **面板上的图标尺寸一律由 CSS 决定**，`icon()` 的 `size` 参数在 `.cell .lab` 里会被覆盖；
> 那个参数只对卡片有效（`.ed-ico` 没有设宽高）。
> 加尺寸例外时要写在通用规则**之后**——`[data-cell="buyback"] .lab svg.ico` 与
> `.cell .lab svg.ico` 特异度都是 (0,3,1)，靠顺序取胜。
> **这个文件里同类的坑已经出现三次**：圆环压图标、真眼空心、买活图标放大。

## 托盘

程序原本**没有任何正常退出的途径**：窗口无边框、`skipTaskbar` 为真、没有托盘，
只能去任务管理器杀进程。托盘补的是这个真窟窿，不只是锦上添花。

```
右键菜单                左键单击图标 → 同样 toggle 编辑态
├ 编辑面板               （与 Ctrl+Alt+F10 共用同一份编辑态，别各存一份）
├ ──────
└ 退出
```

## 编辑态

### 一次返工：设置窗口并入编辑态

最初的设计是**两个入口**——托盘「设置…」开一个独立窗口，托盘「调整面板位置」进编辑态。
上手用过之后推翻了，原因是结构性的：

> 设置窗口必须 `alwaysOnTop`（否则会被覆盖层压住，实测直接"打开后看不见"），
> 而面板默认在屏幕顶部正中、弹窗也在屏幕中央——**两个都置顶就一定互相遮**。
> 更要命的是面板平时藏着（只有按住 Alt 或编辑态才显形），
> 于是调缩放、调透明度、开关显示项**全都是在盲调**。

改成**单一编辑态**：面板常显可拖 + 设置卡片就画在它旁边，改一下当场看到效果。

### 构成

覆盖层窗口内两层，只在编辑态一起出现：

| 层 | z 序 | 作用 |
|---|---|---|
| `.block` ×4 | 下 | 四个真实的块，各自虚线描边、各自可拖 |
| `#editor` | 上 | 设置卡片 |

**卡片是 `.block` 的兄弟节点，不是子节点。** 块被 `--panel-scale` 缩放，
卡片若是子节点会跟着缩到 2× 或 0.8×，都没法用。

**卡片自己也可拖，但只能靠顶部的标题栏**（原因见下面第 3 号坑）。
位置**不存盘**，每次进编辑态回到屏幕中央偏下。

> 拆成四块之前，卡片是"锚在面板下方并跟随拖动"的。四块之后"面板"没有唯一所指，
> 这套锚定失去意义，连同它那圈 rAF 一起删掉了。
> 固定在屏幕某一角也否决过——块一旦被拖到那个角就会互相压住，
> 而"同时看见面板与设置"正是当初合并编辑态的全部意义。

### 三条退出路径

编辑态下覆盖层全屏吃鼠标（`set_ignore_cursor_events(false)`），桌面点不动，连托盘都点不到。
所以出口必须冗余：

1. 卡片底部的**「完成」按钮**——不依赖键盘和窗口焦点，最可靠
2. **ESC**——进编辑态时主动 `set_focus()`，前端监听 `keydown`
3. **`Ctrl+Alt+F10`**——系统级热键，不经过被遮住的窗口，是最后的兜底

> 曾经有第四条「点空白处退出」，**已移除**。它当初按兜底加入，但真被困住时能救场的是热键——
> 点空白处要求你能看见并点中面板以外的区域，而那正是被困场景下最不成立的前提。
> 它没有提供任何独占覆盖，只贡献了摆位时的误触风险。

### 六个必须避开的坑（都只有真机才暴露）

1. **`html, body` 必须 `pointer-events: none`**，否则编辑态下一张看不见的全屏膜会盖住整个桌面，
   连托盘图标都点不到，只能靠热键逃出来。
2. **`set_edit` 内绝不能调 `global_shortcut` 的 register/unregister**——
   它会从热键回调里被调用，而插件派发回调时持有内部锁，在回调里再动注册**直接死锁**，
   实测整个程序卡死。ESC 因此走前端 `keydown`，也不该注册成全局热键（会劫持游戏内菜单键）。
3. **拖拽区里不能有需要点击的控件**：拖拽在 `pointerdown` 时 `setPointerCapture`，
   之后 `pointerup` 会被改派到捕获元素，`click` 便落在那个元素而不是按钮上，
   **按钮的监听器永远不触发**——实测表现为"点完成没反应，且编辑态再也退不出去"。

   最早是「完成」按钮放在面板内部踩的，把按钮移进卡片就解决了。
   但**卡片自己也能拖之后，这个坑原样回来了**：卡片里装着「完成」、九个复选框、
   两个滑块和一个下拉框，整块当拖拽区会把它们全部打死。所以卡片只有顶部那条
   `.ed-bar` 标题栏可拖。四个块没有这个问题，它们内部没有可点的东西。
4. **`.block` / `.cell` 的 `display: flex` 会盖过 `[hidden] { display: none }`**，
   必须显式写 `!important`，否则设置里的显示项开关整个不起作用。
5. **常数表只播种、不补齐 = 静默失效**。`constants.rs` 原本只在文件不存在时写入，
   于是 9/1 播种的 `normal.json` 遇上 9/5 新增的 ward 常数就永远缺那几个键，
   而 `get_constants` 把盘上文件原样返回。后果不是报错而是**静默的错**：
   `this.C.wardSentryDuration` 是 `undefined`，`Math.ceil(x + undefined - y)` 得 NaN
   直接画在地图上；更糟的是 `rem > undefined` 和 `clock - lastSeen > undefined` 恒为假，
   于是**被排检测一次都没触发过、敌方眼永远不移除**，全程没有任何报错。
   现在读盘与播种都把盘上的值盖在内置默认值之上（复用 `settings.rs` 的 `merge`）。
   `item_price_overrides` 例外——那张表里"删掉某项"是用户的明确意图。

6. **`innerWidth` 可能是 0**，而摆位的每一步都要除以它。
   实测浏览器里页面刚导航完、以及窗口被隐藏期间，`innerWidth` 会持续为 0；
   这时 `defaultLayout()` 算出的是 `(0 - 350) / 2 = -175` 这种负坐标，
   而启动流程会把结果**回存**——一次异常启动就足以把摆好的四个坐标全冲掉。
   因此 `applyLayout` 在视口量不出来时返回 `null`（这次不摆、也不写盘），
   由 `resize` 事件补上；`clamp` 同样在视口为 0 时直接放行，不做钳位。

## 设置

卡片沿用覆盖层的深色玻璃配色与 Bahnschrift 字体。

1. **显示项开关**（9 个）：中路符 / 赏金 / 莲花 / 智慧 / 堆野 / 敌塔防 / 敌买活 / 净资产 / 眼位小地图
2. **面板缩放** 0.8 ~ 2.0，默认 1.0。用 `transform: scale()`——走合成器，符合"动画只用
   transform/opacity"的约束。四个块的 `transform-origin` 都是 `top left`，
   缩放时各自从左上角长大，存的坐标才不会失真。
3. **眼位地图大小** 108 ~ 360px，默认 180。地图整幅画在 108×108 的 viewBox 里，
   塔、眼点、标签全是 viewBox 单位，所以这个值就是整体等比缩放，不碰 `wardmap.js` 的坐标。
   单独给它一个滑块而不是跟着面板缩放走，是因为它是**地图**不是文字：
   同一个缩放下别处刚好，地图往往还是看不清。

   > **CSS 特异度的坑**：`.cell svg { width: 52px }` 的特异度是 (0,1,1)，
   > 压得住 `.wardmap` 的 (0,1,0)。地图因此**一直被塞在 52px 里画**，
   > 而不是设计里写的 108px——拆块时才查出来。规则必须写成 `.cell svg.wardmap`。
   > 另外包在外面的 div 也叫 `.wardmap`，只能给它宽度，高度要让 svg 加标签自己撑，
   > 否则"眼位"两个字会压在地图上。

4. **底板**（滑块就叫这两个字）0 ~ 1.0，默认 0.72。**只动块的底板，内容不动**——
   和下面那条「整体」不是一回事，那条会把文字图标一起调淡。
   描边跟着底板一起淡出（系数 0.14，默认的 .72 正好落回 `--hair` 的 .10）：
   底板没了却留一圈白线，会变成一个空方框浮在画面上。

   **眼位地图自己的底跟着一起淡**：`.wm-bg` 曾经写死 `rgba(0,0,0,.35)`，底板拉到 0
   时四个块都透了，只剩它一块灰方块浮在画面中间，比不透明还显眼。现在是
   `rgba(0,0,0, calc(var(--block-bg,.72) * .5))`——系数 .5 让默认的 .72 落回 .36，
   和原来的 .35 基本同一档，只是从此跟着滑块走。它是**块底之上的第二层**，
   所以两层相乘着变淡，这正是想要的：地图那块本来就该比别处再压一点。

   > **拉到 0 的代价是具体的**（实测，最亮背景下）：大号倒计时、图标、净资产金额
   > 都靠自身的 `text-shadow` / `drop-shadow` 活下来了；但 **GPM/XPM**（10px、
   > `--dim` 灰、只有 3px 阴影）基本读不出，**买活的青框**（32% 是按深色底调的）
   > 淡到快没了。先只给滑块、不动这两样——等实际常用值定了再决定要不要为那个值优化。

5. **整体**（滑块就叫这两个字）0.3 ~ 1.0，默认 1.0。四个块（含文字与圆环）一起变淡。

   > 两条滑块原先叫「透明度」和「底板」，并排放着看不出谁管什么。现在是「整体」/
   > 「底板」——对仗、都两个字、宽度不变，各自点名它调的对象，
   > 和「缩放」「眼位地图」同一种命名方式：名词指对象，滑块调它。

   > **`.block.edit` 里绝不能写 `opacity: 1`。** 它会盖掉 `.block.on` 的
   > `var(--panel-opacity)`，而这个滑块只能在编辑态里够到——结果就是"拖了没反应"，
   > 永远看不到效果。把设置并进编辑态本来就是为了不盲调（见上面那次返工的理由），
   > 这条却一直漏在外面，直到 2026-09-08 才发现。下限 0.3 在编辑态下仍看得见、拖得动。
   面板的显隐本来就用 `opacity` 做淡入淡出，设置值**不能另起一套**，否则两者打架——
   写成 `.block.on { opacity: var(--panel-opacity, 1) }`，让淡入的目标值就是设置值。
   已知取舍：调得过低会让数字在明亮的团战画面上变糊，但面板只在按住 Alt 时出现、
   不是常驻，风险可控，由用户自行把握。
6. **重置**。按钮原来叫「恢复默认摆位」、只复位坐标；现在把**这张卡片能改的东西
   一次性还原**：显示项九个勾、缩放、整体、底板、眼位地图大小，外加四块的摆位。
   名字跟着缩成两个字，因为它已经不只管摆位了。

   **开发区那两项（日志级别、对局录制）不在重置范围内**——它们不是"外观"，
   而且悄悄把正在录的对局关掉，用户不会知道自己丢了数据。

   > **顺序有坑**：复位摆位要按**新的**缩放算（`applyLayout(null, scale)`），
   > 而 `main.js` 里的 `cfg` 是靠 `settings` 事件异步更新的，保存后不会立刻变。
   > 所以按钮把新的 scale **当参数传给** `onReset`，不让它去读那个还没刷新的 `cfg`。

   不做二次确认：这是编辑态里的按钮，而编辑态要按住热键才进得来，
   误触成本没到值得多一次点击的程度；勾选和滑块也都能立刻手动改回去。

7. **眼位地图图例**（可折叠）：六种眼状态 + 三种塔状态的色块与说明。
   **只在编辑态可见**，游戏中不占任何屏幕空间——图例只在"学"的阶段需要，记熟了就是纯负担。
   色块**复用地图自己的 `wm-ward` / `wm-tower` class**，另写一套颜色迟早会和地图对不上。

   **实心＝假眼，空心＝真眼**（形状区分类型，颜色区分归属与到期）。

   | 眼 | | 塔 | |
   |---|---|---|---|
   | 青 `#65D9F7` | 我方（实心假眼 / 空心真眼） | 绿 `#66BB6A` | 天辉 |
   | 紫 `#A46BFF` | 敌方（实心假眼 / 空心真眼） | 红 `#E57373` | 夜魇 |
   | 琥珀 `#FFC24B` | 60 秒内到期 | 灰 `#5A6470` | 已推掉 |
   | 亮红 `#FF4D4D` | 刚被排掉（只闪 3 秒） | | |

   > **敌方眼为什么是紫的**：原本是暗红 `#AA3333`，和夜魇塔的 `#E57373` 撞色。
   > 两者都常驻（敌方眼按类型保留到 360s / 420s），而在 2 个 viewBox 单位下
   > 圆和方也分不出来——"敌方有眼"会和地形混为一谈。地图还只有 52px 时反正都看不清，
   > 放大之后就成了实际问题。
   >
   > **动的是眼不是塔**：夜魇的红是 Dota 自己的阵营色，玩家已经内化，改它等于和游戏
   > 本身打架；而且塔是底图（位置固定、只有生死两态），眼才是这块的正文。
   > 紫取自调色板里强化符那支 `--k-power`，不引入新色。
   >
   > 这么一改，**地图上的红只剩一个含义：我方眼刚被排掉**，而且只闪 3 秒
   > （`minimap.js` 里 `clock - k.at < 3`）。红=出事了，是对的直觉。

8. **开发区**：日志级别、对局录制开关、**打开常数表目录**按钮
   （否则改符间隔要自己翻到 `%APPDATA%` 深处）。

**卡片里的下拉框需要 `color-scheme: dark`**，而且只能加在 `.editor` 上：
弹出层由系统绘制，不声明配色方案就是白底，而 `option` 继承卡片的浅色文字 → 白字白底。
加在 `:root` 上会给根元素画上不透明底色，覆盖层就不透明了。

### 配置与生效

存 `settings.json` 于配置目录（与 `constants/`、`layout.json` 同级）：

```json
{
  "show": { "mid": true, "bounty": true, "lotus": true, "wisdom": true,
            "stack": true, "glyph": true, "buyback": true, "econ": true,
            "wardmap": true },
  "scale": 1.0,
  "opacity": 1.0,
  "panelBg": 0.72,
  "wardSize": 180,
  "logLevel": "debug",
  "recordMatches": false
}
```

Rust 提供 `get_settings` / `set_settings`；保存后 emit `settings` 事件，
**覆盖层实时应用，不需重启**。卡片与面板同在覆盖层窗口内，这条事件成了自发自收，
但链路不变——保持单一数据流向，不给卡片开后门直接改面板。

读盘时**缺什么补什么**，所以老配置文件遇上新增字段也能直接用。

**关于关掉某项后面板变窄**：这与"宽度写死防抖动"不冲突。那条针对的是游戏中净资产位数变化
导致的横移；改设置是用户主动的一次性操作，变窄是预期内的结果。

## 明确不做

开机自启、白天黑夜、语音提示、任何形式的输入模拟。
