# 程序外壳：窗口 · 交互 · 编辑态 · 托盘 · 设置

## 纯 Alt 查询

**平时屏幕上什么都没有。按住 Alt 显示完整面板，松开即隐。**

> **v1.4.0 起默认对局中一直显示**（2026-10-09 用户定）：显示都贴到游戏自己的顶栏和小地图上之后，
> 它不再是一块浮在画面中间、要时不时藏起来的面板，常驻也不碍事。按住 Alt 这套仍在——
> 勾上「按住 Alt 才显示」（原「始终显示」，见下）就回到这一节写的样子。
> 老用户的 `settings.json` 里存着自己的值，升级不受影响。

实现：Rust 侧轮询 `GetAsyncKeyState(VK_MENU)`（~40ms）。
**只被动读键盘状态，不注册热键、不拦截按键**——游戏内 Alt 的原有功能（Alt 点地图等）
完全不受影响，与"纯接收器"的定位一致。

#### 状态要能自愈，不能只靠边沿（2026-09-23 修）

原先的写法是「状态变了就 `let _ = app.emit("alt", down)`，同时把 `prev` 推进」。
两个问题叠在一起：**`emit` 的错误被丢掉了，而 `prev` 已经推进**，这一个边沿
就此永远补不回来；之后只要状态不再变化，就再也不会重发。

失步之后前端比实际**落后一个边沿**，用户看到的正是"Alt 变成了切换键"——
按住显示、松开却不消失，再按一次才消失（消失其实发生在第二次的**松开**上）。
用户 2026-09-23 报的就是这个现象，出现在「始终显示」开了又关之后，偶发。

两道防线：`prev` 只在 `emit` 成功后推进；再加一个**每秒无条件重发**，
不管什么原因造成的失步，最多一秒自愈。前端那边 `alt = d` 是幂等的，重发无副作用。

> **没能复现，所以这是按机制修的，不是按现象修的。** 上面那条链路是代码里实打实
> 存在的失步通道（丢掉的 `emit` 永远补不回来），修它无论如何都对；但它是不是
> 用户遇到的那一个，暂时没有证据。前端因此加了一条 debug 日志（`[alt] false -> true`），
> 再遇上把 `logLevel` 调成 `debug`，日志里能直接看出**是不是漏了一个边沿**。
>
> **2026-09-28 实战**：v1.3.4 用下来没再出现。但它本来就是偶发的，
> 这只能算"没再遇到"，不能算证实——上面那条排查路径继续有效。

`GetAsyncKeyState` 在反作弊环境下的风险评估为无（不注入、不 hook，只读键盘状态），
但**"不用按 Alt"的开关作为兜底已经做了**（2026-09-21），见下。

### 按住 Alt 才显示（原「始终显示」，2026-09-21）

设置卡片「通用」第一项「显示方式」，**默认不勾 = 对局中一直显示**；勾上就只在按住 Alt 时显示。
另有全局热键 `Ctrl+Alt+F11`，两处同一个值。存盘的字段一直叫 `alwaysShow`，界面上是它的反面。

> **2026-10-10 反过来叫**：v1.4.0 默认改成一直显示之后，「始终显示」描述的是默认行为，
> 勾选框默认勾着、真正要开关的"按 Alt"反而没写出来。改成只描述那个例外。
> **存盘字段不改名**：老配置文件照常读，v1.3.x 默认按 Alt 的老用户升级后看到的就是勾上的
> 「按住 Alt 才显示」，用法不变。
>
> **托盘里那个勾选项同一天去掉**：打游戏时无边框窗口盖住任务栏，点托盘得先切出游戏，
> 对局中途根本用不上；中途切换靠热键，平时在设置卡片里改。热键原先是标在托盘菜单上让人发现的，
> 改成写在卡片那个勾后面（11px 附注）。

#### 为什么值得再占一个全局热键（2026-09-23）

当初定的是"不给它快捷键"，理由是用户说 `v` 这类裸字母太容易和游戏键冲突。
**那个理由只否掉了裸字母，没否掉快捷键本身**——项目里本来就有一个
`Ctrl+Alt+F10`（编辑态），带两个修饰键的 F 区组合不会撞 Dota。

真正的转折是：**想在对局中途拨这个开关，原本做不到。** 唯一的入口是编辑态，
而编辑态会抢焦点、取消鼠标穿透，那一刻根本没法继续玩。于是它事实上退化成了
"开局前设好就别动"，而它最有价值的用法恰恰是中途切换——对线打钱时开着，
团战时关掉免得挡视野。

键位 `Ctrl+Alt+F11` 由用户定，紧挨着编辑态的 F10，同一族好记。
2026-09-28 实战验过：对局中按下即切换，托盘菜单的勾选跟着变。

> **热键走 `toggle_always_show()` → `set_settings`，不自己写盘。** 那条路上挂着给前端的
> `settings` 事件，卡片上的勾靠它跟着变；绕过去就两处不同步。

> **残留风险：热键被别的软件占了会怎样。** 注册走
> `with_shortcuts([...]).expect(...)`，这个 `expect` 只在**字面量解析失败**时触发
> （写错了是开发期错误，该panic）。操作系统层面被占的情形没能构造出来验证，
> 真撞上的话最坏是这个热键失灵，设置卡片那条路还在。

> **名字**：2026-09-21 定成「始终显示」/「Always show」（先用过「常显」，那是从这份文档的
> 「常显模式」直接搬的词——**设计文档里的简称不等于界面用语**）。2026-10-10 默认值反转后
> 改成「按住 Alt 才显示」/「Only while holding Alt」，理由见上。

存在的意义是兜底：万一 `GetAsyncKeyState` 在某些环境不工作，按 Alt 没反应，
这个开关能让程序仍然可用。那种情况下用户还够得到它——**托盘菜单还在，
而且标着 `Ctrl+Alt+F10`**。

两条刻意的边界：

- **一直显示也不绕过"在不在对局中"。** 主菜单里照样消失。
  它的意思是"不用按 Alt"，**不是"永远杵在桌面上"**。
  编辑态则仍然绕过——看位置对不对这件事恰恰要在开游戏之前做。
  （网页开发时的 `v` 键原先是另一套独立的 `forceShow`，连 `inMatch` 也绕过；
  2026-09-29 起改成切换**同一个** `alwaysShow`，见下面「只有一个值」。）
- **一直显示时按 Alt 什么都不会发生**——面板已经显示着。曾考虑让 Alt 在这时
  **反过来**用（按住临时隐藏，方便看被挡住的东西），否决了：
  **Alt 的含义会随开关反转**，学习成本大于收益。真要临时看，用 `Ctrl+Alt+F11` 关掉它。

#### 只有一个值，卡片要跟着它变（2026-09-29 修）

原先有两个问题，根子都是"同一件事有两份状态"：

1. **网页开发时 `v` 键是另一套独立的 `forceShow`**，和卡片上的「始终显示」互不知道。
   显示条件是两者取或，于是勾着「始终显示」时按 `v` 毫无反应；用 `v` 打开后卡片上的勾也不变。
   项目主页的 demo 框跑的是同一份代码（当时带着开发标记），访客点进框里按一下 `v`，
   "显示 5 秒、隐藏 1.6 秒"的自动演示就失灵了——面板一直在，旁边写着"已隐藏"。
2. **卡片上的勾不跟着热键和托盘变**，这条是正式版的 bug。卡片在启动时建好，之后不重建；
   用 `Ctrl+Alt+F11` 或托盘切换之后，卡片还攥着旧的勾，进编辑态随便动一下别的设置，
   `collect()` 就把旧值一起存回去——**刚切的状态被悄悄改回去**。

改法：

- `v` 改成切换 `alwaysShow` 本身（走 `saveSettings`），`forceShow` 删掉。
  代价是 `v` 不再绕过 `inMatch`；没有对局数据时要看面板摆位，用 `e` 进编辑态，它本来就绕过。
- 卡片监听 `settings` 事件，**只同步「始终显示」这一个勾**。其余控件不跟：它们只有卡片自己改，
  而 Tauri 的 `settings` 事件是异步回来的，拿回来的可能是改动途中的旧值，套上去控件会往回跳
  （当初是拖滑块时撞上的；v1.4.0 滑块都删了，规则照留）。
- 项目主页的 `demo.html` 去掉开发标记（`body.dev`），demo 里 `v` / `e` 都不再生效。
  那里只该有 Alt 这一种交互。
- **网页开发页也认正式版的两个热键**：`Ctrl+Alt+F11` 始终显示、`Ctrl+Alt+F10` 编辑态，
  `v` / `e` 保留当作简写。原先网页只认 `v` / `e`，同一件事两边两套键，容易以为是两个功能。
  **Tauri 里前端不响应这几个键**：正式版的热键由 Rust 注册成全局热键，编辑态下 webview
  有焦点、也会收到同一个按键，前端再切一次就等于没切。靠 `body.dev` 挡——`index.html` 没有它。

> 「重置」会把它一并还原成默认（v1.4.0 起是开）。它是外观行为、和显示项同类；
> 还原它不造成任何数据损失——
> 这和开发区那两项（日志级别、录制开关）被排除在重置之外的理由正好相反。

## 硬约束

- body 透明、锁定态整窗鼠标穿透
- **动画只用 `transform` / `opacity`**（圆环的 `stroke-dashoffset` 是明确许可的例外）
- 深色描边 / 半透明底 / 等宽数字，可读性优先——按住 Alt 就是为了读它
- vanilla JS + SVG，不引入任何框架或图表库
- 渲染由 `setInterval` 每 250ms 驱动，只改文本/类名/CSS 变量，DOM 只建一次
- **净资产金额钉宽**（`.nw` 的 `min-width`）：从 4 位涨到 5 位时不把前面的币往左推
- **没有底板**（v1.4.0 起）：所有东西直接压在游戏画面上，可读性全靠 `text-shadow` / `drop-shadow`。
  例外只有倒计时和塔防那几个圆底下的暗底盘，见「贴着 Dota 自己的界面画」

| `main` | 窗口、全局热键、编辑态 |

| 模块 | 职责 |
|---|---|
| `cachepool` | 合并 GSI 增量包，维护完整状态 |
| `match` | 按 `map.matchid` 切分对局；`game_state` 不在对局中时 `inMatch` 为假（断流由 `main` 判，见下） |
| `timers` | 常数表 + `clock_time` 纯函数算全部倒计时 |
| `events` | events 去重 + 塔防状态机 |

| `minimap` / `wardmap` | 眼位解析；`wardmap` 把它画在原生小地图上 |

| `dotahud` | 读回来的 Dota 设置，渲染和设置卡片共用 |
| `render` | 倒计时与净资产两块（固定位置），调度另外两层 |
| `editor` | 编辑态设置卡片 |
| `main` | 装配 |

**前端是编译期嵌入二进制的**：改完 `ui/` 下的文件必须重新 `cargo build` 才会生效。

`build.rs` 会递归遍历 `ui/`，**逐个文件**发 `cargo:rerun-if-changed`，所以改完直接
`cargo build` 就行。不能图省事写成目录形式 `cargo:rerun-if-changed=../ui`——
实测那样写 cargo 认不出来，会把 crate 当成永远是脏的，**每次** build 都重编一遍
（一次 3 分半），比它要解决的问题更糟。

### 录制的生命周期（2026-09-16 重做）

> 录制是开发者工具：2026-09-29 起要 `settings.json` 里 `devTools` 为真才显示、才会录，
> 见下面「设置」里「开发区」那条。


**原先录制器活在 GSI 那条线程的局部变量里**，而处理开关变化的 `refresh()` 只在
`n % 100 == 0` 时被调用——也就是**只有 Dota 在推包时才会跑**。三个后果，都实测到了：

| 症状 | 实测证据 |
|---|---|
| 不开游戏时勾上「记录对局数据」，什么都不会发生 | — |
| **取消勾选也不生效**，录制状态卡在原地 | `settings.json` 里已是 `false`，日志里却没有「录制已停止」 |
| 刚开录就关掉游戏 → 留下一个 **0 字节**的空壳 | `raw_1789563893.jsonl.gz`，0 字节，创建后再没被写过 |

第三条最糟：gzip 把数据缓存在内存里，`FLUSH_EVERY = 50` 包才落盘一次，而
`finish()` **只在"设置从开变关"这一条路径上**调用。托盘退出、Dota 关掉、
GSI 断流全都不会收尾。不足 50 包的那一局于是整个消失，**而且毫无提示**。
"我明明开了录制，打完却什么都没有"是最坏的失败形态：静默，且数据不可再生。

改法是把录制器挪到一个全局的 `Mutex` 后面，于是三条路都能够到它：

1. **`set_settings` 直接调 `refresh()`** —— 开关立刻生效，不等推包
2. **`RunEvent::Exit` 收尾** —— 托盘退出、关窗口都会 `finish()`
3. **断流看门狗** —— 一条 2 秒一跳的线程，超过 `IDLE_SECS` 没收到包就收尾封口

还有一条顺带的改动：**文件改成第一包数据到来时才建**（懒建）。这样"勾上开关但没开
游戏"不再产生任何文件，文件名里的时间戳也从"你什么时候拨的开关"变成了
"数据什么时候开始"。0 字节空壳这个形态从此不存在。

> **断流 ≠ 对局边界。** Dota 在主菜单里照样推包，所以看门狗只有在**游戏整个关掉**
> 时才会触发。它解决的是"收尾"，不是"分文件"——分文件靠 `matchid`，见下。

#### 按对局分文件（2026-09-20）

原先一个文件是按**开关时机**切的：只要 Dota 开着、开关也开着，一局打完接着下一局
全写进同一个文件。回放时得自己找那一局从哪开始。

现在**换局就换文件**：每包读 `map.matchid`，和当前文件记着的那个不一样就收尾，
下一包懒建新文件。收尾时把 matchid 补进文件名：

```
raw_1789832417.jsonl.gz  ->  raw_1789832417_m9006648438.jsonl.gz
```

**时间戳保留在前面**，因为同一局可能被录两次（比如回放看两遍），只有 matchid
会撞名。`records_stat` / `clear_records` 认的是 `raw_` 前缀加 `.jsonl.gz` 后缀，
新名字照样在内。

> **改名放在 `finish()` 之后**，这时文件已经关上了，是一次普通的重命名。
> 不去改正在写的那个文件的名字——Windows 上对打开着的文件改名能不能成，
> 取决于句柄的共享位，不值得赌。

几条刻意的边界：

- **`map` 段可能整包缺席**（GSI 推的是增量，实测每个录制文件里都有两包没有 `map`）。
  这种包**不动**当前的 matchid，否则会被切得稀碎。
- **只在"两个都是真 matchid 且不相等"时才切**。主菜单里的 `matchid` 是 `"0"`
  或者干脆没有，这种一律当"不知道"，跟着当前文件走——宁可让菜单数据粘在某一局
  的文件尾巴上，也不要凭空造出一堆几十秒的碎文件。
- **没有 matchid 的包不建文件**（2026-09-20 补）。Dota 在主菜单里推的是
  `{"provider":{…},"player":{},"events":[]}` 这样的心跳包，一包 114 字节。
  懒建是"第一包数据到来时才建"，而**心跳包也算数据**——于是断流封口之后，
  只要 Dota 还开着就会立刻建出一个只有心跳包的空壳：

  ```
  20:34:25 收尾（断流）raw_1789906167_m9008012005.jsonl.gz
  20:34:34 开始录制   raw_1789907674.jsonl.gz     ← 114 字节，只有一个心跳包
  20:34:39 收尾（关闭开关）
  ```

  开关叫「记录对局数据」，**没有对局就不该有文件**。注意这只挡"建文件"这一步：
  文件一旦开着，后面缺 `map` 的增量包照样写进去。
- 英雄选择、策略时间、赛后结算**都带着 matchid**，所以它们自然落在这一局的文件里，
  不需要特殊处理。赛后只留结束那一刻的十秒，见下面「比赛结束 10 秒后收尾」。

#### 断流阈值必须长过心跳（2026-09-29 修）

`IDLE_SECS` 原先是 20 秒，而 GSI 配置里的 `heartbeat` 是 **30 秒**（见 `gsicfg.rs`）。
只要游戏里什么都不变，GSI 就只剩心跳，于是：

```
22:02:22 收尾（断流）raw_1790602729_m9020222524.jsonl.gz   ← 正常那份
22:02:31 开始录制   raw_1790604151.jsonl.gz                  ← 心跳到了，懒建
22:02:52 收尾（断流）                                          ← 20 秒后又封口
22:03:02 开始录制   raw_1790604182.jsonl.gz                  ← 下一个心跳
……每 30 秒一个，每个只有 1 包
```

撞上的场景是**回放看完不关**：停在结束画面（`DOTA_GAMERULES_STATE_DISCONNECT`、
`paused = true`），心跳照样带着 matchid，所以"没有 matchid 不建文件"那条挡不住。

**更要紧的是正式对局里的暂停。** 暂停时同样只剩心跳，一旦超过 20 秒就会把
**一局切成两段**，后半局落进另一个文件，对账得自己拼。现有语料里唯一一次暂停
（9006189153 的开局前暂停）最长隔了 **19 秒**，差一秒就切了。

改成 **40 秒**，和前端的"暂停中断流阈值"同一个数、同一个理由（见下面的「断流要退回待机」）。
心跳 30 秒一次，40 秒内必来一包，只要 Dota 还开着文件就不会被封口；
回放结束后的心跳也就写进原来那份文件的尾巴，而不是每个都另起一份。
看门狗于是真正只在**游戏整个关掉**时触发——这正是它的注释一直声称、但原先并不成立的事。

> 曾打算再加一条"封口之后只剩心跳就不开新文件"。阈值长过心跳之后，心跳本身就让
> 文件保持开着，封口只会发生在 Dota 真的停止推包之后，那条规则**再也走不到**，所以没加。

#### 回到主菜单就收尾（2026-10-04 修）

上面那次改动的副作用：**自己打完一局，录制不会自己结束**。用户 2026-10-04 报的，
m9029221681 那局 22:06 开录，打完回到主菜单后文件一直开着，直到 22:42 手动关开关。

以前回到主菜单后能收尾，靠的是 20 秒阈值卡在两次 30 秒心跳之间；改成 40 秒之后，
主菜单的心跳让看门狗永远等不到断流。**而主菜单的包长得和对局包完全不同**：

```
对局中      {"provider", "map", "player":{…有内容…}, "hero", "items", …}
回到主菜单  {"provider", "player":{}, "events":[]}     ← 没有 map，player 是空对象
```

所以文件开着时收到"没有 `map`、`player` 是空对象"的包，就以「回到主菜单」收尾，这一包不写进去。
十三份录制、三万八千多包核对过：**这种包在对局中途一次都没出现过**（有两份在第 0 包出现过一次，
是"没有 matchid 不建文件"那条规则之前的老文件刚建出来的那一包），只在回到主菜单之后才有。
按结构判断，不是调出来的参数。

看回放的情况不受影响：回放放完停在结束画面时心跳还带着 `map`，不会收尾；退出到主菜单才收。

#### 比赛结束 10 秒后收尾（2026-10-09）

`map.game_state` 变成 `DOTA_GAMERULES_STATE_POST_GAME`（同一包 `map.win_team` 从 `none`
变成 `radiant` / `dire`）之后，**再录 10 秒就收尾**（`POST_TAIL_SECS`）。对账要的只是结束那一刻的
几包（官方终局净资产、胜方）；之后结算画面挂着、GSI 照推，全是噪声——m9035205154 那份回放里，
遗迹倒下后十几包金钱还在一直涨（从 9017 涨到 9069，结算画面是 9015）。

- 写包时判一次，看门狗也判一次：结束后 GSI 可能只剩 30 秒一个的心跳，等下一包才收尾太晚
- 收尾后**同一局后面的 POST_GAME 包不再建新文件**（记在 `sealed` 里），否则每局都多一个只有结算包的碎片；
  只挡 POST_GAME 的包——同一局的回放从头再看一遍时状态会退回去，那是新的一次录制，照常建文件
- 回放也适用：放到结束 10 秒后就收尾，不用等退出回放

#### 第四条路：文件在录制途中消失（2026-09-19）

同一个失败形态又出现了一次，这次的原因在程序之外：**用户在资源管理器里删掉了
正在录的那个文件**，而程序毫不知情地继续写了 26 分钟，收尾时数据全没。

日志复原的时间线：

```
22:33:26 [record] 开始录制 ...\records\raw_1789828406.jsonl.gz
22:33:36  ← 目录结构变动（用户删掉几个不完整的录制，把刚建出来的这个也带走了）
22:59:32 [record] 收尾（关闭开关）：...\records\raw_1789828406.jsonl.gz
```

能这样是因为 **Rust 的 `File::create` 在 Windows 上默认带 `FILE_SHARE_DELETE`**
（`std::os::windows::fs::OpenOptionsExt::share_mode` 的默认值是
`FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`）。实测：持有写句柄时
`remove_file` 返回 `Ok`，之后 `write_all` 和 `flush` **也全部返回 `Ok`**，
而路径已经不存在——文件进入"删除挂起"，写入流向一个没有目录项的句柄。
**没有任何一层会报错**，这正是它静默的原因。

> 不去改 `share_mode` 挡住删除：那只会把"删不掉"的困惑转嫁给用户
> （资源管理器会弹"文件正在使用"，而用户并不知道哪个是正在录的）。
> **让删除成功、但别让它静默**才是对的方向。

所以给看门狗加了第二件事：每跳**顺便确认 `CURRENT` 指的文件还在**。不在就

1. 打一条 `ERROR` 日志，把丢掉的那段明确说出来；
2. 收尾当前这个幽灵句柄，把 `sink` 清掉。

下一包到来时 `write()` 会懒建一个新文件，**这一局剩下的部分照样录得到**。
已经写进幽灵句柄的那段找不回来——它连目录项都没有了——但损失从"整局"缩到
"最多 2 秒内发现之前的那一段"。

#### 断流要退回待机（2026-09-22 加）

Dota 崩了、被关掉、或者网络断了之后**不会有任何通知**，`main.js` 里的 `last`
会一直留着最后一包。按住 Alt 仍然显示一份**冻结**的旧面板：倒计时不动、
净资产不动，而它看起来和正常面板一模一样——**比不显示更坏**。

POST_GAME 那一半原本就是对的：它不在 `match.js` 的 `IN_MATCH` 集合里，
`inMatch` 自然为假，面板会隐藏。缺的只有断流，而 `match.update()` 只在**收到包时**
才跑，检测不了"没有包"。所以判断放在 250ms 那圈渲染循环里。

**阈值分两档**，因为 GSI 配置里 `heartbeat` 是 **30 秒**（见 `gsicfg.rs`）：

| 情况 | 阈值 | 理由 |
|---|---|---|
| 没暂停 | **5 秒** | `clock_time` 每秒都在变，`throttle 0.1` 下包是连着来的 |
| 暂停中 | **40 秒** | 暂停时什么都不变，GSI 只剩心跳，30 秒才推一次 |

用单一的 5 秒会把正常的暂停误判成断流、把面板关掉。

> **只是不渲染，不重置各个 tracker。** 数据回来时若还是同一局，接着算就是了；
> 换局了 `newMatch` 自然会触发重置。

> **断流只藏面板，不换数据**（2026-09-29 改）。原先断流时把整份渲染数据换成空的 `IDLE`，
> 但眼位、买活、塔防这些 tracker 并不跟着清空，结果只有**净资产归零**、其余停在最后一刻——
> 进编辑态时看到半份 0、半份旧值，毫无意义；用户对账时要看的恰恰是最后那个净资产。
> 现在断流时照常用最后一包渲染，只把 `visible` 压成假：**平时照样看不到**（不显示冻结数据
> 的初衷不变），编辑态里看到的是最后一刻完整、一致的状态。

实测：`demo.html?speed=60&loop=0` 让回放 10 秒跑完然后停住，净资产在最后一包
之后 **5 秒**从 5,346 变成 0——渲染循环换到了 `IDLE`，而 `IDLE.info.inMatch`
为假正是 `visible` 的必要条件。

> **截图工具要绕开它。** `tools/make_shots.py` 的做法是切一段录像、播完停在最后一包，
> 断流检测会在 5 秒后把面板藏掉，截出来一片空白。它在页面里设 `window.HELPER2_FREEZE`，
> `main.js` 见到就不判断流；Tauri 和项目主页都不设。这条是 2026-09-29 重拍截图时才发现的——
> 断流检测上线后没人重拍过面板图，而原先网页开发的 `v` 键连 `inMatch` 也绕过，把问题盖住了一半
> （能显示，但显示的是待机的空数据）。

上面这个只验到了数据归零，没看到面板真的消失（测试环境里 Alt 和始终显示都进不去）。
**2026-09-28 实战补上了**：GSI 停了之后面板隐藏，不再显示冻结的旧面板。

> `isinstance(ev, dict)`），把每一包的事件全丢了——对账在 `glyph` 上逮到 54 处
> 不一致。`cachepool.js` 的注释其实写着"数组不适用"，我没照着读。
> 光看白名单是发现不了的。

> **demo 数据绝不能放进 `ui/`。** `tauri.conf.json` 的 `frontendDist` 指着 `../ui`，
> **整个目录都会编译期嵌进 exe**——往里扔一份几 MB 的回放，每个用户下载的包里
> 都背着它。数据放 `site/`，只有部署流水线会去拿。
>
> 这条是实测撞出来的：测静态回放时把切片临时放进 `ui/`，才想起来它会被嵌进去。

#### 常数的路径去掉了前导斜杠

浏览器分支原先五处写的是 `fetch("/constants/…")`，**绝对路径**——部署在
`https://<user>.github.io/dota2-game-helper2/` 这种子路径下会 404。
backlog 里把这条标成"唯一一个一定会咬人的地方"。

实际解法比预想的小：**去掉那个前导斜杠**就行。相对路径按页面所在目录解析，
Pages 上 `/dota2-game-helper2/index.html` → `/dota2-game-helper2/constants/…`，
开发服务器上 `/dev.html` → `/constants/…`，两边都对，不需要任何可配的 base。

五处的 Tauri 那一半各不相同（三处走 `get_constants`，价格表走 `get_item_prices`，
版本走 `get_versions`），所以**只把浏览器那一半收进 `fetchConstant()`**，
Tauri 那半留在原地。硬要把两半都抽出来，就得在一个函数里塞三种命令的分支，
比现在难读。

> **前提是页面在部署根目录。** 页面要是挪进子目录（比如未来加一页使用文档
> 放在 `docs/`），相对路径会跟着一起挪。那时再给它一个 `<base>` 标签，
> 而不是把斜杠加回去。

### 智能显隐

`map.game_state` 不在 PRE_GAME / GAME_IN_PROGRESS 时整窗隐藏。

**观战 / 回放视角也整窗隐藏**（2026-09-08 定，见 [../backlog.md](../backlog.md) 的"明确不做"）。

判定不靠白名单，靠**结构**：自己打的时候 `player` 是扁平的一份人（`player.team_name`
是 `"radiant"` / `"dire"` 这样的字符串）；观战和看回放时 GSI 推的是**全员结构**——
`player` 变成 `{ team2: { player0: {...}, player1: {...} }, team3: {...} }`，
`hero` 同理。于是"`player` 在、但没有 `team_name`、却有 `team\d` 这样的键"就是观战。

```js
const spectating = !!p && !p.team_name && Object.keys(p).some(k => /^team\d+$/.test(k));
```

**为什么必须显式判掉，而不是"反正算不出来就空着"**：净资产那条链路读的是
`player.gold` / `player.items`，在全员结构下这些键根本不存在，取到 `undefined` 之后
一路算成 0——面板会**照常显示一个看起来正常的 0**，而不是明显的坏值。
显示一个错数字比什么都不显示更糟。

**不做部分降级**。技术上是能的：符、莲花、智慧、堆野只依赖 `map.clock_time`，
眼位只依赖 `minimap`，这两样在观战下反而更全；坏掉的只有净资产（需要
`player.gold`）和买活、塔防的左右（需要 `myTeam`）。不做的理由是产品定位——
观战和回放本来就有一堆现成工具，这个覆盖层要解决的是**你正在打的那一局**里
游戏不告诉你的事。半开的面板还会让人以为是坏了。

## 贴着 Dota 自己的界面画（2026-10-08 起，v1.4.0）

**v1.3.x 是四个可独立拖动的块**（倒计时 / 敌方塔防 + 买活 / 净资产 / 眼位小地图），
各存一份坐标在 `layout.json`，有默认摆位、钳位、重置。**v1.4.0 全部改成贴着 Dota 自己的界面画**，
不能拖、不存坐标；`layout.json` 不再读写，Rust 的 `save_layout` / `load_layout` 删掉了。
v1.3.x 那套设计（815px 的整条面板怎么拆成四块、默认摆位、钳位）见 v1.3.6 的 tag。

为什么改：

- **买活的圆点要去顶栏对颜色**才知道是谁；贴到每个人头像底下之后，**位置本身就是身份**
- **眼位小地图是另一张地图**，眼要在两张图之间对照；直接画在原生小地图上就只有一张
- 块浮在画面中间，每个人摆的位置不一样、也会挡东西；贴着游戏界面，位置本身就有意义
- 拖动带来的一串麻烦（拖出屏幕、换分辨率乱掉、存坐标的文件）一起没了

**用户确认拖动不加回来**（2026-10-09）：买活、塔防、眼位拖了反而对不准；
倒计时和净资产的位置是用户自己定的，也会跟着分辨率缩放。真遇上别人的界面对不上
（4:3 拉伸、超宽屏），该改的是代码里量的值，不是让用户去拖。

### 怎么算位置

**Dota 的界面按屏幕高度等比缩放，顶栏水平居中。** 所以只量一次、记成"1080 高下离中线 / 离边多远"，
任何分辨率都是：

```
k = 屏高 / 1080
x = 屏宽 / 2 + 偏移 × k        （顶栏那一排）
y = 偏移 × k
```

覆盖层窗口铺满主屏，所以视口就是屏幕，程序自己知道 `屏宽 × 屏高`。大小也乘 `k`——
换分辨率时覆盖层和游戏界面一起变大变小。

| 元素 | 锚点 | 1080 下的值 | 代码 |
|---|---|---|---|
| 买活 | 每个人头像正下方 | 最靠中线的头像中心离中线 138，间距 62.3；行中心 y = 68 | `topbar.js` |
| 敌方塔防 | 敌方那一端、挨着最外侧头像 | 中心离中线 434、y = 19；圆直径约 37 | `topbar.js` |
| 倒计时 | 顶栏计时牌正下方，水平居中 | 圆环顶边 y = 44；块缩放 0.72 | `render.js` |
| 净资产 | Dota 左上角「击/死/助」面板右边 | 左 175、顶 64 | `render.js` |
| 眼位 | 原生小地图上 | 见下 | `wardmap.js` |

量自两张截图：一张 1863×1047 的直播画面（16:9），一张用户自己的 2560×1600（16:10），
两边对得上，"按屏高缩放"在 16:9 和 16:10 上都成立。**没验过**：4:3 拉伸（游戏横向拉伸了、
视口却还是 16:9）、比 16:9 更窄的屏、游戏不在主屏上。

### 读 Dota 的设置（2026-10-08）

`dotacfg.rs` 的 `dota_hud` 命令，**只读**：

| 文件（`Steam\userdata\<账号>\570\` 下） | 键 | 用途 |
|---|---|---|
| `remote\user_convars.vcfg` | `dota_hud_extra_large_minimap` | 「使用特大尺寸小地图」 |
| | `dota_minimap_position_option` | 「地图位置」，0 靠左、1 靠右 |
| | `dota_hud_flip` | 老版本的整个 HUD 翻转，新版设置里没有了；只在读不到上一项时兜底 |
| `local\cfg\video.txt` | `setting.defaultres` / `defaultresheight` / `fullscreen` / `nowindowborder` | 分辨率与窗口模式，暂时只记日志 |

键和设置项的对应是用户截了 Dota 设置界面对过的。一台机器登过好几个账号时，取 `user_convars.vcfg`
**最近被写过**的那个（Dota 每次退出都会写它）。启动时读一次、每局开始再读一次——两局之间可能改了设置。

读不到（文件不在、Valve 改了键名）时用设置卡片里「小地图」那个下拉框：默认「自动」，
可以手动指定左下 / 右下、普通 / 特大，见「设置」。

> **没去读游戏进程里的界面布局**：那要读内存或注入，和外挂是同一类行为，有 VAC 风险，
> 也违背"只收 GSI"的定位。**也没去解包游戏的界面文件**（VPK 里编译过的 Panorama 布局）：
> 要第三方工具反编译，而且很多位置是运行时算的；截图量出来误差已经在 1px 左右，
> 等哪天 Valve 大改界面、截图量起来太麻烦时再说。

## 图标：覆盖层上没有文字

**覆盖层上不出现任何需要翻译的词。** 剩下的只有数字（倒计时、净资产）和
GPM / XPM 这两个通用缩写。

收益不是"省掉十几条翻译"，而是**那条写死的宽度约束自己消失了**——

### 尺寸与两个坑

**环内 24px，行内 16px。** 12px 下书和莲花的细节会糊。倒计时块缩到 0.72 之后，
环内图标单独放大到 32px（缩完约 23px，再乘屏高比例）；顶栏的买活图标 14px。

1. **`.cell svg { width: 52px }` 会把图标撑成 52px。** 那条是给圆环用的，特异度 (0,1,1)。
   必须写成 `.cell .lab svg.ico`（0,2,1）——**和眼位地图那个 bug 是同一个坑**。
2. **`set()` 用不了。** 它比较值后写 `textContent`；图标要整段替换 SVG，
   得走另一个 `setHtml()`，同样只在变化时才动 DOM（渲染 250ms 一轮，别每帧重建 SVG）。

### 放大不糊，风险在小端

实测缩放 2× 时 SVG 布局尺寸仍是 52、渲染尺寸变成 104——浏览器按新尺寸重新光栅化，
不是拉伸位图，边缘保持矢量清晰。

风险在**缩小**：描边 `1.7` 是 24 viewBox 里的值，图标越小描边越细。
标签位那版 14px 在 0.8× 时只剩 **0.79px**，会被抗锯齿摊成浅灰；
挪进环里放大到 24px 之后是 **1.36px**，实测在最暗和最亮的背景上都清楚。
另加了 `drop-shadow(0 0 2px #000)` 作衬底。

### 程序图标

锈红粗边方块 + **挖空**的开口环，背景透明，见
[`tools/make_icons.py`](../../tools/make_icons.py)（形状即代码，改常量重新生成整套）。

结论都是排开十几版、只按 **16px** 挑出来的——托盘上就这么大，别的尺寸都是参考：

1. **实心色块挖空，不要描边。** 描边到 16px 只剩一两个像素宽，一糊就没了；
   挖空的图形有整块颜色撑对比。第一轮全用描边的九版，没有一个比这一版清楚。
   Dota 自己那个标能缩到很小还立得住，也是这个原因。
2. **去掉底板就得把红提亮。** 中途试过加一层深蓝圆角底板（取自 Dota 横版 logo 的底色），
   它确实能解决浅色任务栏的对比度。去掉之后，原来的 `#A6392A` 贴在**深色**任务栏上
   明显发闷，于是提两档明度到 `#C24A34`——同一个色相，只动明度，深浅两种任务栏都够。
3. **缺口 60°，正对 45°。** 中轴线因此就是左上—右下那根对角线，
   和那个标里那道白色斜刃同向。中心必须落在 45° 整——先试过 67.5°，
   只偏 22.5° 就看得出轴是歪的，缺口像"滑到了下面"而不是"顺着对角切开"。
   宽度再窄，16px 下那道缝会被抗锯齿抹平，环就退化成一个实心甜甜圈。
4. **毛边只留少数几个大缺口**，步长 4（画布 24）、幅度 ±0.85。再细的锯齿 16px 下
   一定被抹平，白费。而且顶点是**一次性生成后定死写进代码**的：
   每次构建重新随机，图标就会悄悄变样，而图标必须是稳定的身份。

> 原来那版是金色开口细环。它在 16px 下**读作"程序卡住了"**——一个加载转圈，
> 这才是它真正的问题，不是"看不出和 Dota 有关"。
>
> **借的是画法，不是身份。** 实心方块 + 挖空图形 + 粗糙手绘边是通用作图技术，
> 也正是 16px 下唯一有效的那条路；那个"D"和它的整体识别特征不碰。

> **ICO 里 256 以下必须用 DIB，不能用 PNG。** PNG 压缩的图标条目微软只保证
> 256×256 那一档；更小的尺寸，资源管理器在有些路径上认不出来，于是回退到别的
> 条目、或者干脆继续用缓存里的旧图——表现就是"exe 图标怎么都换不掉"，
> 排查时极易误判成 Windows 图标缓存。`make_icons.py` 因此 <256 出 DIB
> （BITMAPINFOHEADER + 自下而上的 BGRA + AND 掩码）、256 出 PNG。
> AND 掩码对 32 位图没实际作用（透明看 alpha），但**必须在**，
> 且每行按 4 字节对齐，否则整张图会错位。

> **换了图标却只变了一半：`build.rs` 必须监视 `icons/`。**
> **一旦发出任何 `cargo:rerun-if-changed`，cargo 就不再监视整个包目录**，
> 只认声明过的那几个；而 tauri-build 自己只声明 `tauri.conf.json` 和 `capabilities`，
> `icons/` 谁都没管。结果是换图标后**托盘变了、exe 在资源管理器里的图标没变**——
> 前者走 `generate_context!` 宏，跟着 crate 重编一起展开；后者是 `build.rs` 里
> tauri-winres 编出来的 `resource.lib`，`build.rs` 不跑就永远是旧的。
> 看起来像"Windows 图标缓存没刷新"，其实是根本没重新生成。
> 查法：解 PE 的资源表，把 RT_ICON 的字节和 `icons/icon.ico` 逐条比。

> **只生成用得上的那几个**（2026-09-29 精简）。脚手架那套里有 9 个 `Square*Logo.png`
> 和 `StoreLogo.png`（Windows 应用商店 MSIX 用）、`icon.icns`（macOS 用）、`64x64.png`（没人引用），
> 这个程序只出 Windows 版、发的是 zip，将来的安装包也是 nsis，一个都用不上。
> 现在只剩：`icon.ico`（exe 与托盘）、`32x32.png` / `128x128.png` / `128x128@2x.png`
> （`tauri.conf.json` 的 `bundle.icon` 引用）、`icon.png`（两份 README 和项目主页）。
> `make_icons.py` 跟着只写这五个，否则一跑又全回来。

本机没有 Pillow / cairosvg / ImageMagick，所以 `make_icons.py` 自带一个极小的
光栅化器：形状全可解析判定（多边形、圆角矩形、带缺口的圆环），4×4 超采样，
PNG 用 zlib 手写。**边缘的颜色按覆盖到的子样本平均、透明度按覆盖率，两者分开算**——
不分开算，边缘会被背景色拉暗，出现一圈脏边。

### 一个实测教训

币堆最初画成两个叠起来的**扁椭圆**，13px 下退化成**两条横杠**，完全看不出是硬币——
正好败在图标化的全部目的上（不靠文字也能理解）。改成两枚**相互叠压的圆**才立得住。
小尺寸下椭圆和细线是最先垮掉的两种形状。

### 卡片同时是图例

九个显示项开关每行前面放对应图标（`showIcon()`），**和覆盖层用的是同一份 `icons.js`**，
形状永远不会脱节——眼位图例复用地图自己的 `wardIcon` / `crossIcon` 是同一个思路。
文字集中在卡片，而卡片正好是唯一需要翻译的地方。

**每行只放一个图标。** 眼位那行曾经放过"眼 + 塔"（想表达那块地图画了哪两类东西），
但九行里只有它是两个，反而不齐。

> **那个塔图标已从 `icons.js` 删掉**（2026-09-16）。这里原先写着"仍留着供眼位图例
> 那一节使用"，而那是**假的**：图例画的是 `<rect class="wm-tower">`——直接复用地图
> 自己的 class，颜色才不会和地图脱节，这正是图例那一节定下的做法。
> 于是它从加进来那天起一次都没被引用过。

> **覆盖层上的图标尺寸一律由 CSS 决定**，`icon()` 的 `size` 参数在 `.cell .lab` 里会被覆盖；
> 那个参数只对卡片有效（`.ed-ico` 没有设宽高）。
> 加尺寸例外时**要么写在通用规则之后、要么把特异度做高**——两条同特异度时靠顺序取胜。
> 这个文件里同类的坑出现过三次（圆环压图标、真眼空心、买活图标放大），
> v1.4.0 的倒计时图标放大写成 `[data-block="timers"] .cell:not(.wide) .lab svg.ico`，特异度更高，不靠顺序。

## 托盘

程序原本**没有任何正常退出的途径**：窗口无边框、`skipTaskbar` 为真、没有托盘，
只能去任务管理器杀进程。托盘补的是这个真窟窿，不只是锦上添花。

```
右键菜单                              左键单击图标 → 同样 toggle 编辑态
├ 设置 (Ctrl+Alt+F10)                  （与热键共用同一份编辑态，别各存一份）
├ ──────
└ 退出
悬停提示：dota2-game-helper2 v1.3.6
```

> **「编辑面板」改名「设置」**（2026-10-09，v1.4.0）：块不能拖了，编辑态就只是打开设置卡片。
> **悬停提示带版本号**：用户报问题时鼠标移上去就能念出来。
> **有新版本时多一项「有新版本 X」**，点了打开设置卡片，见「一键更新」。
> **原先第一项是带勾的「始终显示」，2026-10-10 去掉了**：对局中够不着托盘，用不上，
> 见「纯 Alt 查询」的「按住 Alt 才显示」。

**菜单上标出热键**（2026-09-20）。在此之前 `Ctrl+Alt+F10` **只在 README 里出现过**，
产品本身一个字没提——而它恰恰是「三条退出路径」里的最后一条兜底，
**被编辑态困住时最需要它的人，正是最没机会去翻 README 的人**。
托盘是进编辑态的主路径，标在这里学一次就记住。

> 热键那串拼在 Rust 里，不进语言包。当时两个原因：`Ctrl+Alt+F10` 两种语言一个样；
> 而且语言包那时**只补缺键、不覆盖已有值**，改包里的 `tray.edit` 到不了老用户手上
> （2026-09-29 起语言包不再播种，后一条不成立了，前一条仍然够）。

### 左键单击一直是坏的（2026-09-20 修）

原先的事件匹配是 `TrayIconEvent::Click { button: Left, .. }`，**没有过滤
`button_state`**。而 Windows 上按下和抬起各发一条 `Click`：

| 操作 | 收到的消息 | 原先 toggle 次数 | 表现 |
|---|---|---|---|
| 单击 | `DOWN`, `UP` | 2 | 开了又关，**看起来没反应** |
| 双击 | `DOWN`, `UP`, `DBLCLK`, `UP` | 3（`DoubleClick` 被忽略） | 停在"开" |

所以上面那句"左键单击 → toggle 编辑态"**一直是不成立的**：真正能用的是双击，
而那只是凑出来的奇数次。这个 bug 藏了很久，因为它不报错、也不崩——
单击没反应的人会默认"大概本来就没这个功能"，改用右键菜单。

改成**只认 `Up`**之后单击恰好一次。双击还会多出一个 `Up`（序列里 `DBLCLK`
之后那个），用一个 `SWALLOW_UP` 标志吞掉——**让双击和单击表现一致**，
而不是开了立刻又关。

> 顺带加了三条 `Debug` 级日志（抬起 / 双击 / 吞掉），这类事件序列的问题
> 光看代码推不出来，得让它自己说。

## 编辑态

### 一次返工：设置窗口并入编辑态

最初的设计是**两个入口**——托盘「设置…」开一个独立窗口，托盘「调整面板位置」进编辑态。
上手用过之后推翻了，原因是结构性的：

> 设置窗口必须 `alwaysOnTop`（否则会被覆盖层压住，实测直接"打开后看不见"），
> 而面板默认在屏幕顶部正中、弹窗也在屏幕中央——**两个都置顶就一定互相遮**。
> 更要命的是面板平时藏着（只有按住 Alt 或编辑态才显形），
> 于是调缩放、调透明度、开关显示项**全都是在盲调**。

改成**单一编辑态**：面板常显可拖 + 设置卡片就画在它旁边，改一下当场看到效果。
（v1.4.0 起块不能拖了，编辑态只剩"开设置卡片 + 看位置对不对"，见「贴着 Dota 自己的界面画」的「编辑态」。）

### 构成

覆盖层窗口内两层，只在编辑态一起出现：

| 层 | z 序 | 作用 |
|---|---|---|
| `.block` ×2 + 顶栏层 + 小地图层 | 下 | 真实的覆盖层，各自画出虚线框 / 占位框，不能拖 |
| `#editor` | 上 | 设置卡片（标题栏 + 一页内容 + 底部「重置 / 完成」） |

**卡片是 `.block` 的兄弟节点，不是子节点。** 块被 `--panel-scale` 缩放（屏高比例 × 各自基准），
卡片若是子节点会跟着缩，没法用。

**卡片自己也可拖，但只能靠顶部的标题栏**（原因见下面第 3 号坑）。
位置**不存盘**，每次进编辑态回到屏幕中央偏下。

> 拆成四块之前，卡片是"锚在面板下方并跟随拖动"的。四块之后"面板"没有唯一所指，
> 这套锚定失去意义，连同它那圈 rAF 一起删掉了。
> 固定在屏幕某一角也否决过——块一旦被拖到那个角就会互相压住，
> 而"同时看见面板与设置"正是当初合并编辑态的全部意义。

### 只有卡片吃鼠标（2026-10-09，v1.4.0）

**v1.3.x 编辑态整窗不穿透**（`set_ignore_cursor_events(false)`）：全屏一张透明的膜，卡片以外
点不到游戏、桌面、任务栏。那是给拖块用的——块可能在屏幕任何位置。v1.4.0 块不能拖了，
要点的只剩卡片，所以改成**只有卡片那块吃鼠标**：

- Tauri 只能整窗切换穿透，没法只放开一块区域。`hittest.rs` 每 30ms 读一次鼠标位置
  （`GetCursorPos`，和读 Alt 一样是被动读），编辑态下在卡片矩形里就关掉穿透，离开就恢复
- 卡片的矩形由前端报过去（`set_card_rect`，物理像素）：打开、关上、拖动、尺寸变化
  （`ResizeObserver`）时各一次
- **按住左键时不切**：拖卡片拖得快时鼠标会跑到还没更新的矩形外面，下拉框的弹出层也会伸出卡片；
  这时切成穿透，松手那一下就落进游戏里了
- 不在编辑态时轮询那边也强制穿透，兜住和 `set_edit` 的时序交错——不会留下一张挡住全屏的膜

代价：鼠标点了游戏之后焦点回到游戏，**ESC 就交给游戏了**，要退出编辑态点「完成」或按 `Ctrl+Alt+F10`。

### 三条退出路径

v1.3.x 编辑态下桌面点不动、连托盘都点不到，所以出口必须冗余；v1.4.0 卡片以外能点了，
这三条照留：

1. 卡片底部的**「完成」按钮**——不依赖键盘和窗口焦点，最可靠。
   卡片最底下一行，展开什么都不会把它挤出屏幕
2. **ESC**——进编辑态时主动 `set_focus()`，前端监听 `keydown`
3. **`Ctrl+Alt+F10`**——系统级热键，不经过被遮住的窗口，是最后的兜底

> 曾经有第四条「点空白处退出」，**已移除**。它当初按兜底加入，但真被困住时能救场的是热键——
> 点空白处要求你能看见并点中面板以外的区域，而那正是被困场景下最不成立的前提。
> 它没有提供任何独占覆盖，只贡献了摆位时的误触风险。

### 六个必须避开的坑（都只有真机才暴露）

1. **`html, body` 必须 `pointer-events: none`**，否则编辑态下一张看不见的全屏膜会盖住整个桌面，
   连托盘图标都点不到，只能靠热键逃出来。
2. **`set_edit` 内绝不能调 `global_shortcut` 的 register/unregister**——
   它会从热键回调里被调用，而插件派发回调时持有内部锁，在回调里再动注册**直接死锁**，
   实测整个程序卡死。ESC 因此走前端 `keydown`，也不该注册成全局热键（会劫持游戏内菜单键）。
3. **拖拽区里不能有需要点击的控件**：拖拽在 `pointerdown` 时 `setPointerCapture`，
   之后 `pointerup` 会被改派到捕获元素，`click` 便落在那个元素而不是按钮上，
   **按钮的监听器永远不触发**——实测表现为"点完成没反应，且编辑态再也退不出去"。

   最早是「完成」按钮放在面板内部踩的，把按钮移进卡片就解决了。
   但**卡片自己也能拖之后，这个坑原样回来了**：卡片里装着「完成」、九个复选框
   和几个下拉框，整块当拖拽区会把它们全部打死。所以卡片只有顶部那条
   `.ed-bar` 标题栏可拖。
4. **`.block` / `.cell` 的 `display: flex` 会盖过 `[hidden] { display: none }`**，
   必须显式写 `!important`，否则设置里的显示项开关整个不起作用。
5. **常数表只播种、不补齐 = 静默失效**。`constants.rs` 原本只在文件不存在时写入，
   于是 9/1 播种的 `normal.json` 遇上 9/5 新增的 ward 常数就永远缺那几个键，
   而 `get_constants` 把盘上文件原样返回。后果不是报错而是**静默的错**：
   `this.C.wardSentryDuration` 是 `undefined`，`Math.ceil(x + undefined - y)` 得 NaN
   直接画在地图上；更糟的是 `rem > undefined` 和 `clock - lastSeen > undefined` 恒为假，
   于是**被排检测一次都没触发过、敌方眼永远不移除**，全程没有任何报错。
   现在读盘与播种都把盘上的值盖在内置默认值之上（复用 `settings.rs` 的 `merge`）。

   > **价格表刻意不进这套，它根本不播种到配置目录。** 盘上那份会静默压住内嵌的新表，
   > 而「只补缺键、不改已有键」修不了已经改过价的物品。价格源换成游戏本体之后
   > 用户也没有再手改它的理由，于是副本整个去掉——见 design/networth.md 的
   > 「为什么价格表不再播种到配置目录」。`patch.json` 同理，它只内嵌、不落盘。

   > **2026-09-29 起其余常数表和语言包也不再播种**，这一条描述的失败形态整个不存在了：
   > 只有内嵌的那一份，没有"盘上缺键"可言。理由见 [timers.md](timers.md)「常数外置」。

6. **`innerWidth` 可能是 0**，而所有摆位都要按视口算。
   实测浏览器里页面刚导航完、以及窗口被隐藏期间，`innerWidth` 会持续为 0。
   v1.3.x 那时更危险：摆位结果会**回存**到 `layout.json`，一次异常启动就把摆好的坐标全冲掉。
   v1.4.0 不存坐标了，但按 `0` 算出来的位置照样是错的——`placeBlocks`、`topbar.js` 的 `place`、
   `wardmap.js` 的 `place` 在视口为 0 时都直接跳过这一帧，下一帧再算。

竖着堆成一条要 475~754px。v1.4.0 去掉了缩放、整体、底板、眼位地图大小四个滑块，
图例从九条缩到三条，常用的东西一页放得下（收起开发区约 330px）。
中间试过"一页 + 底部可展开的「版本与开发」"，展开那一栏里版本、按钮、下拉框、勾选框
混在一起没有分组，用户嫌怪，改成现在这样：**版本一行常驻，开发区按 `devTools` 整节出现或不出现**，
不需要折叠。

**下半部分是一张两列的表**（`.ed-form`）：左边标签、右边控件，三个下拉框一样宽、起点对齐。
原先每行"标签 + 控件"自然排，标签长短不一，控件起点各不相同，再加上几个靠右的按钮，看着乱。

**字号只有两档**：13px 给所有要读、要点的东西（标题、分组名、选项、按钮、版本号），
11px 只给附注（图例、小地图读到的结果、热键提示、底部提示、更新状态）。

标题和分组名反而比正文小，层级是乱的。

**显示项排三列**（原先两列五行），卡片宽 300 → 330px，为的是英文的 `Enemy glyph`、
`Net worth` 在三列里放得下。九个勾前面的图标和覆盖层用的是同一份 `icons.js`，
所以这一栏同时是图例；眼位那三样（品红眼睛、绿叉）在下面单独一行，复用地图自己的
`wardIcon` / `crossIcon`，另写一套迟早会和地图对不上。

#### 开发区（录制）

> **只给开发者看**（2026-09-29）。`settings.json` 里 `devTools` 为真才有这一节，
> **录制器也只在 `devTools && recordMatches` 时工作**——万一 `recordMatches` 早先被打开过，
> 没有 `devTools` 也不会录。`devTools` 界面上没有开关，要在 `settings.json` 里手写
> `"devTools": true`，重启生效。**卡片里刻意不放这个开关**（2026-10-09 讨论过"单独一页、
> 顶上一个 devTools 勾选框"）：那等于把录制又摆到了所有人面前。
>
> 录制是对账用的：一局 4~90 MB，普通用户用不上，开着只会悄悄吃硬盘。
> **没做成编译开关**：那样开发者平时打游戏用的就不是发出去的那个 exe，
> 测的和发的不是同一个东西。

> **「打开数据目录」「打开下载页」点了先退出编辑态**（2026-09-29 修）。编辑态下覆盖层是
> 铺满屏幕、置顶、**不穿透鼠标**的透明窗口，打开的资源管理器和浏览器被压在它下面，
> 看得见点不到。所以先走和「完成」同一条退出路径（恢复穿透），再打开。
>
> **`set_settings` 因此改成盖在盘上那份之上，而不是盖在默认值之上。** 前端只收卡片上
> 有的控件，原先那样写，手写进去的 `devTools` 卡片上随便动一下就被抹掉了。

> **「打开数据目录」开的是 `%APPDATA%\dev.dota2helper2.app` 本身**，`records/`、`logs/`、
> `settings.json` 都在里面——给每个配一个按钮是把文件树抄到了卡片上。
> 真正让它划算的是 `logs/`：用户报"数字不对"，念完版本号下一句必然是"把日志发我看看"。

> **录制的清理是手动的，刻意不做自动清理**（2026-09-16）。按时间或大小自动删，
> 删掉的很可能正是待验清单在等的那一局，而打过的对局回不来。做决定的必须是人。
> **显示体积是这件事一半的价值**：不打开资源管理器就想不起来该删，
> 一个打开卡片就看得见的数字才是触发清理的那个东西。
>
> - 这个数字**在打开卡片的那一刻重拉**（2026-09-20 修；原先只在程序启动时拉一次，
>   打了三局再看还是旧数），拨录制开关后延后 300ms 再拉一次。不做轮询。
> - 个数的单位在英文里是空串：别把可数名词摆在数字旁边，名词在左边的标签里。
> - **清空要点两下**：第一下变成"确定删除？"，5 秒无操作退回。不用 `confirm()`，
>   它会弹一个抢焦点的系统框。
> - **正在录的那个文件跳过**：删掉它的结果是这一局后面的数据静默流进一个不存在的文件。

**卡片里的下拉框需要 `color-scheme: dark`**，而且只能加在 `.editor` 上：
弹出层由系统绘制，不声明配色方案就是白底，而 `option` 继承卡片的浅色文字 → 白字白底。
加在 `:root` 上会给根元素画上不透明底色，覆盖层就不透明了。

> 也不打算知道（见 backlog「已明确不做」）。版本号摆在卡片上，是为了用户报"数字不对"时

- **启动时静默查一次**，另有「检查更新」按钮手动再查。查到新版**只**在版本号旁边标 NEW，

  只开这一个写死的地址，前端传不进任意 URL。
- 已是最新不留常驻文字——版本号旁边没有 NEW 就说明了；只有手动点了「检查更新」时，按钮上闪两秒"已是最新"作为回应。

**请求从前端发，不从 Rust 发。** 前端的 `fetch` 跑在 WebView2 里，代理设置和 Edge 完全一样
（系统代理、PAC 都认）；而 Rust 的 HTTP 库默认不读 Windows 系统代理。很多用户能上 GitHub
靠的是系统代理，从 Rust 发就会出现"浏览器打得开、程序连不上"。顺带不用加依赖。
`tauri.conf.json` 的 CSP 是 `null`，GitHub API 带 `Access-Control-Allow-Origin: *`。

**只查 GitHub**：`api.github.com/repos/shizzhang0/dota2-game-helper2/releases/latest`，4 秒超时。
只取 `tag_name`。

> **曾经加过 jsDelivr 备用源，后来去掉了**（2026-09-29 用户定）。它要仓库里多一个 `latest.json`、
> 发版多一步，而国内对 jsDelivr 的可用性同样不稳定，换来的"多一条路"不确定。
> 连不上就显示"连不上更新服务器"，去浏览器里自己打开 Releases 页即可。

版本比较按三段数字（`v` 前缀去掉）。**只在 Tauri 里查**：浏览器开发和 GitHub Pages
的 demo 用的是同一份 `ui/js`，那里没有"程序版本"，也不该替访客去请求 GitHub。

**不加"启动时检查更新"的开关**（用户 2026-09-29 定）。自动的只有启动时这一次请求（手动点「检查更新」再发一次）、失败悄悄算了，
不带任何个人数据（GitHub 看得到的只有 IP 和 User-Agent）。代价是 README 里
"运行时不联网"那句要改成"只在启动时查一次版本"。

> **这件事之前的定案是"点了才查、不自动查"**（2026-09-23，理由是保住"运行时不联网"
> 这句对外承诺）。改成启动时查，是因为只有手动按钮的话，没人会想起来去点——
> 而常数表 2026-09-29 起不再落盘、用户没法自己改，**Dota 一更新就只能等新版**，
> 让用户知道有新版比这句承诺更要紧。

### 一键更新（2026-10-09，v1.4.0）

**发现**还是上面那套（前端查 GitHub 的 tag）；**安装**交给 Tauri 的 updater 插件（`updater.rs`）：
它读最新 Release 里的 `latest.json`，下载安装包、用公钥验签、静默安装（`passive`），
**安装器一启动程序就退出，装完自己重启**。下载进度通过 `update-progress` 事件给卡片显示。

- **只对安装版生效**：插件装的是 nsis 安装包、装到安装目录。用 zip 绿色版的人点了，结果是电脑上多一份
  安装版、手上那份 exe 还是旧的。所以先看 exe 旁边有没有 nsis 写的 `uninstall.exe`——
  没有就当绿色版，只给「打开下载页」
- **失败就退回「打开下载页」**：读不到 `latest.json`（漏传、连不上）、验签不过、下载断了，
  状态行写"自动更新失败，请到下载页手动下载"，错误原文进日志
- **托盘多一项「有新版本 X」**：前端查到新版后告诉 Rust（`set_update_available`），托盘菜单重建时
  多这一项，点了打开设置卡片。不在托盘里直接装：没地方显示进度，也不该在对局中途一点就退出程序
- **代理**：插件的 HTTP 走 reqwest 的 `system-proxy`（读 Windows 注册表里的系统代理），
  PAC 脚本不认。查新版本那一步仍在前端，PAC 也认；装不上就是上面那条退路
- 签名私钥和发版步骤见 [dev-tools.md](dev-tools.md)「发版」

### 安装包（2026-10-09，v1.4.0）

nsis，**只给当前用户装**（`installMode: currentUser`）：装到 `%LOCALAPPDATA%`，不进 Program Files、
不弹 UAC。开始菜单有快捷方式，Windows「应用」里能卸载；缺 WebView2 的机器安装时会自动装上
（单 exe 在那种机器上直接打不开）。

- **卸载时删掉写进 Dota 目录的 GSI 配置**：nsis 卸载前带 `--cleanup` 启动程序一次
  （`windows/hooks.nsh`），程序只删自己那个配置文件就退出，不起窗口。不在 NSIS 脚本里删，
  是因为 Dota 可能装在 Steam 的任何一个库里，找库的逻辑 `gsicfg.rs` 里已经有了。
  卸载器自带一个"删除应用数据"的勾，勾了才删 `%APPDATA%\dev.dota2helper2.app`（设置、日志、录制）
- **没有代码签名**，SmartScreen 会拦（单 exe 也一样，不是新问题）；签名证书一年几百美元，先不买
- **绿色版 zip 保留**，解压即用；它没有一键更新
- 应用标识 `dev.dota2helper2.app` 以 `.app` 结尾，打包时 Tauri 会警告（只影响 macOS）。**不改**：
  改了标识 `%APPDATA%` 下的数据目录跟着换，老用户的设置和录制就找不到了

### 配置与生效

存 `settings.json` 于配置目录（与 `records/`、`logs/` 同级）：

```json
{
  "show": { "mid": true, "bounty": true, "wisdom": true, "lotus": true,
            "stack": true, "glyph": true, "buyback": true, "econ": true,
            "wardmap": true },
  "alwaysShow": true,
  "minimap": "auto",
  "logLevel": "info",
  "recordMatches": false,
  "devTools": false,
  "lang": "zh-CN"
}
```

v1.3.x 留下的 `scale`、`opacity`、`panelBg`、`wardSize` 还在老用户的文件里，读了也不用，无害；
`layout.json` 同理，v1.4.0 起不再读写。

Rust 提供 `get_settings` / `set_settings`；保存后 emit `settings` 事件，
**覆盖层实时应用，不需重启**。卡片与面板同在覆盖层窗口内，这条事件成了自发自收，
但链路不变——保持单一数据流向，不给卡片开后门直接改面板。

读盘时**缺什么补什么**，所以老配置文件遇上新增字段也能直接用。


## 多语言

**范围只有两处**：编辑态卡片和托盘菜单。覆盖层上一个字都没有（2026-09-08 图标化），
所以面板本身不需要翻译——这才是图标化真正的收益。代码里的中文全是注释和日志，
给开发者看的，不该翻。

**不上 i18n 框架**，理由写全在这儿，免得以后重新讨论：

1. 框架值钱的地方是复数规则、ICU 消息格式、locale 懒加载、词条抽取工具链、
   fallback 链。我们是 30 来条静态短语 × 2 种语言，**一条插值都没有**，这些全用不上。
2. **前端没有构建步骤**——`ui/` 是原生 ES 模块，编译期直接嵌进二进制。引框架要么
   加打包器、要么往仓库里塞 UMD；而覆盖层必须离线可用，CDN 这条路本来就堵死。
3. **托盘菜单在 Rust 侧**，JS 框架管不到。无论如何都得有一份两边都能读的东西，
   那正好就是一个 JSON——框架在这里只覆盖一半，还多一套机制。

需要的就是 `T[lang][key]` 加一条"缺键回退中文"，十几行。

框架唯一能白给而我们会缺的是**漏翻检查**——一段 grep 比较两份 JSON 的键集合即可补上。

> **会改主意的情形**：词条涨到几百条、有第三方帮忙翻译（那时抽取和校验工具才值钱）、
> 或需要复数 / 日期本地化。数字已用 `toLocaleString` 处理，日期没用到。

> **原先最难的那一条在动工前就消失了。** 当初记的是：面板宽度写死（`.cell` 60px、
> 买活 104px、净资产 116px），而"净资产"换成 `Net Worth` 会更宽，直接翻译会撑破或截断，
> "得让宽度跟着语言走"。图标化之后面板上没有词，这个约束不复存在——
> **这才是图标化真正的收益**，不是省掉那十几条翻译。
>
> 也因此界面多语言原本"排在整个清单的最后"（与布局耦合：布局定了才知道每格能给多宽），
> 耦合拆掉后它提前做完了。

### 语言包走"常数外置"那套

`constants/lang.zh-CN.json` / `lang.en.json`，和其他常数表同一套读取：
Rust 和前端都走 `constants::read`，**只读编译期内嵌的那份**（2026-09-29 起，
理由见 [timers.md](timers.md)「常数外置」）。措辞放在 JSON 里而不是散在代码里，
改一处、发版即到。

键是扁平的 `card.* / show.* / legend.* / tray.*`，取值就是字符串。
**缺键回退中文**，不回退键名——漏翻的地方显示中文至少还是句人话。

> **曾经：发布出去的键，值就不能再改了**（2026-09-29 起不再成立）。
> 那时语言包会播种到配置目录，`constants::seed` **只补缺键、不覆盖已有值**，
> 于是改仓库里的措辞到不了老用户眼前，只能换一个新键。开发机上那份
> 「打开常数表目录」就是这么一直没变成「打开数据目录」的。不再播种之后，改措辞直接改值即可。
>
> **语言无关的东西仍然别进语言包**——托盘菜单上那个 `Ctrl+Alt+F10`
> 就是在 Rust 里拼上去的，两种语言一个样，没必要各写一遍。

### 首次运行跟随系统语言

`GetUserDefaultLocaleName` 取到的名字以 `zh` 开头就用中文，否则英文
（`windows` crate 已经是依赖，只多开一个 `Win32_Globalization` 特性）。
仓库是公开的，默认给陌生人一个看不懂的界面没道理；而对中文用户，
这个判断的结果和写死中文完全一样。存进 `settings.json` 的 `lang` 字段后就以它为准。

### 切换要同时管两边

卡片在前端、托盘在 Rust，一次切换得两边都动：

- **卡片**：整个 `innerHTML` 重建。因此建卡片和绑事件必须是同一个函数——
  重建会换掉所有节点，包括 `.ed-bar` 那个拖拽把手，只重建不重绑就把卡片钉死了。
- **托盘**：`set_settings` 里重建整个菜单再 `set_menu`。不用 `set_text` 逐项改，
  那要把菜单项句柄存进全局状态，为两个词不值当。

### 「重置」不动语言

和开发区那两项同理，但理由更硬：**重置回中文会让看不懂中文的用户无法退出这个状态**
——他得先猜出哪一行是语言、再猜哪个选项是英文。可恢复性是重置的前提，
这一项恰好不满足。

## 明确不做

开机自启、白天黑夜、语音提示、任何形式的输入模拟。
