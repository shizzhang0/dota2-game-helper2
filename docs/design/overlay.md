# 程序外壳：窗口 · 交互 · 编辑态 · 托盘 · 设置

## 纯 Alt 查询

**平时屏幕上什么都没有。按住 Alt 显示完整面板，松开即隐。**

实现：Rust 侧轮询 `GetAsyncKeyState(VK_MENU)`（~40ms）。
**只被动读键盘状态，不注册热键、不拦截按键**——游戏内 Alt 的原有功能（Alt 点地图等）
完全不受影响，与"纯接收器"的定位一致。

#### 状态要能自愈，不能只靠边沿（2026-09-23 修）

原先的写法是「状态变了就 `let _ = app.emit("alt", down)`，同时把 `prev` 推进」。
两个问题叠在一起：**`emit` 的错误被丢掉了，而 `prev` 已经推进**，这一个边沿
就此永远补不回来；之后只要状态不再变化，就再也不会重发。

失步之后前端比实际**落后一个边沿**，用户看到的正是"Alt 变成了切换键"——
按住显示、松开却不消失，再按一次才消失（消失其实发生在第二次的**松开**上）。
用户 2026-09-23 报的就是这个现象，出现在「始终显示」开了又关之后，偶发。

两道防线：`prev` 只在 `emit` 成功后推进；再加一个**每秒无条件重发**，
不管什么原因造成的失步，最多一秒自愈。前端那边 `alt = d` 是幂等的，重发无副作用。

> **没能复现，所以这是按机制修的，不是按现象修的。** 上面那条链路是代码里实打实
> 存在的失步通道（丢掉的 `emit` 永远补不回来），修它无论如何都对；但它是不是
> 用户遇到的那一个，暂时没有证据。前端因此加了一条 debug 日志（`[alt] false -> true`），
> 再遇上把 `logLevel` 调成 `debug`，日志里能直接看出**是不是漏了一个边沿**。

`GetAsyncKeyState` 在反作弊环境下的风险评估为无（不注入、不 hook，只读键盘状态），
但**「始终显示」作为兜底配置项已经做了**（2026-09-21），见下。

### 始终显示（2026-09-21）

设置卡片「面板」页第一项，默认关。勾上之后**对局中一直显示，不用按 Alt**。
另有全局热键 `Ctrl+Alt+F11` 和托盘菜单里的勾选项，三处同一个值（2026-09-23 加）。

#### 为什么值得再占一个全局热键（2026-09-23）

当初定的是"不给它快捷键"，理由是用户说 `v` 这类裸字母太容易和游戏键冲突。
**那个理由只否掉了裸字母，没否掉快捷键本身**——项目里本来就有一个
`Ctrl+Alt+F10`（编辑态），带两个修饰键的 F 区组合不会撞 Dota。

真正的转折是：**想在对局中途拨这个开关，原本做不到。** 唯一的入口是编辑态，
而编辑态会抢焦点、取消鼠标穿透，那一刻根本没法继续玩。于是它事实上退化成了
"开局前设好就别动"，而它最有价值的用法恰恰是中途切换——对线打钱时开着，
团战时关掉免得挡视野。

键位 `Ctrl+Alt+F11` 由用户定，紧挨着编辑态的 F10，同一族好记。

> **三处入口共用一个 `toggle_always_show()`，不各写各的。** 它走 `set_settings`,
> 那条路上挂着托盘菜单重建（勾选状态要跟着变）和给前端的 `settings` 事件，
> 绕过去就会三处不同步。托盘那一项也**不读菜单自己的勾选状态**，
> 直接翻设置里的值——单一数据源。

> **残留风险：热键被别的软件占了会怎样。** 注册走
> `with_shortcuts([...]).expect(...)`，这个 `expect` 只在**字面量解析失败**时触发
> （写错了是开发期错误，该panic）。操作系统层面被占的情形没能构造出来验证，
> 真撞上的话最坏是这个热键失灵，托盘那条路还在。

> **名字定成「始终显示」/「Always show」**（2026-09-21）。先用过「常显」，
> 那是从这份文档的「常显模式」直接搬的词——**设计文档里的简称不等于界面用语**，
> 读起来像内部黑话。「始终显示」是各家设置里的标准说法，中英文也天然对得上。

存在的意义是兜底：万一 `GetAsyncKeyState` 在某些环境不工作，按 Alt 没反应，
这个开关能让程序仍然可用。那种情况下用户还够得到它——**托盘菜单还在，
而且标着 `Ctrl+Alt+F10`**。

三条刻意的边界：

- **不绕过"在不在对局中"。** 勾了也只在对局中显示，主菜单里照样消失。
  它的意思是"把按住 Alt 这个条件去掉"，**不是"永远杵在桌面上"**。
  编辑态则仍然绕过——摆位置这件事恰恰要在开游戏之前做。
- **不配快捷键。** 游戏内按键本来就挤，多给一个绑定只是多一个冲突源；
  而这个开关是低频的一次性设置，不是要反复按的东西。
  （开发页的 `v` 键保留，它连 `inMatch` 也绕过，那是开发时要的。）
- **勾上之后按 Alt 什么都不会发生**——面板已经显示着。曾考虑让 Alt 在这时
  **反过来**用（按住临时隐藏，方便看被挡住的东西），否决了：
  **Alt 的含义会随开关反转**，学习成本大于收益。真要临时看，把面板拖开或者关掉它。

> 「重置」会把它一并还原成关。它是外观行为、和四条滑块同类，
> 而"按住 Alt 才显示"是产品的默认形态；还原它不造成任何数据损失——
> 这和开发区那两项（日志级别、录制开关）被排除在重置之外的理由正好相反。

## 硬约束

- body 透明、锁定态整窗鼠标穿透
- **动画只用 `transform` / `opacity`**（圆环的 `stroke-dashoffset` 是明确许可的例外）
- 深色描边 / 半透明底 / 等宽数字，可读性优先——按住 Alt 就是为了读它
- vanilla JS + SVG，不引入任何框架或图表库
- 渲染由 `setInterval` 每 250ms 驱动，只改文本/类名/CSS 变量，DOM 只建一次
- **宽度写死**：净资产从 4 位涨到 5 位时若让宽度自适应，居中面板会整体横移，读数时抖动
- 块与块之间不画分隔线——**块本身就是分组边界**，四块各自独立摆位，中间隔着的是桌面

| 模块 | 职责 |
|---|---|
| `cachepool` | 合并 GSI 增量包，维护完整状态 |
| `match` | 按 `map.matchid` 切分对局；`game_state` 不在对局中时 `inMatch` 为假（断流由 `main` 判，见下） |
| `timers` | 常数表 + `clock_time` 纯函数算全部倒计时 |
| `events` | events 去重 + 塔防状态机 |

| `editor` | 编辑态设置卡片 |
| `main` | 装配 |

**前端是编译期嵌入二进制的**：改完 `ui/` 下的文件必须重新 `cargo build` 才会生效。

`build.rs` 会递归遍历 `ui/`，**逐个文件**发 `cargo:rerun-if-changed`，所以改完直接
`cargo build` 就行。不能图省事写成目录形式 `cargo:rerun-if-changed=../ui`——
实测那样写 cargo 认不出来，会把 crate 当成永远是脏的，**每次** build 都重编一遍
（一次 3 分半），比它要解决的问题更糟。

### 录制的生命周期（2026-09-16 重做）

**原先录制器活在 GSI 那条线程的局部变量里**，而处理开关变化的 `refresh()` 只在
`n % 100 == 0` 时被调用——也就是**只有 Dota 在推包时才会跑**。三个后果，都实测到了：

| 症状 | 实测证据 |
|---|---|
| 不开游戏时勾上「记录对局数据」，什么都不会发生 | — |
| **取消勾选也不生效**，录制状态卡在原地 | `settings.json` 里已是 `false`，日志里却没有「录制已停止」 |
| 刚开录就关掉游戏 → 留下一个 **0 字节**的空壳 | `raw_1789563893.jsonl.gz`，0 字节，创建后再没被写过 |

第三条最糟：gzip 把数据缓存在内存里，`FLUSH_EVERY = 50` 包才落盘一次，而
`finish()` **只在"设置从开变关"这一条路径上**调用。托盘退出、Dota 关掉、
GSI 断流全都不会收尾。不足 50 包的那一局于是整个消失，**而且毫无提示**。
"我明明开了录制，打完却什么都没有"是最坏的失败形态：静默，且数据不可再生。

改法是把录制器挪到一个全局的 `Mutex` 后面，于是三条路都能够到它：

1. **`set_settings` 直接调 `refresh()`** —— 开关立刻生效，不等推包
2. **`RunEvent::Exit` 收尾** —— 托盘退出、关窗口都会 `finish()`
3. **断流看门狗** —— 一条 2 秒一跳的线程，超过 `IDLE_SECS` 没收到包就收尾封口

还有一条顺带的改动：**文件改成第一包数据到来时才建**（懒建）。这样"勾上开关但没开
游戏"不再产生任何文件，文件名里的时间戳也从"你什么时候拨的开关"变成了
"数据什么时候开始"。0 字节空壳这个形态从此不存在。

> **断流 ≠ 对局边界。** Dota 在主菜单里照样推包，所以看门狗只有在**游戏整个关掉**
> 时才会触发。它解决的是"收尾"，不是"分文件"——分文件靠 `matchid`，见下。

#### 按对局分文件（2026-09-20）

原先一个文件是按**开关时机**切的：只要 Dota 开着、开关也开着，一局打完接着下一局
全写进同一个文件。回放时得自己找那一局从哪开始。

现在**换局就换文件**：每包读 `map.matchid`，和当前文件记着的那个不一样就收尾，
下一包懒建新文件。收尾时把 matchid 补进文件名：

```
raw_1789832417.jsonl.gz  ->  raw_1789832417_m9006648438.jsonl.gz
```

**时间戳保留在前面**，因为同一局可能被录两次（比如回放看两遍），只有 matchid
会撞名。`records_stat` / `clear_records` 认的是 `raw_` 前缀加 `.jsonl.gz` 后缀，
新名字照样在内。

> **改名放在 `finish()` 之后**，这时文件已经关上了，是一次普通的重命名。
> 不去改正在写的那个文件的名字——Windows 上对打开着的文件改名能不能成，
> 取决于句柄的共享位，不值得赌。

几条刻意的边界：

- **`map` 段可能整包缺席**（GSI 推的是增量，实测每个录制文件里都有两包没有 `map`）。
  这种包**不动**当前的 matchid，否则会被切得稀碎。
- **只在"两个都是真 matchid 且不相等"时才切**。主菜单里的 `matchid` 是 `"0"`
  或者干脆没有，这种一律当"不知道"，跟着当前文件走——宁可让菜单数据粘在某一局
  的文件尾巴上，也不要凭空造出一堆几十秒的碎文件。
- **没有 matchid 的包不建文件**（2026-09-20 补）。Dota 在主菜单里推的是
  `{"provider":{…},"player":{},"events":[]}` 这样的心跳包，一包 114 字节。
  懒建是"第一包数据到来时才建"，而**心跳包也算数据**——于是断流封口之后，
  只要 Dota 还开着就会立刻建出一个只有心跳包的空壳：

  ```
  20:34:25 收尾（断流）raw_1789906167_m9008012005.jsonl.gz
  20:34:34 开始录制   raw_1789907674.jsonl.gz     ← 114 字节，只有一个心跳包
  20:34:39 收尾（关闭开关）
  ```

  开关叫「记录对局数据」，**没有对局就不该有文件**。注意这只挡"建文件"这一步：
  文件一旦开着，后面缺 `map` 的增量包照样写进去。
- 英雄选择、策略时间、赛后结算**都带着 matchid**，所以它们自然落在这一局的文件里，
  不需要特殊处理。赛后那几十包尤其要留着，最终净资产就在里面。

#### 第四条路：文件在录制途中消失（2026-09-19）

同一个失败形态又出现了一次，这次的原因在程序之外：**用户在资源管理器里删掉了
正在录的那个文件**，而程序毫不知情地继续写了 26 分钟，收尾时数据全没。

日志复原的时间线：

```
22:33:26 [record] 开始录制 ...\records\raw_1789828406.jsonl.gz
22:33:36  ← 目录结构变动（用户删掉几个不完整的录制，把刚建出来的这个也带走了）
22:59:32 [record] 收尾（关闭开关）：...\records\raw_1789828406.jsonl.gz
```

能这样是因为 **Rust 的 `File::create` 在 Windows 上默认带 `FILE_SHARE_DELETE`**
（`std::os::windows::fs::OpenOptionsExt::share_mode` 的默认值是
`FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`）。实测：持有写句柄时
`remove_file` 返回 `Ok`，之后 `write_all` 和 `flush` **也全部返回 `Ok`**，
而路径已经不存在——文件进入"删除挂起"，写入流向一个没有目录项的句柄。
**没有任何一层会报错**，这正是它静默的原因。

> 不去改 `share_mode` 挡住删除：那只会把"删不掉"的困惑转嫁给用户
> （资源管理器会弹"文件正在使用"，而用户并不知道哪个是正在录的）。
> **让删除成功、但别让它静默**才是对的方向。

所以给看门狗加了第二件事：每跳**顺便确认 `CURRENT` 指的文件还在**。不在就

1. 打一条 `ERROR` 日志，把丢掉的那段明确说出来；
2. 收尾当前这个幽灵句柄，把 `sink` 清掉。

下一包到来时 `write()` 会懒建一个新文件，**这一局剩下的部分照样录得到**。
已经写进幽灵句柄的那段找不回来——它连目录项都没有了——但损失从"整局"缩到
"最多 2 秒内发现之前的那一段"。

### 数据源的第三个分支：静态回放（2026-09-17）

`connectSource()` 原本只有两条路：Tauri 事件、开发用的 SSE。加第三条
**从静态文件回放**，是为了 GitHub Pages 上那个 live demo——Pages 没有服务器，
SSE 走不通。

```
Tauri          window.__TAURI__.event.listen("gsi")
SSE            EventSource("stream?speed=…")      开发用的回放服务器
静态回放       fetch(demo.jsonl) 逐行按节奏喂       Pages / 截图流水线
```

怎么选：`?demo=<url>` 查询参数，或页面在加载 `main.js` **之前**设 `window.HELPER2_DEMO`。
两个都不给就还是走 SSE，开发页一个字都不用改。

> **demo 用的是同一份 `ui/js`，不是另抄一份。** 站点目录里只放页面和数据，
> `ui/` 与 `constants/` 由部署流水线原样带过去。抄一份代码过去迟早会和真程序脱节，
> 而这个 demo 全部的意义就在于它是真的。

#### 站点：一个页面 + 一个 iframe + 一条部署流水线

`site/index.html` 是落地页，`site/demo.html` 是**框里跑的那份真覆盖层**，
`tools/build_site.py` 把它们和 `ui/` `constants/` 组装成 `dist/`，
`.github/workflows/pages.yml` 调同一个脚本发出去。

**组装逻辑放脚本不放 YAML**：写进 workflow 就没法本地验了。
`python tools/build_site.py --serve` 起出来的，和线上发的是同一份。

四个不显然的点：

1. **demo 必须放 `<iframe>` 里。** 覆盖层的四个块是 `position: fixed`——
   相对**视口**而不是容器。直接嵌进首页，它们会飞到整个页面上去。
2. **iframe 固定 900×400，再整体 `scale()` 去适配容器**，不让它跟着容器变宽窄。
   块的摆位会被 `clamp()` 钳进视口，窄一点就会被挤到一起甚至互相压住——
   固定尺寸加缩放，任何屏幕上的构图都一样。
3. **显隐走产品自己那条路**：合成 Alt 的 keydown/keyup 打进 iframe，
   和真人按 Alt 走同一个 `onAltChange`。不另写一套显示逻辑——那样 demo 就不是真程序了。
   自动循环显示 5 秒、隐藏 1.6 秒；访客一按 Alt 就停掉循环把控制权交出去。
   **隐藏那一段是有意的**，它恰恰是这个东西最重要的特性。
4. **手机上没有 Alt 键。** 触屏设备（`(hover: hover) and (pointer: fine)` 为假）
   常显，并把"按住 Alt 接管"那句提示整个删掉——做不到的事不要写在界面上。
5. **提示文字必须跟画面对得上。** `shown` 的初值一度写成 `true`，而页面刚加载时
   demo 还没开始放（要等 iframe load 再过 600ms）——那段时间提示说着"这就是那个
   覆盖层"，框里却是空的。初值改成 `false`，并把"隐藏态"的文案写成
   **在"还没按过"和"松开之后"两种情况下都成立**的说法。

#### 站点的中英切换

**两种语言都写在 HTML 里，靠 CSS 显示其中一份**：

```css
html[data-lang="en"] [lang="zh"] { display: none; }
html[data-lang="zh"] [lang="en"] { display: none; }
```

不用 JS 拼模板——文案里有 `<kbd>`、`<code>`、`<a>`，塞进字符串字典就得靠
`innerHTML` 拼回去，既难读又容易出错。代价只是 DOM 里多一份文本，整页几 KB。

> **和卡片那套 i18n 不共用，是对的。** 卡片走的是 `T[lang][key]` 加常数外置的
> 语言包，因为那是**运行在用户机器上、要能不重新编译就改翻译**的东西。
> 站点是静态页，改文案本来就要重新部署，多引一套机制只有成本。
>
> 只有一处是 JS 管的：demo 那句提示。它的文本随播放状态变，不是静态内容。

默认语言：**上次选的 > 浏览器语言 > 英文**。英文兜底和两份 README 拿英文当默认
入口是同一个理由——公开仓库的陌生访客里英文读者更多。选择记在 `localStorage`，
无痕模式下读写都包了 try/catch。

> 站点上**不再链接 README 的中英两份**了。页面自己能切，再放两个跳到 GitHub 的
> 语言链接只会让人以为"点了会换语言"，结果跳走了。

> **`ui/` 是拷进去的，不是另写一份。** demo 全部的意义就在于跑的是真程序。
> 部署前还有一道 grep 闸门再查一遍 demo 数据里有没有身份字段——
> 白名单理论上已经挡住了，但这是发到公网前的最后一道。

> **Pages 必须先由人开一次，workflow 自己开不了。** 首次部署就栽在这上面：
> `configure-pages` 加 `enablement: true` 会报
> `Create Pages site failed. Error: Resource not accessible by integration`。
> 默认的 `GITHUB_TOKEN` 能**读**仓库的 Pages 配置，但没有**创建**它的权限，
> 而且这不是 `permissions:` 里加一条能解决的。一次性命令：
>
> ```bash
> gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow
> ```

#### 截图是生成的，不是摆拍的

[`tools/make_shots.py`](../../tools/make_shots.py) 一条命令重出全部九张
（整体 + 四个块特写 + 卡片四页）。backlog 原先把「截图是这件事的主要成本」列为
README 迟迟做不起来的原因——工具化之后它不再是成本，改完界面重跑一次就行。

跑的是**真程序**：同一份 `ui/js`、同一条渲染管线、真实录制的数据。

三个踩过的坑，都记在脚本里：

1. **不要"跑到某一刻再冻结"。** headless 的虚拟时间和真实网络对不齐，实测截到空白。
   改成**每张图配一段截止到那一刻的数据切片**，极高倍速播完（`loop=0`），
   页面自然停在最后一包上——没有时序，也就没有不确定性。
2. **摆位要在 `main.js` 之前写进 `localStorage`。** 块的位置每帧由 `render()`
   重新套用，事后改 inline style 会被立刻覆盖。
3. **`--window-size` 给的是窗口不是视口**，实测差 30×95。`clamp()` 按视口钳摆位，
   视口矮了就把下面那块往上顶——第一版里净资产块正好盖住地图左上角，
   而敌方眼就在那儿。脚本**实测一次偏移**（不写死魔数），截完再把多出的边裁掉。

> **编辑态那张历史上从没截成功过**（卡片比可用窗口高，`PrintWindow` 只渲染屏上部分）。
> 这条路同时绕开了两头：headless 不走 `PrintWindow`，而页签把卡片压到了 316px。

> **地图那两张必须挑有敌方眼的时刻。** 自视角下敌方眼只在真视罩到时才看得见，
> 那份录制里只有 53 秒有。这不是取巧——它恰好说明了产品的真实样子。

> **卡片那四张出中英两套**，`card-*.png` 给 `README.md`、`card-*-zh.png` 给
> `README.zh-CN.md`。卡片是界面上**唯一有文字的地方**（覆盖层本身一个字都没有），
> 所以也只有它需要重复；另外五张与语言无关。
>
> 英文那套用不带后缀的名字，因为 `README.md` 是 GitHub 的默认入口。
> 原先两份 README 共用同一套中文图，等于让英文读者看一张看不懂的截图。
>
> **程序自己的默认语言不用改**：`lang.rs` 的 `system_default()` 本来就跟随系统——
> 非中文系统给英文，中文系统给中文。改成永远英文反而会让中文用户拿到看不懂的界面。

#### 断流要退回待机（2026-09-22 加）

Dota 崩了、被关掉、或者网络断了之后**不会有任何通知**，`main.js` 里的 `last`
会一直留着最后一包。按住 Alt 仍然显示一份**冻结**的旧面板：倒计时不动、
净资产不动，而它看起来和正常面板一模一样——**比不显示更坏**。

POST_GAME 那一半原本就是对的：它不在 `match.js` 的 `IN_MATCH` 集合里，
`inMatch` 自然为假，面板会隐藏。缺的只有断流，而 `match.update()` 只在**收到包时**
才跑，检测不了"没有包"。所以判断放在 250ms 那圈渲染循环里。

**阈值分两档**，因为 GSI 配置里 `heartbeat` 是 **30 秒**（见 `gsicfg.rs`）：

| 情况 | 阈值 | 理由 |
|---|---|---|
| 没暂停 | **5 秒** | `clock_time` 每秒都在变，`throttle 0.1` 下包是连着来的 |
| 暂停中 | **40 秒** | 暂停时什么都不变，GSI 只剩心跳，30 秒才推一次 |

用单一的 5 秒会把正常的暂停误判成断流、把面板关掉。

> **只是不渲染，不重置各个 tracker。** 数据回来时若还是同一局，接着算就是了；
> 换局了 `newMatch` 自然会触发重置。

实测：`demo.html?speed=60&loop=0` 让回放 10 秒跑完然后停住，净资产在最后一包
之后 **5 秒**从 5,346 变成 0——渲染循环换到了 `IDLE`，而 `IDLE.info.inMatch`
为假正是 `visible` 的必要条件。

#### demo 数据：白名单裁剪，并用对账验证裁得对

生成脚本是 [`tools/make_demo.py`](../../tools/make_demo.py)。

**裁剪即脱敏**：只保留 `ui/js` 真正读的字段，其余一律丢。比"逐个删掉
steamid / accountid / name"更安全——后者要求我们记全所有身份字段，而且 Dota
以后在 GSI 里新增一个，它会悄悄混进 demo；白名单则是新字段默认不进。

顺带解决体积。实测同一段（clock 60~460，1489 包）：

| | 大小 |
|---|---|
| 原始 | 42.4 MB |
| 裁剪后 | 5.09 MB（12.0%） |
| **gzip 后（Pages 实际传输）** | **52 KB** |

> **不能抽稀。** GSI 推的是**增量包**，隔一包取一包会把状态丢掉
> （`cachepool.js` 的整套语义就建立在"每一包都并进去"上）。
> 体积只能靠窗口长度调，不能靠降采样。

丢掉的大头是 `minimap` 里几百个小兵，而地图只画眼和塔；其次是每件装备的冷却、
可否施放、等级等**没有任何代码读**的字段。整段丢掉的还有 `provider` /
`buildings` / `abilities` / `wearables`——它们在 `cachepool.js` 的 `SECTIONS` 里，
但全项目零消费者。

> **28 KB 意味着体积这件事到此为止。** 别再去想 delta 编码或二进制格式，
> 那只会让 demo 数据不再是"真实的包"。

**裁得对不对靠对账，不靠人眼核白名单**：把裁剪前后两份分别喂进真实管线，
逐包比较渲染层实际拿到的十二项（clock / inMatch / mode / myTeam / paused /
spectating / 倒计时 / 塔防 / 买活 / 眼位 / 被推掉的塔 / 净资产）。
1489 包 × 12 项**完全一致**才算过。

> 写的，之后 networth.js 三次改动都没跟：少了 `player.deaths`（TP 自购/白送的判据）、

#### 常数的路径去掉了前导斜杠

浏览器分支原先五处写的是 `fetch("/constants/…")`，**绝对路径**——部署在
`https://<user>.github.io/dota2-game-helper2/` 这种子路径下会 404。
backlog 里把这条标成"唯一一个一定会咬人的地方"。

实际解法比预想的小：**去掉那个前导斜杠**就行。相对路径按页面所在目录解析，
Pages 上 `/dota2-game-helper2/index.html` → `/dota2-game-helper2/constants/…`，
开发服务器上 `/dev.html` → `/constants/…`，两边都对，不需要任何可配的 base。

五处的 Tauri 那一半各不相同（三处走 `get_constants`，价格表走 `get_item_prices`，
版本走 `get_versions`），所以**只把浏览器那一半收进 `fetchConstant()`**，
Tauri 那半留在原地。硬要把两半都抽出来，就得在一个函数里塞三种命令的分支，
比现在难读。

> **前提是页面在部署根目录。** 页面要是挪进子目录（比如未来加一页使用文档
> 放在 `docs/`），相对路径会跟着一起挪。那时再给它一个 `<base>` 标签，
> 而不是把斜杠加回去。

### 智能显隐

`map.game_state` 不在 PRE_GAME / GAME_IN_PROGRESS 时整窗隐藏。

**观战 / 回放视角也整窗隐藏**（2026-09-08 定，见 [../backlog.md](../backlog.md) 的"明确不做"）。

判定不靠白名单，靠**结构**：自己打的时候 `player` 是扁平的一份人（`player.team_name`
是 `"radiant"` / `"dire"` 这样的字符串）；观战和看回放时 GSI 推的是**全员结构**——
`player` 变成 `{ team2: { player0: {...}, player1: {...} }, team3: {...} }`，
`hero` 同理。于是"`player` 在、但没有 `team_name`、却有 `team\d` 这样的键"就是观战。

```js
const spectating = !!p && !p.team_name && Object.keys(p).some(k => /^team\d+$/.test(k));
```

**为什么必须显式判掉，而不是"反正算不出来就空着"**：净资产那条链路读的是
`player.gold` / `player.items`，在全员结构下这些键根本不存在，取到 `undefined` 之后
一路算成 0——面板会**照常显示一个看起来正常的 0**，而不是明显的坏值。
显示一个错数字比什么都不显示更糟。

**不做部分降级**。技术上是能的：符、莲花、智慧、堆野只依赖 `map.clock_time`，
眼位地图只依赖 `minimap`，这两样在观战下反而更全；坏掉的只有净资产（需要
`player.gold`）和敌方买活（需要 `myTeam`）。不做的理由是产品定位——
观战和回放本来就有一堆现成工具，这个覆盖层要解决的是**你正在打的那一局**里
游戏不告诉你的事。半开的面板还会让人以为是坏了。

## 四个可独立摆位的块

面板原本是一整条：`324`（五个符）+ `170`（塔防+买活）+ `116`（净资产）+ `116`（眼位）
+ 分隔与间距 `63` + 内边距 `24` + 边框 `2` = **815px**，1.5× 缩放下 **1223px**，
1920 屏上占 64%，而且正横跨在 Dota 顶部计分板上。高度 **126px** 完全由眼位小地图撑起——
另外八格上下各空出 20px。

拆成四块，各自一份坐标：

| id | 内容 | 1× 尺寸 | 1.5× 尺寸 |
|---|---|---|---|
| `timers` | 中路符 · 赏金 · 莲花 · 智慧 · 堆野 | 350×85 | 525×128 |
| `enemy` | 敌塔防 · 敌买活 | 196×85 | 294×128 |
| `econ` | 净资产 · GPM · XPM | 142×70 | 213×105 |
| `wardmap` | 眼位小地图 | 214×213 | 321×320 |

尺寸是实测的 `offsetWidth` / `offsetHeight`（含 1px 边框）。
**`econ` 比另外两个矮**——它那格没有圆环，CSS 里写死了 `height: 52px`。
**`wardmap` 的尺寸跟着「眼位地图大小」设置走**，表里是默认 180px 时的值。

`#panel` 从"面板本体"降级成一个**无样式的容器**，四个 `.block` 由 `render.js` 建在它里面。
块是 `position: fixed`，父容器有没有尺寸都不影响；`--panel-scale` / `--panel-opacity`
设在容器上，靠 CSS 变量的继承传给四块，仍然只写一次。

**`transform-origin` 必须是 `top left`**：缩放时块从自己的左上角长大，存的坐标才不会失真。

**一个块里的格子被显示项开关全部关掉时，整块连底板一起消失**，不留空壳。

### 默认摆位

全部按视口比例算，不写死像素。

| 块 | x | y | 1920×1080 / 1.5× 实测 |
|---|---|---|---|
| `timers` | 水平居中 | `屏高 × 7.5%` | (698, 81) |
| `enemy` | 水平居中 | `timers` 下方 10px | (813, 217) |
| `econ` | `16` | 与 `timers` 同一水平线 | (16, 81) |
| `wardmap` | `16` | `econ` 下方 10px | (16, 196) |

`y = 屏高 × 7.5%` 是为了让开计分板（1080 屏上 81px）；拆块之前的 14px 是压在它上面的。
顶部这一摞到 y=345，左列到 y=385，都在视线焦点（y≈540）上方。

### layout.json

```json
{
  "timers":  { "x": 698, "y": 81 },
  "enemy":   { "x": 813, "y": 217 },
  "econ":    { "x": 16,  "y": 81 },
  "wardmap": { "x": 16,  "y": 196 }

```

Rust 侧不参与：`save_layout` / `load_layout` 把它当不透明字符串收发，不解析结构。

**迁移**：老文件里的顶层 `{x, y}` 当作 `timers` 的位置沿用，其余三块取默认值。

### 钳位与重置

四块独立可拖之后，把某块拖到 `x = -400` 就**彻底找不回来了**——它平时隐藏，
编辑态下也在屏幕外，没有任何入口能救。所以：

- **读盘时钳进视口**，顺带解决换分辨率、拔掉副屏
- **拖拽落点也钳一次**，否则本次会话里那块就丢了，要等下次启动才回得来
- 卡片里有**「重置」**按钮作为显式复位入口（见「设置」第 6 条）

拆块之前单块面板也有同样的风险，只是概率低四倍。

## 图标：覆盖层上没有文字

**覆盖层上不出现任何需要翻译的词。** 剩下的只有数字（倒计时、净资产）和
GPM / XPM 这两个通用缩写。

收益不是"省掉十几条翻译"，而是**那条写死的宽度约束自己消失了**——
原先"净资产"换成 `Net Worth` 会撑破格子，所以多语言最难的一块是"让宽度跟着语言走"。
面板上没有词，这个问题就不存在。多语言因此收敛到**编辑态卡片 + 托盘菜单**两处。

**不用 Valve 的素材。** 仓库公开且是 MIT，backlog 里为托盘图标已经记过这条。
做法是原创描边式 SVG，沿用游戏的视觉语汇（形状语言 + 配色），但不是它的文件——
这是现有决定的延续，`--k-*` 那组符色注释早就写着"取自游戏中各事件自身的颜色"。

### 图标集（`ui/js/icons.js`）

全部 24×24 viewBox、`stroke="currentColor"`，颜色由所在格子的 `--accent` 决定。

| 项 | 图标 |
|---|---|
| 中路符 | **随阶段变**：两枚叠压的硬币 / 水滴 / 双箭头 |
| 赏金符 | 钱袋 |
| 莲花 · 智慧 · 堆野 | 莲花 / 摊开的书 / 三层堆叠 |
| 敌方塔防 · 敌方买活 · 净资产 | 盾 / 回转箭头 / 硬币 |
| 眼位地图 | **面板上不放标签**；眼 + 塔只用在卡片那一行 |
| 卡片四个页签 | 九宫格 / 滑块 / 条目 / 扳手 |

页签那四个只用在设置卡片上，覆盖层不出现。它们画的是**"那一页长什么样"**
而不是抽象概念——九宫格 = 一堆开关，滑块 = 一堆滑块，条目 = 一张对照表，
扳手 = 一堆工具。因为页签上没有文字，每个都得自解释；选中那个的名字就显示在
页签条下面，所以认错也只错一次。

> **图例那个页签刻意不复用 `eye`。** 页签条上摆一只眼，读起来会像"这一页讲眼位"，
> 而它讲的是"这些符号各是什么意思"。

### 三个非显然的取舍

1. **赏金符用钱袋而不是硬币。** 中路符 0:00 那一阶段就是赏金，两格会撞图标，
   而原本靠"中·"这个前缀区分的文字已经没了。只有赏金阶段会撞
   （水滴和双箭头在别处没有对应格子），所以只改赏金那一格。

2. **堆野用堆叠层而不是营地框。** 语义上营地框更准——这格数的是"野怪刷新"这个事件，
   而 Dota Plus 自己的堆野提示就是按住 Alt 时画在营地上的刷新框。
   但虚线框在 14px 下糊成一团，**这里让位给可读性**。
   将来若做"营地画到眼位小地图上"，那时该换回营地框——它和地图是同一个隐喻。

3. **眼位那一格不放标签。** 其余格子是"圆环 + 数字"，没标签认不出；
   但一张画着塔和彩色圆点的 Dota 地图是自明的。而且灰色的塔图标会**和地图自己的配色撞**
   ——地图上灰塔的含义是"已被推掉"。顺带矮了约 15px。

### 图标和数字的位置是对调的

**有圆环的格子**（五个倒计时 + 塔防）：图标压在环中央，倒计时移到环下面。
一开始是反过来的——数字在环里、图标在环下当标签。上手看过之后推翻：
环是那一格的"容器"，装身份（图标）比装数字更自然；而数字读起来像图注。

**净资产**：图标和金额同一行、放左边。

**买活**：图标在下方当标签，**不能照搬净资产**。分界不是"有没有圆环"，
而是**内容是单值还是一行数据**：净资产只有一个值，币 + 数字读起来就是"金钱：7319"；
买活是五个值，图标摆进那一行就成了"第六个东西"，混进数据里了。
放到下方之后，它和塔防的倒计时正好落在同一水平线上，两格反而对齐了。

塔防与买活之间的间距要单独放大到 14px：它们是两种不同形态的格子，
块里通用的 6px 太挤，会读成一组。

**买活的圆点外面套一个圆角框。** 塔防有个很重的圆环当容器，圆点却什么都没有，
两边一比就"飘"——框是圆环在这种形态下的对应物。

**框撑满格子高度**，把塔防"环 + 倒计时"的结构镜像一遍：框顶对齐圆环顶、
框底对齐倒计时底；圆点吃掉箭头以外的全部高度并居中，中心因此正好落在圆环中心那条线上。
实测四处偏差全为 0。

> 中间走过一次弯路：为了"框别显得空"把它收紧、再在格子里垂直居中——
> 结果它和圆环、倒计时两边都不挨着，比没框还乱。
> **框该对齐的不是自己的内容，是隔壁那一格。**

框宽 118px，格子因此从 104 放宽到 122，否则会溢出。

框的颜色取 `--k-chance`（"敌方缺失 = 机会"）的 **32%**，和框里的图标同色系。
不用满强度：**框是容器不是数据**，太亮会和旁边塔防那个红色进度环抢，
也会让人误以为它自己在表达某种状态。

**塔防 ready 时把盾填实**（`fill-opacity: .3`）。数字位这时是空的（数字位永远只放数字），
光靠"环画满"不够显眼。曾考虑写 `READY`，但那是英文单词、不像 GPM/XPM 那样是
Dota 各语言版本通用的缩写，等于在刚清空的面板上重新放回一个要翻译的词。

这一改还顺手解决了描边过细的风险：环内径 48px，图标能放到 **24px**，
0.8× 时描边从 **0.79px 变成 1.36px**。原先 14px 时那条是最大的可读性隐患。

两个不能省的细节：

- **`.num` 要 `min-height`**：塔防 ready 态数字为空，不留高度那一格会比旁边矮、整行跳。
- **`.nw` 要 `min-width`**：币在左边之后，净资产从 4 位涨到 5 位会把币往左推。
  这和"格子宽度写死防抖动"是同一个理由，只是尺度小了一层。

格子高度因此从 69px 变成 75px。

### 尺寸与两个坑

**环内 24px，行内 16px。** 12px 下书和莲花的细节会糊；
最初取的 14px 标签位在 0.8× 下描边只剩 0.79px，是挪进环里之后才不成问题的。

1. **`.cell svg { width: 52px }` 会把图标撑成 52px。** 那条是给圆环用的，特异度 (0,1,1)。
   必须写成 `.cell .lab svg.ico`（0,2,1）——**和眼位地图那个 bug 是同一个坑**。
2. **`set()` 用不了。** 它比较值后写 `textContent`；图标要整段替换 SVG，
   得走另一个 `setHtml()`，同样只在变化时才动 DOM（渲染 250ms 一轮，别每帧重建 SVG）。

### 放大不糊，风险在小端

实测缩放 2× 时 SVG 布局尺寸仍是 52、渲染尺寸变成 104——浏览器按新尺寸重新光栅化，
不是拉伸位图，边缘保持矢量清晰。

风险在**缩小**：描边 `1.7` 是 24 viewBox 里的值，图标越小描边越细。
标签位那版 14px 在 0.8× 时只剩 **0.79px**，会被抗锯齿摊成浅灰；
挪进环里放大到 24px 之后是 **1.36px**，实测在最暗和最亮的背景上都清楚。
另加了 `drop-shadow(0 0 2px #000)` 作衬底。

### 程序图标

锈红粗边方块 + **挖空**的开口环，背景透明，见
[`tools/make_icons.py`](../../tools/make_icons.py)（形状即代码，改常量重新生成整套）。

结论都是排开十几版、只按 **16px** 挑出来的——托盘上就这么大，别的尺寸都是参考：

1. **实心色块挖空，不要描边。** 描边到 16px 只剩一两个像素宽，一糊就没了；
   挖空的图形有整块颜色撑对比。第一轮全用描边的九版，没有一个比这一版清楚。
   Dota 自己那个标能缩到很小还立得住，也是这个原因。
2. **去掉底板就得把红提亮。** 中途试过加一层深蓝圆角底板（取自 Dota 横版 logo 的底色），
   它确实能解决浅色任务栏的对比度。去掉之后，原来的 `#A6392A` 贴在**深色**任务栏上
   明显发闷，于是提两档明度到 `#C24A34`——同一个色相，只动明度，深浅两种任务栏都够。
3. **缺口 60°，正对 45°。** 中轴线因此就是左上—右下那根对角线，
   和那个标里那道白色斜刃同向。中心必须落在 45° 整——先试过 67.5°，
   只偏 22.5° 就看得出轴是歪的，缺口像"滑到了下面"而不是"顺着对角切开"。
   宽度再窄，16px 下那道缝会被抗锯齿抹平，环就退化成一个实心甜甜圈。
4. **毛边只留少数几个大缺口**，步长 4（画布 24）、幅度 ±0.85。再细的锯齿 16px 下
   一定被抹平，白费。而且顶点是**一次性生成后定死写进代码**的：
   每次构建重新随机，图标就会悄悄变样，而图标必须是稳定的身份。

> 原来那版是金色开口细环。它在 16px 下**读作"程序卡住了"**——一个加载转圈，
> 这才是它真正的问题，不是"看不出和 Dota 有关"。
>
> **借的是画法，不是身份。** 实心方块 + 挖空图形 + 粗糙手绘边是通用作图技术，
> 也正是 16px 下唯一有效的那条路；那个"D"和它的整体识别特征不碰。

> **ICO 里 256 以下必须用 DIB，不能用 PNG。** PNG 压缩的图标条目微软只保证
> 256×256 那一档；更小的尺寸，资源管理器在有些路径上认不出来，于是回退到别的
> 条目、或者干脆继续用缓存里的旧图——表现就是"exe 图标怎么都换不掉"，
> 排查时极易误判成 Windows 图标缓存。`make_icons.py` 因此 <256 出 DIB
> （BITMAPINFOHEADER + 自下而上的 BGRA + AND 掩码）、256 出 PNG。
> AND 掩码对 32 位图没实际作用（透明看 alpha），但**必须在**，
> 且每行按 4 字节对齐，否则整张图会错位。

> **换了图标却只变了一半：`build.rs` 必须监视 `icons/`。**
> **一旦发出任何 `cargo:rerun-if-changed`，cargo 就不再监视整个包目录**，
> 只认声明过的那几个；而 tauri-build 自己只声明 `tauri.conf.json` 和 `capabilities`，
> `icons/` 谁都没管。结果是换图标后**托盘变了、exe 在资源管理器里的图标没变**——
> 前者走 `generate_context!` 宏，跟着 crate 重编一起展开；后者是 `build.rs` 里
> tauri-winres 编出来的 `resource.lib`，`build.rs` 不跑就永远是旧的。
> 看起来像"Windows 图标缓存没刷新"，其实是根本没重新生成。
> 查法：解 PE 的资源表，把 RT_ICON 的字节和 `icons/icon.ico` 逐条比。

本机没有 Pillow / cairosvg / ImageMagick，所以 `make_icons.py` 自带一个极小的
光栅化器：形状全可解析判定（多边形、圆角矩形、带缺口的圆环），4×4 超采样，
PNG 用 zlib 手写。**边缘的颜色按覆盖到的子样本平均、透明度按覆盖率，两者分开算**——
不分开算，边缘会被背景色拉暗，出现一圈脏边。

### 一个实测教训

币堆最初画成两个叠起来的**扁椭圆**，13px 下退化成**两条横杠**，完全看不出是硬币——
正好败在图标化的全部目的上（不靠文字也能理解）。改成两枚**相互叠压的圆**才立得住。
小尺寸下椭圆和细线是最先垮掉的两种形状。

### 卡片同时是图例

九个显示项开关每行前面放对应图标（`showIcon()`），**和面板用的是同一份 `icons.js`**，
形状永远不会脱节——和眼位图例复用地图 class 是同一个思路。
文字集中在卡片，而卡片正好是唯一需要翻译的地方。

**每行只放一个图标。** 眼位那行曾经放过"眼 + 塔"（想表达那块地图画了哪两类东西），
但九行里只有它是两个，反而不齐。

> **那个塔图标已从 `icons.js` 删掉**（2026-09-16）。这里原先写着"仍留着供眼位图例
> 那一节使用"，而那是**假的**：图例画的是 `<rect class="wm-tower">`——直接复用地图
> 自己的 class，颜色才不会和地图脱节，这正是图例那一节定下的做法。

## 托盘

程序原本**没有任何正常退出的途径**：窗口无边框、`skipTaskbar` 为真、没有托盘，
只能去任务管理器杀进程。托盘补的是这个真窟窿，不只是锦上添花。

```
右键菜单                              左键单击图标 → 同样 toggle 编辑态
├ 编辑面板 (Ctrl+Alt+F10)              （与热键共用同一份编辑态，别各存一份）
├ ──────
└ 退出
```

**菜单上标出热键**（2026-09-20）。在此之前 `Ctrl+Alt+F10` **只在 README 里出现过**，
产品本身一个字没提——而它恰恰是「三条退出路径」里的最后一条兜底，
**被编辑态困住时最需要它的人，正是最没机会去翻 README 的人**。
托盘是进编辑态的主路径，标在这里学一次就记住。

> 热键那串拼在 Rust 里，不进语言包。两个原因：`Ctrl+Alt+F10` 两种语言一个样；
> 而且语言包**只补缺键、不覆盖已有值**，改包里的 `tray.edit` 到不了老用户手上。

### 左键单击一直是坏的（2026-09-20 修）

原先的事件匹配是 `TrayIconEvent::Click { button: Left, .. }`，**没有过滤
`button_state`**。而 Windows 上按下和抬起各发一条 `Click`：

| 操作 | 收到的消息 | 原先 toggle 次数 | 表现 |
|---|---|---|---|
| 单击 | `DOWN`, `UP` | 2 | 开了又关，**看起来没反应** |
| 双击 | `DOWN`, `UP`, `DBLCLK`, `UP` | 3（`DoubleClick` 被忽略） | 停在"开" |

所以上面那句"左键单击 → toggle 编辑态"**一直是不成立的**：真正能用的是双击，
而那只是凑出来的奇数次。这个 bug 藏了很久，因为它不报错、也不崩——
单击没反应的人会默认"大概本来就没这个功能"，改用右键菜单。

改成**只认 `Up`**之后单击恰好一次。双击还会多出一个 `Up`（序列里 `DBLCLK`
之后那个），用一个 `SWALLOW_UP` 标志吞掉——**让双击和单击表现一致**，
而不是开了立刻又关。

> 顺带加了三条 `Debug` 级日志（抬起 / 双击 / 吞掉），这类事件序列的问题
> 光看代码推不出来，得让它自己说。

## 编辑态

### 一次返工：设置窗口并入编辑态

最初的设计是**两个入口**——托盘「设置…」开一个独立窗口，托盘「调整面板位置」进编辑态。
上手用过之后推翻了，原因是结构性的：

> 设置窗口必须 `alwaysOnTop`（否则会被覆盖层压住，实测直接"打开后看不见"），
> 而面板默认在屏幕顶部正中、弹窗也在屏幕中央——**两个都置顶就一定互相遮**。
> 更要命的是面板平时藏着（只有按住 Alt 或编辑态才显形），
> 于是调缩放、调透明度、开关显示项**全都是在盲调**。

改成**单一编辑态**：面板常显可拖 + 设置卡片就画在它旁边，改一下当场看到效果。

### 构成

覆盖层窗口内两层，只在编辑态一起出现：

| 层 | z 序 | 作用 |
|---|---|---|
| `.block` ×4 | 下 | 四个真实的块，各自虚线描边、各自可拖 |
| `#editor` | 上 | 设置卡片（标题栏 + 页签条 + 当前页 + 底部「完成」） |

**卡片是 `.block` 的兄弟节点，不是子节点。** 块被 `--panel-scale` 缩放，
卡片若是子节点会跟着缩到 2× 或 0.8×，都没法用。

**卡片自己也可拖，但只能靠顶部的标题栏**（原因见下面第 3 号坑）。
位置**不存盘**，每次进编辑态回到屏幕中央偏下。

> 拆成四块之前，卡片是"锚在面板下方并跟随拖动"的。四块之后"面板"没有唯一所指，
> 这套锚定失去意义，连同它那圈 rAF 一起删掉了。
> 固定在屏幕某一角也否决过——块一旦被拖到那个角就会互相压住，
> 而"同时看见面板与设置"正是当初合并编辑态的全部意义。

### 三条退出路径

编辑态下覆盖层全屏吃鼠标（`set_ignore_cursor_events(false)`），桌面点不动，连托盘都点不到。
所以出口必须冗余：

1. 卡片底部的**「完成」按钮**——不依赖键盘和窗口焦点，最可靠。
   **它在页签之外**，四页里都在同一个位置（见「设置」的「四页页签」）
2. **ESC**——进编辑态时主动 `set_focus()`，前端监听 `keydown`
3. **`Ctrl+Alt+F10`**——系统级热键，不经过被遮住的窗口，是最后的兜底

> 曾经有第四条「点空白处退出」，**已移除**。它当初按兜底加入，但真被困住时能救场的是热键——
> 点空白处要求你能看见并点中面板以外的区域，而那正是被困场景下最不成立的前提。
> 它没有提供任何独占覆盖，只贡献了摆位时的误触风险。

### 六个必须避开的坑（都只有真机才暴露）

1. **`html, body` 必须 `pointer-events: none`**，否则编辑态下一张看不见的全屏膜会盖住整个桌面，
   连托盘图标都点不到，只能靠热键逃出来。
2. **`set_edit` 内绝不能调 `global_shortcut` 的 register/unregister**——
   它会从热键回调里被调用，而插件派发回调时持有内部锁，在回调里再动注册**直接死锁**，
   实测整个程序卡死。ESC 因此走前端 `keydown`，也不该注册成全局热键（会劫持游戏内菜单键）。
3. **拖拽区里不能有需要点击的控件**：拖拽在 `pointerdown` 时 `setPointerCapture`，
   之后 `pointerup` 会被改派到捕获元素，`click` 便落在那个元素而不是按钮上，
   **按钮的监听器永远不触发**——实测表现为"点完成没反应，且编辑态再也退不出去"。

   最早是「完成」按钮放在面板内部踩的，把按钮移进卡片就解决了。
   但**卡片自己也能拖之后，这个坑原样回来了**：卡片里装着「完成」、九个复选框、
   两个滑块和一个下拉框，整块当拖拽区会把它们全部打死。所以卡片只有顶部那条
   `.ed-bar` 标题栏可拖。四个块没有这个问题，它们内部没有可点的东西。
4. **`.block` / `.cell` 的 `display: flex` 会盖过 `[hidden] { display: none }`**，
   必须显式写 `!important`，否则设置里的显示项开关整个不起作用。
5. **常数表只播种、不补齐 = 静默失效**。`constants.rs` 原本只在文件不存在时写入，
   于是 9/1 播种的 `normal.json` 遇上 9/5 新增的 ward 常数就永远缺那几个键，
   而 `get_constants` 把盘上文件原样返回。后果不是报错而是**静默的错**：
   `this.C.wardSentryDuration` 是 `undefined`，`Math.ceil(x + undefined - y)` 得 NaN
   直接画在地图上；更糟的是 `rem > undefined` 和 `clock - lastSeen > undefined` 恒为假，
   于是**被排检测一次都没触发过、敌方眼永远不移除**，全程没有任何报错。
   现在读盘与播种都把盘上的值盖在内置默认值之上（复用 `settings.rs` 的 `merge`）。

   > **价格表刻意不进这套，它根本不播种到配置目录。** 盘上那份会静默压住内嵌的新表，
   > 而「只补缺键、不改已有键」修不了已经改过价的物品。价格源换成游戏本体之后
   > 用户也没有再手改它的理由，于是副本整个去掉——见 design/networth.md 的
   > 「为什么价格表不再播种到配置目录」。`patch.json` 同理，它只内嵌、不落盘。

6. **`innerWidth` 可能是 0**，而摆位的每一步都要除以它。
   实测浏览器里页面刚导航完、以及窗口被隐藏期间，`innerWidth` 会持续为 0；
   这时 `defaultLayout()` 算出的是 `(0 - 350) / 2 = -175` 这种负坐标，
   而启动流程会把结果**回存**——一次异常启动就足以把摆好的四个坐标全冲掉。
   因此 `applyLayout` 在视口量不出来时返回 `null`（这次不摆、也不写盘），
   由 `resize` 事件补上；`clamp` 同样在视口为 0 时直接放行，不做钳位。

## 设置

卡片沿用覆盖层的深色玻璃配色与 Bahnschrift 字体。

### 四页页签（2026-09-16）

> 会是一排 0——和下面「构成」里 `place()` 那条注释是同一个坑。量完缓存，
> 切语言重建时作废重量（中英文不一样高）。

> **当前页存在模块级变量里，不进 `settings.json`。** 它是瞬时的界面状态不是用户偏好，
> 存盘会让配置文件多一个和外观无关的键。切语言要整卡重建，靠它把选中项接回去，
> 否则每次换语言都被踢回第一页。

> **切页只改 `hidden`，不动任何控件**——九个勾、四条滑块、两个下拉框在四页里一直都在，

1. **显示项开关**（9 个）：中路符 / 赏金 / 莲花 / 智慧 / 堆野 / 敌塔防 / 敌买活 / 净资产 / 眼位小地图
2. **面板缩放** 0.8 ~ 2.0，默认 1.0。用 `transform: scale()`——走合成器，符合"动画只用
   transform/opacity"的约束。四个块的 `transform-origin` 都是 `top left`，
   缩放时各自从左上角长大，存的坐标才不会失真。
3. **眼位地图大小** 108 ~ 360px，默认 180。地图整幅画在 108×108 的 viewBox 里，
   塔、眼点、标签全是 viewBox 单位，所以这个值就是整体等比缩放，不碰 `wardmap.js` 的坐标。
   单独给它一个滑块而不是跟着面板缩放走，是因为它是**地图**不是文字：
   同一个缩放下别处刚好，地图往往还是看不清。

   > **CSS 特异度的坑**：`.cell svg { width: 52px }` 的特异度是 (0,1,1)，
   > 压得住 `.wardmap` 的 (0,1,0)。地图因此**一直被塞在 52px 里画**，
   > 而不是设计里写的 108px——拆块时才查出来。规则必须写成 `.cell svg.wardmap`。
   > 另外包在外面的 div 也叫 `.wardmap`，只能给它宽度，高度要让 svg 加标签自己撑，
   > 否则"眼位"两个字会压在地图上。

4. **底板**（滑块就叫这两个字）0 ~ 1.0，默认 0.72。**只动块的底板，内容不动**——
   和下面那条「整体」不是一回事，那条会把文字图标一起调淡。
   描边跟着底板一起淡出（系数 0.14，默认的 .72 正好落回 `--hair` 的 .10）：
   底板没了却留一圈白线，会变成一个空方框浮在画面上。

   **眼位地图自己的底跟着一起淡**：`.wm-bg` 曾经写死 `rgba(0,0,0,.35)`，底板拉到 0
   时四个块都透了，只剩它一块灰方块浮在画面中间，比不透明还显眼。现在是
   `rgba(0,0,0, calc(var(--block-bg,.72) * .5))`——系数 .5 让默认的 .72 落回 .36，
   和原来的 .35 基本同一档，只是从此跟着滑块走。它是**块底之上的第二层**，
   所以两层相乘着变淡，这正是想要的：地图那块本来就该比别处再压一点。

   > **拉到 0 的代价是具体的**（实测，最亮背景下）：大号倒计时、图标、净资产金额
   > 都靠自身的 `text-shadow` / `drop-shadow` 活下来了；但 **GPM/XPM**（10px、
   > `--dim` 灰、只有 3px 阴影）基本读不出，**买活的青框**（32% 是按深色底调的）
   > 淡到快没了。先只给滑块、不动这两样——等实际常用值定了再决定要不要为那个值优化。

5. **整体**（滑块就叫这两个字）0.3 ~ 1.0，默认 1.0。四个块（含文字与圆环）一起变淡。

   > 两条滑块原先叫「透明度」和「底板」，并排放着看不出谁管什么。现在是「整体」/
   > 「底板」——对仗、都两个字、宽度不变，各自点名它调的对象，
   > 和「缩放」「眼位地图」同一种命名方式：名词指对象，滑块调它。

   > **`.block.edit` 里绝不能写 `opacity: 1`。** 它会盖掉 `.block.on` 的
   > `var(--panel-opacity)`，而这个滑块只能在编辑态里够到——结果就是"拖了没反应"，
   > 永远看不到效果。把设置并进编辑态本来就是为了不盲调（见上面那次返工的理由），
   > 这条却一直漏在外面，直到 2026-09-08 才发现。下限 0.3 在编辑态下仍看得见、拖得动。
   面板的显隐本来就用 `opacity` 做淡入淡出，设置值**不能另起一套**，否则两者打架——
   写成 `.block.on { opacity: var(--panel-opacity, 1) }`，让淡入的目标值就是设置值。
   已知取舍：调得过低会让数字在明亮的团战画面上变糊，但面板只在按住 Alt 时出现、
   不是常驻，风险可控，由用户自行把握。
6. **重置**。按钮原来叫「恢复默认摆位」、只复位坐标；现在把**这张卡片能改的东西
   一次性还原**：显示项九个勾、缩放、整体、底板、眼位地图大小，外加四块的摆位。
   名字跟着缩成两个字，因为它已经不只管摆位了。

   **开发区那两项（日志级别、对局录制）不在重置范围内**——它们不是"外观"，
   而且悄悄把正在录的对局关掉，用户不会知道自己丢了数据。

   > **顺序有坑**：复位摆位要按**新的**缩放算（`applyLayout(null, scale)`），
   > 而 `main.js` 里的 `cfg` 是靠 `settings` 事件异步更新的，保存后不会立刻变。
   > 所以按钮把新的 scale **当参数传给** `onReset`，不让它去读那个还没刷新的 `cfg`。

   不做二次确认：这是编辑态里的按钮，而编辑态要按住热键才进得来，
   误触成本没到值得多一次点击的程度；勾选和滑块也都能立刻手动改回去。

7. **眼位地图图例**（第三页）：六种眼状态 + 三种塔状态的色块与说明。

   | 通道 | 取值 |

   | 颜色 | 青 `#65D9F7` = 我方 · 红 `#FF4D4D` = 敌方 · 琥珀 `#FFC24B` = 60 秒内到期 |

   |---|---|

   >    完全分不出来。

   >

   > 就想不起来该删**；一个每次展开开发区都看得见的数字才是触发清理的那个东西。
   > 按钮只省掉后半步。
   >

   > 不在卡片里做文件列表——那是资源管理器已经做得很好的事，而卡片只有 300px 宽。

   > **这个数字要在打开卡片的那一刻重拉**（2026-09-20 修）。原先它只在**程序启动
   > 那一刻**拉过一次：打开 / 关闭卡片走的是 `card.hidden`，不重建也不重拉，
   > 于是开着程序打了三局再去看，显示的还是启动时的数字——而那恰恰是最想看它的
   > 时候（想确认刚才那局录下来没有）。**上面说"每次展开开发区都看得见的数字
   > 才是触发清理的那个东西"，前提就是它得是真的。**
   >
   > 拨录制开关之后也刷一次（会新建或收尾一个文件），**延后 300ms**——
   > `saveSettings` 在 Tauri 下是异步 invoke，Rust 那边要先 `refresh()` 完才有结果。
   >
   > **不做轮询。** 这个数字只有卡片开着时有人看，开的那一刻拉一次就够，
   > 代价是一次 `readdir`。
   >
   > **个数的单位在英文里是空串**（中文是"个"）。这是多语言那套**没有复数规则**
   > 的第一次撞墙：写死 `files` 会在只有一个文件时显示 `1 files`。
   > 解法不是补复数规则，是**别把可数名词摆在数字旁边**——名词已经在左边的标签里
   > （`Recordings`），右边只留 `1 · 0.1 MB`。
   >

   > 5 秒无操作自动退回。不引入 dialog 插件，也不用 `confirm()`——
   > 它会弹一个抢焦点的系统框，而编辑态本来就在跟焦点较劲。
   > 确认文案里**不带个数**：那会需要往词条里塞占位符，而个数就在正上方那一行摆着。
   >
   > **正在录的那个文件必须跳过。** `Recorder` 攥着一个打开的 `GzEncoder<File>`，
   > 删掉它的结果不是"删干净了"：这一局后面的数据会静默流进一个已经不存在的文件。
   > 跳过而不是"先停录再删"——**别让一次清理顺手关掉用户正在录的对局**。

   > **版本号为什么值得占两行**（2026-09-16 加）：价格表是跟着 Dota 版本走的快照，
   > 表旧了的症状是净资产**看起来正常但偏低**——没有任何报错，用户只会说"数字不对"。
   > 这时第一件要问的就是"你手上那份表是哪一版"，而那之前只写在日志里，
   > 要教用户翻到 `%APPDATA%` 深处再找一行。摆在开发区就能直接念出来。
   >
   > **程序版本一起显示**，因为下一个问题必然是"你装的是哪一版程序"。
   > 两行都是纯文本、可以选中复制（`user-select: none` 只加在拖拽把手上）。
   >
   > **不做插值**：写成"版本 1.2.2 · 价格表 7.41f"就需要往词条里塞占位符，
   > 而多语言那套刻意"一条插值都没有"。两行各自一个标签，代价只是多一行。
   >
   > **标签是「Dota2 版本」，但它指的是这份价格表对齐到哪一版，不是你装的是哪一版。**
   > 程序根本不知道后者——而且**不打算让它知道**（2026-09-23 定，见
   > [../backlog.md](../backlog.md) 的「已明确不做」）。这个歧义是知情的取舍：写全成"价格表对齐的
   > Dota 版本"更准，但那已经不像一个标签了，而念版本号的人只关心那串数字。

**卡片里的下拉框需要 `color-scheme: dark`**，而且只能加在 `.editor` 上：
弹出层由系统绘制，不声明配色方案就是白底，而 `option` 继承卡片的浅色文字 → 白字白底。
加在 `:root` 上会给根元素画上不透明底色，覆盖层就不透明了。

### 配置与生效

存 `settings.json` 于配置目录（与 `constants/`、`layout.json` 同级）：

```json
{
  "show": { "mid": true, "bounty": true, "lotus": true, "wisdom": true,
            "stack": true, "glyph": true, "buyback": true, "econ": true,
            "wardmap": true },
  "alwaysShow": false,
  "scale": 1.0,
  "opacity": 1.0,
  "panelBg": 0.72,
  "wardSize": 180,
  "logLevel": "info",
  "recordMatches": false,
  "lang": "zh-CN"
}
```

Rust 提供 `get_settings` / `set_settings`；保存后 emit `settings` 事件，
**覆盖层实时应用，不需重启**。卡片与面板同在覆盖层窗口内，这条事件成了自发自收，
但链路不变——保持单一数据流向，不给卡片开后门直接改面板。

读盘时**缺什么补什么**，所以老配置文件遇上新增字段也能直接用。

**关于关掉某项后面板变窄**：这与"宽度写死防抖动"不冲突。那条针对的是游戏中净资产位数变化
导致的横移；改设置是用户主动的一次性操作，变窄是预期内的结果。

## 多语言

**范围只有两处**：编辑态卡片和托盘菜单。覆盖层上一个字都没有（2026-09-08 图标化），
所以面板本身不需要翻译——这才是图标化真正的收益。代码里的中文全是注释和日志，
给开发者看的，不该翻。

**不上 i18n 框架**，理由写全在这儿，免得以后重新讨论：

1. 框架值钱的地方是复数规则、ICU 消息格式、locale 懒加载、词条抽取工具链、
   fallback 链。我们是 30 来条静态短语 × 2 种语言，**一条插值都没有**，这些全用不上。
2. **前端没有构建步骤**——`ui/` 是原生 ES 模块，编译期直接嵌进二进制。引框架要么
   加打包器、要么往仓库里塞 UMD；而覆盖层必须离线可用，CDN 这条路本来就堵死。
3. **托盘菜单在 Rust 侧**，JS 框架管不到。无论如何都得有一份两边都能读的东西，
   那正好就是一个 JSON——框架在这里只覆盖一半，还多一套机制。

需要的就是 `T[lang][key]` 加一条"缺键回退中文"，十几行。

框架唯一能白给而我们会缺的是**漏翻检查**——一段 grep 比较两份 JSON 的键集合即可补上。

> **会改主意的情形**：词条涨到几百条、有第三方帮忙翻译（那时抽取和校验工具才值钱）、
> 或需要复数 / 日期本地化。数字已用 `toLocaleString` 处理，日期没用到。

> **原先最难的那一条在动工前就消失了。** 当初记的是：面板宽度写死（`.cell` 60px、
> 买活 104px、净资产 116px），而"净资产"换成 `Net Worth` 会更宽，直接翻译会撑破或截断，
> "得让宽度跟着语言走"。图标化之后面板上没有词，这个约束不复存在——
> **这才是图标化真正的收益**，不是省掉那十几条翻译。
>
> 也因此界面多语言原本"排在整个清单的最后"（与布局耦合：布局定了才知道每格能给多宽），
> 耦合拆掉后它提前做完了。

### 语言包走"常数外置"那套

`constants/lang.zh-CN.json` / `lang.en.json`，与其他常数表一起播种到配置目录，
一起补齐新增的键。白捡三样：Rust 和前端都已经会读那个目录；翻译别扭时改 JSON
重启即可，不必重新编译；版本升级新增的词条会自动出现在用户已有的文件里。

键是扁平的 `card.* / show.* / legend.* / tray.*`，取值就是字符串。
**缺键回退中文**，不回退键名——漏翻的地方显示中文至少还是句人话。

> **发布出去的键，值就不能再改了。** 播种是 `constants::seed`，它**只补缺键、
> 不覆盖已有值**（这是对的：用户手改过的翻译不该被升级冲掉）。于是改仓库里的
> 措辞**到不了老用户眼前**——他们的文件里已经有那个键了。
>
> 要改措辞只有两条路：**换一个新键**，或者接受"只有新用户看得到"。
> 2026-09-21 把「常显」改成「始终显示」时没踩到，只因为那个键还没随任何版本发布过。
>
> 同样的道理，**语言无关的东西干脆别进语言包**——托盘菜单上那个
> `Ctrl+Alt+F10` 就是在 Rust 里拼上去的，两种语言一个样，也就不受这条限制。

### 首次运行跟随系统语言

`GetUserDefaultLocaleName` 取到的名字以 `zh` 开头就用中文，否则英文
（`windows` crate 已经是依赖，只多开一个 `Win32_Globalization` 特性）。
仓库是公开的，默认给陌生人一个看不懂的界面没道理；而对中文用户，
这个判断的结果和写死中文完全一样。存进 `settings.json` 的 `lang` 字段后就以它为准。

### 切换要同时管两边

卡片在前端、托盘在 Rust，一次切换得两边都动：

- **卡片**：整个 `innerHTML` 重建。因此建卡片和绑事件必须是同一个函数——
  重建会换掉所有节点，包括 `.ed-bar` 那个拖拽把手，只重建不重绑就把卡片钉死了。
- **托盘**：`set_settings` 里重建整个菜单再 `set_menu`。不用 `set_text` 逐项改，
  那要把菜单项句柄存进全局状态，为两个词不值当。

### 「重置」不动语言

和开发区那两项同理，但理由更硬：**重置回中文会让看不懂中文的用户无法退出这个状态**
——他得先猜出哪一行是语言、再猜哪个选项是英文。可恢复性是重置的前提，
这一项恰好不满足。

## 明确不做

开机自启、白天黑夜、语音提示、任何形式的输入模拟。
