# dota2-game-helper2

**Hold Alt to see the timers Dota 2 never shows you**

**English** · [简体中文](README.zh-CN.md)

[![CI](https://github.com/shizzhang0/dota2-game-helper2/actions/workflows/ci.yml/badge.svg)](https://github.com/shizzhang0/dota2-game-helper2/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE) ![Platform: Windows](https://img.shields.io/badge/platform-Windows-lightgrey.svg) ![Dota 2: 7.41f](https://img.shields.io/badge/Dota%202-7.41f-C24A34.svg)

</div>

**Bounty runes, lotuses, wisdom runes, enemy glyph and enemy buyback — Dota 2 shows
none of these timers anywhere. You are expected to keep them in your head.**

But all of it is **already in the data the game pushes to you**. It just isn't drawn
on screen. So draw it.

This is a desktop overlay built on Dota 2's official GSI interface. Nothing is on
screen normally; **hold Alt** and it appears. No memory reading, no file changes, no
simulated input — only data the game pushes on its own, that you can already see
([why this is safe](#why-this-is-safe)).

![The overlay](docs/images/overlay.png)

<sub>Top left: net worth / GPM / XPM. Bottom left: the ward map. Top right: the
timers. Bottom right: enemy glyph and buyback. This and every screenshot below is
generated by [`tools/make_shots.py`](tools/make_shots.py) from a real recorded match,
running the same front-end code as the shipped build. The background is a placeholder
colour, not real gameplay.</sub>

## Up and running in three minutes

1. Grab the zip from [Releases](https://github.com/shizzhang0/dota2-game-helper2/releases)
   and unpack it anywhere — **there is no installer, just an exe**
2. Add `-gamestateintegration` to Dota 2's launch options
3. Run the game in **borderless window** mode
4. Double-click `dota2-game-helper2.exe`. It lives in the notification area and writes
   the GSI config file on first run
5. Get into a match and **hold Alt**

That's it. To move things around or turn cells off: right-click the tray icon →
"Edit panel" (or `Ctrl+Alt+F10`).

> **Panel never shows up?** Check steps 2 and 3 first — no non-injecting overlay can
> draw over exclusive fullscreen, which is an OS-level limitation rather than a bug
> here. Then look at the logs in `%APPDATA%\dev.dota2helper2.app\logs\`.

## What it remembers for you

### Five timers: runes, lotus, wisdom, stacking

![Timers](docs/images/block-timers.png)

| Item | Rule |
|---|---|
| Mid rune | 0:00 bounty → 2:00 / 4:00 water → power runes every 2 min from 6:00 |
| Bounty runes | Every 3 min |
| Lotus | Every 3 min from 3:00 |
| Wisdom rune | Every 7 min from 7:00 |
| Stacking | Neutrals spawn on the minute; counts you down to it |

The icon sits inside the ring and the number below it. **A nearly-empty ring means
it's nearly up** — you can read the state at a glance without reading digits.

### What the enemy still has: glyph and buyback

![Enemy](docs/images/block-enemy.png)

**Glyph** is not just a cooldown timer. Dota refreshes it whenever a side loses its
first T1, T2, T3 or melee barracks, and that whole rule set is implemented here — so
it knows whether the enemy actually has a glyph available right now, not merely when
they last used one.

**Buyback** is announced once and then gone. Here the 480-second cooldown is kept as
state for each of the five enemies: **a lit dot means that player cannot buy back.**

### Your economy

![Net worth](docs/images/block-econ.png)

Net worth (items + stash + ward dispenser + items in transit on the courier + gold),
GPM and XPM.

> Net worth is an **approximation**. GSI only pushes your own inventory, so items on
> the ground or held by a teammate are invisible; consumables are discounted by
> remaining charges, and consumed buffs (Aghanim's Shard/Scepter, Moon Shard) are
> counted from the item they came from. The exact definition and the known error
> sources are in [design/networth.md](docs/design/networth.md) (Chinese).

### Ward map

![Ward map](docs/images/block-wardmap.png)

**Colour is ownership, shape is state** — two channels that never interfere:

| Channel | Values |
|---|---|
| Colour | cyan = yours · red = enemy · amber = expiring within 60s |
| Shape | filled circle = observer · hollow ring = sentry · **cross = just dewarded** |

In the shot above a cyan ring and a red ring sit side by side — both sentries, one
yours and one theirs.

The base map draws only towers (green = Radiant, dim red = Dire, grey = destroyed),
**deliberately faint**: towers are the reference grid, the wards are what you came to
look at.

#### Why enemy wards have no countdown

You only see an enemy ward during the seconds your sentry lights it up, so **there is
no way to know when it was planted** — it could be fresh, it could have ten seconds
left. A countdown that might be five minutes too high would mislead you, while "there
is a ward there" is already enough to act on (don't walk here / go kill it).

The memory does **fade**, though: the longer since an enemy ward was last confirmed,
the more transparent it is drawn. It disappears once it reaches its nominal lifetime,
so it can never sit on the map forever lying to you.

## The rest of the time it isn't there

There is exactly one in-game interaction: **hold Alt to show, release to hide.** When
you aren't holding it the screen is clean — nothing to move out of the way, nothing to
remember to close.

Alt is detected passively by polling the key state. It **registers no hotkey and
swallows no input**, so Alt's normal in-game behaviour (Alt-clicking the map and so on)
is completely unaffected.

### What's supported

| | |
|---|---|
| OS | Windows 10 / 11 |
| Display mode | Borderless window ✅ · exclusive fullscreen ❌ (OS-level limit; applies to any non-injecting overlay) |
| Game modes | Ranked / unranked / Turbo, with the timing table switched automatically |
| Spectating · replays | **Whole window hidden** — on purpose, see below |
| UI languages | English · 简体中文 |

> **Why it hides completely while spectating**: GSI pushes the whole roster in those
> modes, which makes net worth and enemy buyback wrong, while runes and wards are
> actually more complete. A half-working panel reads as a broken program, so it hides
> entirely — this overlay exists for **the match you are playing**, and spectating
> already has plenty of tools.

## Making it yours

Right-click the tray icon → "Edit panel" (or `Ctrl+Alt+F10`). The four blocks —
**timers / enemy / net worth / ward map** — become permanently visible and individually
draggable, and a settings card floats up. The card has four pages, switched by icon:

|  |  |
|---|---|
| ![Display](docs/images/card-show.png) | ![Panel](docs/images/card-panel.png) |
| **Display** — a toggle for each of the nine cells | **Panel** — language, scale, opacity, backdrop, map size, reset |
| ![Legend](docs/images/card-legend.png) | ![Developer](docs/images/card-dev.png) |
| **Legend** — what every colour and shape on the map means | **Developer** — log level, match recording, data folder, versions |

Changes apply immediately, no restart. The card itself can be dragged by its title bar.

> **Why settings and placement share one mode**: the panel is normally hidden, so a
> separate settings window would mean adjusting scale and opacity blind.

In edit mode the overlay takes over the whole screen for the mouse (otherwise you
could not drag the blocks), so there are three ways out: **the "Done" button · ESC ·
pressing `Ctrl+Alt+F10` again**.

> ESC is handled by the front end rather than registered as a global hotkey — doing
> that would hijack the in-game menu key.

### Where the files live

All under `%APPDATA%\dev.dota2helper2.app\`:

| | |
|---|---|
| `constants/` | Timing tables + language packs. **Edit the JSON, restart, done** (item prices are not here — see below) |
| `settings.json` | Everything from the card |
| `layout.json` | Where each of the four blocks sits |
| `logs/` | Run log (rotates past 5 MB, one backup kept) |
| `records/` | Match recordings (off by default) |

### Uninstalling

No installer means no uninstaller — delete three things:

1. `dota2-game-helper2.exe`
2. The config directory `%APPDATA%\dev.dota2helper2.app\`
3. `gamestate_integration_helper2.cfg` in Dota's
   `game\dota\cfg\gamestate_integration\`

## Why this is safe

This is a **pure receiver**. That isn't a promise, it's a checklist you can verify:

| What it does **not** do | What it does |
|---|---|
| ❌ Read game memory | ✅ Accept JSON the game POSTs to `127.0.0.1:53000` |
| ❌ Modify game files | ✅ Write one GSI config file (the mechanism Valve built for this) |
| ❌ Inject into the process / hook graphics APIs | ✅ Be an ordinary transparent always-on-top window |
| ❌ Simulate any input | ✅ Passively poll the Alt key state |
| ❌ Touch the network at runtime | ✅ Keep every constant locally — works offline once installed |

GSI is an official Valve interface; Logitech and Razer drivers use the same mechanism.
**During a match it only pushes your own data**, so by design it cannot be used to
obtain hidden information — anything this overlay computes, you could see yourself by
pressing Tab. It just remembers the timing for you.

The source is entirely open: [what goes into the GSI config](src-tauri/src/gsicfg.rs)
and [what happens to the data](ui/js) are both there to read.

## How it works

```
Dota 2  ──GSI (HTTP POST)──▶  127.0.0.1:53000
                                    │
                    ┌───────────────┴───────────────┐
                    │  Rust / Tauri 2               │
                    │  gsi · altkey · gsicfg        │  receive, poll Alt, write cfg
                    │  constants · settings · log   │  seed constants, settings, logs
                    └───────────────┬───────────────┘
                                    │  events
                    ┌───────────────┴───────────────┐
                    │  Front end: vanilla JS + SVG  │
                    │  cachepool → match            │  merge deltas, split matches
                    │    → timers    countdowns     │
                    │    → events    glyph/buyback  │
                    │    → networth                 │
                    │    → minimap   wards          │
                    │    → render    four blocks    │
                    └───────────────┬───────────────┘
                                    ▼
                  transparent · always-on-top · click-through
                        (visible only while Alt is held)
```

- Shell: [Tauri 2](https://tauri.app/) (Rust)
- Front end: vanilla JS + SVG, **no framework, no build step**, embedded into the
  binary at compile time
- Data source: Dota 2 GSI (local HTTP push)
- Item prices: a local constant table, snapshotted from **the game's own data files**

### Why the constants live outside the code

The timing tables (normal and Turbo) and the language packs are in `constants/*.json`,
so a patch changes data rather than code. **The previous project died of hardcoded
constants** — Dota changed an interval and it silently stopped being right.

Which Dota version this table matches is recorded in `constants/patch.json`, which is
also the badge at the top:

```json
{ "dota": "7.41f", "synced": "2026-09-16" }
```

**Item prices are the exception: they are not seeded to the config directory**, only
compiled in. They are generated by `python tools/sync_constants.py` from the game's own
files (`ItemCost` in `items.txt`, item ids from `npc_ability_ids.txt`). That is a step
**on the development machine** — the shipped exe contains none of that parsing and
never looks inside your Dota installation.

The cost is waiting a few days after a patch until a new release goes out. What it buys
is that **a stale table on disk can never silently shadow a newer one** — and that is
much harder to notice than prices being a few days late. Timing tables are not subject
to this and remain editable.

## Development

```bash
cargo build --release --manifest-path src-tauri/Cargo.toml   # build
python tools/replay.py                                       # replay server
python tools/sync_constants.py                               # follow a Dota patch
python tools/make_shots.py                                   # regenerate README shots
python tools/make_demo.py <recording> --from 60 --to 460      # build the site demo data
```

**The replay server** serves <http://127.0.0.1:8000/dev.html> and drives the front end
from a real dump, so you don't have to keep launching the game. `?file=` picks the
file, `?speed=` the rate, `?demo=` switches to static-file replay; in the page `v` is
always-on, `e` is edit mode, `b` cycles backgrounds. Recorded `.jsonl.gz` files work
directly, including ones truncated by a hard kill.

**After a Dota patch** run `sync_constants.py`: it regenerates the price table from the
local Dota VPK, updates the version and both README badges, and prints two things — the
price diff against the previous version, and the patch-note entries that mention runes,
Roshan, glyph, buyback, lotus, stacking and so on. Prices are automatic; those entries
need a human read to decide whether `normal.json` / `turbo.json` / `towers.json` need
changing — rune intervals are not in the game's item tables.

**The front end is embedded at compile time**, so changes under `ui/` need a fresh
`cargo build` (`build.rs` watches `ui/` and `icons/`). Every push and PR runs a
front-end syntax check plus `cargo build --release` in CI — a typo under `ui/` only
surfaces at compile time, and day-to-day development goes through the replay server,
which does not compile.

**Test on release builds**: debug builds carry a console window that cannot be closed
(`windows_subsystem = "windows"` only applies to release). When something goes wrong,
start with `%APPDATA%\dev.dota2helper2.app\logs\` — the shipped build has no console
and no devtools, so front-end exceptions are forwarded to Rust and written there.

Design documents are organised by topic under [docs/design/](docs/design/): timers,
net worth, the ward map, the app shell and the dev tools; open items are in
[docs/backlog.md](docs/backlog.md) and things awaiting real-match confirmation in
[docs/verify-checklist.md](docs/verify-checklist.md). **These are development notes and
are Chinese-only.**
